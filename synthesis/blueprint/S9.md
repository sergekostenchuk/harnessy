### 0.2 Где проходят три линии в этой сцене

- **Линия взаимодействия** (пользователь ↔ frontstage): чат-окно вендора (участвует во всех 20 эпизодах инвентаря), терминалы-хвосты, пикер моделей, OAuth-страница в браузере, тосты и плашки, терминальная таблица хуков, список вахт Codex Desktop, скриншот как канал «покажи агенту мой экран» (15 из 73 реплик — только картинка) — `r2-touchpoints.md N1`; `r2-screenshots.md F11` (через `cjm/S9.md §1.1`).
- **Линия видимости** (frontstage ↔ backstage): проходит «по границе чат-окна вендора и всего, что доставляет сообщения между ролями» (`r2-touchpoints.md N1`). За ней — `channel.ndjson`, `automation.toml`, Stop-хуки, диспетчер `kimi_seat.py`, ACP-база Devin, cron Hermes, `reviewers.txt`, allow-список Desktop, `config.*`. Подробно — §2.
- **Линия внутреннего взаимодействия** (backstage ↔ поддерживающие): агент → клиент вендора → API (события `rate_limits`, `task_complete.error`, `model_refusal_fallback`); агент → файл конфига (`config.yaml`, `~/.zshrc`); агент → git (`om/module`, worktree); сторож → канал; движок OMG → `state.sqlite` и очередь `backend-runs` — `r2-touchpoints.md N5`; `claude-code.md §2.4`; `omg-process.md §3.3–3.4`; `owner-vision.md §3.3`.

[вывод] Особенность сцены: пользователь сам регулярно пересекает линию видимости вниз (правит `approvals_reviewer`, `reviewers.txt`, `~/.zshrc` по кнопке; читает `agent.log`; ходит в консоль QwenCloud) — потому что frontstage не показывает того, что лежит под линией (`codex.md П-05`; `r2-owner-voice.md §4`; `r2-other-harnesses.md 3.8 п.6`).
