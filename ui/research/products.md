# Линза «Продукты»: как ведущие продукты 2025–2026 показывают «где я, что происходит, что дальше, когда, чего ждать»

Дата исследования: 30.09.2026. Автор: исследователь программы UX харнесса. Язык: русский; названия продуктов и терминов — как в оригинале.

**Как читать.** Метки достоверности у фактов: (П) — прочитан первоисточник (документация, блог, changelog вендора); (В) — только вторичный источник или сниппет поиска; (Н) — не подтверждено. Цитаты не приводятся, факты пересказаны; в кавычках остаются только названия элементов интерфейса. Сценарии нашего харнесса обозначены так: **С1** чат в папке проекта · **С2** планирование по стадиям (TaskPlan Pro/OMG) · **С3** ресёрч · **С4** команда агентов · **С5** ревью · **С6** живой прогон · **С7** восстановление после обрыва.

## Резюме (семь наблюдений)

1. **Боковая панель группируется по состоянию, а не по времени.** Devin, Claude Code (Agent View, Projects), Codex сходятся на одном ядре: «работает / нужен ты / готово к ревью / завершено / сбой». Отдельная очередь «ждут тебя» есть почти везде.
2. **Режимы — это лестница автономии, а не разные приложения.** Переключение в том же потоке (Shift+Tab, селектор рядом с кнопкой отправки), режим всегда виден в строке статуса. План — редактируемый документ с явным шлюзом «утвердить»; утверждение плана часто совмещено с выбором режима исполнения.
3. **Команда агентов показывается тремя слоями:** панель строк под полем ввода (или боковая панель), coordinator + Overview, и вход «внутрь» одного агента по Enter. Провенанс (кто автор сообщения, у кого нет полномочий) выделяется явно.
4. **Точки подтверждения смещаются с «каждого действия» на «наблюдение + прерывание».** По данным Anthropic, пользователи одобряют 93% запросов на разрешение; продукты отвечают классификаторами, рецензентами-агентами и областью одобрения «один раз / всегда / отказ». Риск объясняется в основном в документации, редко в самой карточке подтверждения.
5. **Времени завершения (ETA) в прочитанных источниках нет нигде.** Показывают прошедшее время, счётчики агентов/ходов, токены, класс размера; ожидания задаются диапазонами и статистикой.
6. **Восстановление строится на трёх опорах:** долгоживущий процесс-супервизор, сохранение состояния с возобновлением, откат (checkpoints/rewind) с честным перечнем того, что откатить нельзя.
7. **Терминология продуктов постоянно меняется** (Ultraplan удалён; у Lovable режимы переименованы; у Antigravity — два разных приложения). Дизайн харнесса должен опираться на собственный устойчивый словарь, а не копировать названия.

## Вопросы

- **В1.** Как продукты показывают «где я» (проект, сессия, режим, стадия) и как устроена навигация между множеством параллельных потоков?
- **В2.** Как отображается «что происходит сейчас» у длительных работ: статусы, прогресс, строка-резюме, глубина погружения?
- **В3.** Как оформлены переходы между режимами чат ↔ план ↔ агент и что является «шлюзом» между ними?
- **В4.** Как показывается команда агентов (роли, модели, иерархия, координатор, изоляция)?
- **В5.** Как устроены точки подтверждения (approvals): что спрашивают, с какой областью действия, как объясняют риск?
- **В6.** Как показывают стоимость и как задают ожидания по времени?
- **В7.** Как продукты помогают вернуться после обрыва (закрыл окно, закончился лимит, сбой машины, смена устройства)?
- **В8.** Какие провалы и антипаттерны документированы самими вендорами?

## Паттерны

Формат: **имя** · кто · что именно · почему работает · применимость к нашему харнессу (с метками С1–С7).

### Блок A. «Где я» и «что происходит»: навигация по многим потокам

**A1. Иерархия «Проект → Сессия/Тред» с фильтрами по статусу, проекту и окружению**
- **Кто:** Claude Desktop (вкладка Code), Codex app, Antigravity 2.0, Cursor Agents Window, Claude Projects. [S7, S30, S58, S37, S6] (П)
- **Что именно:** в Claude Desktop каждый чат — это сессия со своей историей и папкой проекта; боковая панель даёт параллельные сессии, фильтры по статусу/проекту/окружению и группировку по проекту; можно открыть две сессии рядом (Cmd+клик), переименовать. В Antigravity 2.0 разговоры группируются по «project», который может включать несколько папок. В Cursor все локальные и облачные агенты, включая запущенные из мобильного, веба, Slack, GitHub, Linear, видны в одной боковой панели. Codex: проекты и чаты, тредом можно вернуться без потери контекста.
- **Почему работает:** ответ на «где я» превращается в адрес из двух уровней (контейнер работы → поток), а не в плоский список чатов. Источник запуска (Slack, Web, API, Jira, Linear) — отдельный фильтр у Devin (18.09.2026). [S47]
- **Применимость:** С1, С2, С4, С7. Проект = папка, но контейнер должен уметь объединять несколько папок (как в Antigravity 2.0).

**A2. Боковая панель сгруппирована по состоянию**
- **Кто:** Devin, Claude Code Agent View, Claude Projects Overview, Codex. [S47, S2, S6, S21] (П)
- **Что именно:** Devin (25.09.2026): группы Working / Ready / Blocked / Inactive по состояниям PR и запросов ввода. Agent View: порядок Pinned → Ready for review (есть открытый PR) → Needs input → Working → Completed (завершено, сбой, остановлено); Ctrl+S переключает на группировку по директории. Projects: Ready for review / Waiting on you (нужен ответ, одобрение или был сбой) / Working. Codex: состояния Running / Needs input / Ready / Blocked.
- **Почему работает:** пользователь спрашивает не «какие у меня чаты», а «что требует меня прямо сейчас». Группа «нужен ты» — очередь внимания.
- **Применимость:** С4, С5, С6. Отметить, что у Projects «Waiting on you» смешивает «ждёт ответа» и «упал» — этому смешению лучше не следовать (см. таблицу словарей ниже).

**A3. Общий словарь из 5–7 состояний с формой и цветом**
- **Кто:** Claude Agent View, Linear, Codex, Devin, Replit, Warp. [S2, S60, S21, S24, S25, S47, S53, S65] (П)
- **Что именно:** сравнение словарей:

| Продукт | Состояния |
|---|---|
| Claude Agent View | Working (анимированный значок), Needs input (жёлтый), Idle (приглушённый), Completed (зелёный), Failed (красный), Stopped (серый); отдельный значок «спящий /loop с обратным отсчётом»; форма значка означает «процесс жив / завершён» |
| Claude Projects (треды) | Ready for review · Waiting on you (включая сбой) · Working |
| Codex (чаты, pet, уведомления) | Running · Needs input · Ready (завершён, есть непрочитанное) · Blocked (сбой или системная ошибка) |
| Codex Micro (шесть клавиш с подсветкой) | белый — простой; синий — обработка; зелёный — завершено с непрочитанным; жёлтый — ждёт одобрения или ответа; красный — ошибка; выкл — нет чата |
| Linear (сессия агента) | pending · active · error · awaitingInput · complete · stale |
| Devin (боковая панель) | Working · Ready · Blocked · Inactive |
| Replit Agent 4 (доска задач) | Drafts · Active · Ready · Done |
| Claude Agent Teams (общий список задач) | pending · in progress · completed, плюс зависимости между задачами |
| Warp Oz (неявно, из контекста) | queued · in progress · succeeded · failed (явного перечня нет, Н) |
| GitHub Copilot | у каждой сессии есть статус; значения на прочитанных страницах не перечислены (Н) |

- **Почему работает:** все словари сводятся к одному ядру: **работает · нужен человек · готово к проверке · завершено · сбой/блок · простаивает/остановлено**. Отдельного «устарело/stale» нет почти нигде, кроме Linear.
- **Оговорка о доступности:** у Claude состояние кодируется формой значка и цветом одновременно; у Codex Micro — только цветом (это аппаратный аксессуар, для программного интерфейса подражать нельзя).
- **Применимость:** С1–С7 — основа единого словаря статусов харнесса; добавить состояния стадии («ждёт утверждения плана», «ждёт ревью») как подвиды «нужен человек».

**A4. Строка-резюме одной фразой у каждого агента**
- **Кто:** Claude Agent View; GitHub Copilot (субагенты). [S2, S64] (П)
- **Что именно:** в Agent View у каждой строки одна фраза от модели Haiku: у работающего — что делает; у заблокированного — вопрос, который он задаёт; обновление не чаще раза в 15 секунд, свежая фраза в конце хода, при долгих ходах пересказ раз в несколько минут. Фраза тратит запросы к модели и оплачивается подпиской. У Copilot работа субагентов свёрнута по умолчанию, но виден компактный индикатор «над чем работает сейчас» (19.03.2026).
- **Почему работает:** пользователь читает 10 строк, а не 10 журналов; вопрос заблокированного агента виден без входа в сессию.
- **Применимость:** С4, С6. Учесть, что «статус» стоит токенов: нужен собственный бюджет на сводки.

**A5. Три глубины погружения: строка → peek → полная сессия**
- **Кто:** Claude Agent View. [S2] (П)
- **Что именно:** Space на строке открывает peek-панель: точный вопрос сессии, последний вывод, связанные PR; можно ответить и отправить, не покидая списка. Enter или стрелка вправо подключает полную интерактивную сессию; стрелка влево на пустом вводе возвращает к списку. Диспетчеризация новых сессий — прямо из нижнего поля ввода списка.
- **Почему работает:** обзор и вмешательство не требуют контекстного переключения; вход в сессию — осознанное действие.
- **Применимость:** С4, С6. Прямая модель для «таблицы потоков» с быстрым ответом на запрос агента.

**A6. Фоновое оповещение: уровни «не мешать»**
- **Кто:** Codex, Claude Desktop/Projects/Dispatch, Agent View. [S21, S7, S6, S19, S2] (П)
- **Что именно:** Codex: три режима оповещения о завершении хода (никогда / только в фоне / всегда), отдельные переключатели для запросов разрешения и вопросов, каналы: ОС, колокольчик в боковой панели, вид Activity, «плавающий» pet (опционально), на вебе — push/email/SMS. Claude Desktop: уведомление ОС, когда сессия закончила задачу и вы её не смотрите; у проектов свои уведомления (об ошибке потока, о запросе ввода; по желанию о каждом ходе); точка на кнопке Overview в браузере; push на телефон от Dispatch, когда задача готова или нужно «добро». Agent View: терминальные уведомления при «нужен ввод / завершено / ошибка» и события хуков agent_needs_input / agent_completed.
- **Почему работает:** оповещение разделено по причинам (нужен ты / готово / сбой) и настраивается отдельно; pet-трей отделён от системных уведомлений — статус доступен без всплывающих окон.
- **Применимость:** С4, С6, С7. Особенно у владельца, который «отходит» на часы.

**A7. Живая страница-«табло» вместо терминального лога**
- **Кто:** Claude Code Artifacts. [S14] (П)
- **Что именно:** сессия публикует живую страницу на закрытом URL, которая обновляется на месте по мере работы: таймлайн расследования, чек-лист миграции с отметками, дашборд; можно делиться, ставить версии, оставлять комментарии, на которые Claude может отвечать сам.
- **Почему работает:** длительная работа получает адресуемое «табло», доступное вне терминала и вне сессии.
- **Применимость:** С2, С3, С6. Прототип «страницы проекта» с паспортом стадии.

### Блок B. Режимы: чат ↔ план ↔ агент

**B1. Режим как ступень автономии в одном потоке**
- **Кто:** Claude Code/Desktop, Cursor, Lovable, Antigravity, v0, Kimi, Replit. [S1, S7, S40, S55, S57, S67, S66, S52] (П)
- **Что именно:** Claude Code: Shift+Tab по кругу default → acceptEdits → plan (и auto при наличии), строка статуса всегда показывает активный режим («manual mode on», «plan mode on», «auto mode on» и т. п.); в Desktop — селектор режима рядом с кнопкой отправки с метками Manual / Accept edits / Plan / Auto / Bypass permissions. Выбранный режим запоминается по папке, **кроме Plan: он действует только на текущую сессию**. Cursor: Shift+Tab входит в Plan. Lovable: Chat, Plan, Build, «переключайтесь в любой момент, разговор переходит между режимами». Antigravity: режимы Planning и Fast. v0: три режима разрешений Ask / Auto / Full. Kimi: четыре режима K2.5 Instant / Thinking / Agent / Agent Swarm (Beta).
- **Почему работает:** пользователь не «уходит» в другой инструмент; контекст сохраняется, меняется только степень свободы. Не-запоминаемость Plan защищает от случайного застревания в режиме «только читаю».
- **Применимость:** С1 → С2 → С6. Ступени харнесса: обсуждение → дискавери/план → исполнение; переход должен быть виден в постоянной полосе режима.

**B2. План как редактируемый документ с явным шлюзом**
- **Кто:** Claude Code, Cursor, Lovable, Devin, Factory, Antigravity. [S1, S40, S35, S55, S44, S50, S57] (П)
- **Что именно:** Claude Code: план предлагается на утверждение; можно открыть в редакторе (Ctrl+G) и править. Cursor: агент задаёт уточняющие вопросы, строит план в markdown, план правится чатом или файлом, кнопка сборки; в 2.2 — встроенные Mermaid-диаграммы и выбор отдельных задач для передачи разным агентам; можно планировать одной моделью, строить другой. Lovable: план — отдельное представление-документ (обзор подхода, решения, допущения, компоненты, шаги, диаграммы); правится напрямую, версионируется с undo/redo; кнопка Approve переключает в Build; гарантия «код меняется только после утверждения». Devin: за секунды после старта показывает релевантные файлы, находки и предварительный план, который можно менять до автономной работы. Factory: план — набор фич по вехам (milestones) с нужными навыками, утверждается пользователем.
- **Почему работает:** план — единственный артефакт, который читают целиком; шлюз «утвердить» формально отделяет мышление от изменения.
- **Применимость:** С2 — центральный образец. Для стадийного планирования нужна «карточка стадии» с планом, областью, критериями и кнопкой утверждения.

**B3. Утверждение плана = выбор режима исполнения**
- **Кто:** Claude Code. [S1] (П)
- **Что именно:** при утверждении плана предлагаются варианты: «Да, и использовать auto mode» (если auto недоступен — «Да, авто-принимать правки»; при запуске с bypass — вариант перехода в bypass), «Да, править вручную каждую правку», «Нет, продолжать планирование». Утверждение выводит из режима плана и переключает сессию в выбранный режим. Опционально первая строка «утвердить и очистить контекст планирования».
- **Почему работает:** решение «идти» и решение «насколько свободно идти» принимаются одним действием с явными последствиями.
- **Применимость:** С2 → С6: шлюз стадии должен фиксировать не только «утверждено», но и профиль автономии исполнения.

**B4. «План во время сборки» против «план, затем сборка»**
- **Кто:** Replit Agent 4 против Claude/Cursor/Lovable. [S53] (П)
- **Что именно:** Agent 4: планирование и сборка идут одновременно; задачи выполняются в изолированных средах; общая доска Drafts / Active / Ready / Done; ничто не касается основного проекта, пока пользователь явно не одобрит.
- **Почему важно:** это противоположная философия шлюзу B2. Обе сходятся на инварианте «в основную ветку — только после одобрения».
- **Применимость:** С2/С6. Для стадий OMG выбран путь «план-затем-сборка»; из Replit брать инвариант изоляции и одобрения, а не параллельное планирование.

**B5. Комментарии как у Google Docs, агент не останавливается**
- **Кто:** Antigravity, Claude Desktop, Codex, GitHub Copilot, Claude Artifacts. [S56, S57, S7, S27, S63, S14] (П)
- **Что именно:** Antigravity: комментарии к текстовым артефактам и выделение с комментарием на скриншотах; обратная связь учитывается автоматически, не останавливая выполнение; при политике «Request Review» агент останавливается после плана или диффа и уведомляет. Claude Desktop: комментарий на строке диффа, отправка пачкой Cmd+Enter, Claude вносит правки и показывает новый дифф; кнопка «Review code» просит Claude оценить изменения. Codex: строчные комментарии в панели ревью; действия stage/unstage/revert на трёх уровнях — весь дифф, файл, hunk; область диффа: unstaged / staged / commit / branch / last turn. Copilot: рулить можно чатом или комментарием во вкладке Files changed.
- **Почему работает:** обратная связь привязана к месту в артефакте, а не к «общему указанию»; частичное принятие (по hunk) снижает стоимость ревью.
- **Применимость:** С5. Панель ревью с привязкой комментариев и областью диффа «последний ход».

**B6. Артефакты как единица доверия**
- **Кто:** Antigravity, Cursor Cloud Agents, Devin, Replit. [S56, S57, S39, S46, S52] (П)
- **Что именно:** Antigravity: агент сообщает понимание не сырыми вызовами инструментов, а артефактами на «естественном уровне задачи»: Task List (бегущий чек-лист), Implementation Plan («предполётная» проверка), Walkthrough (отчёт после работы с доказательствами проверки), скриншоты и записи браузера. Cursor Cloud Agents: готовые к слиянию PR с демо-артефактами — скриншоты, видео, логи проверки. Devin 2.2: записи экрана тестирования настольных приложений; самопроверка и исправление до открытия PR. Replit Agent 3: в панели агента виден курсор агента, кликающего по приложению.
- **Почему работает:** доверие строится на проверяемых свидетельствах результата, а не на потоке действий.
- **Применимость:** С5, С6. У каждой стадии — обязательный «отчёт с доказательствами».

**B7. Оценка уверенности до и во время работы**
- **Кто:** Devin. [S45] (П)
- **Что именно:** три уровня уверенности (зелёный, жёлтый, красный) выставляются в начале сессии, после составления плана и при ответе на вопросы о коде; при не-зелёном Devin задаёт уточняющие вопросы, чтобы поднять оценку; интеграции Linear/Jira позволяют оценить много задач пакетом без запуска сессий и запускать только самые уверенные. Вендор заявляет: зелёные оценки дают вдвое большую вероятность влитого PR, чем красные (заявление вендора, независимо не проверено).
- **Почему работает:** ожидание «получится ли» появляется до затрат; вопросы агента превращаются в способ повысить шансы.
- **Применимость:** С2/С6. Индикатор готовности стадии «уверенность выполнения» с причиной и вопросами.

### Блок C. Команда агентов

**C1. Панель агентов под полем ввода с входом по Enter**
- **Кто:** Claude Code (subagents, agent teams), Codex. [S3, S4, S23] (П)
- **Что именно:** Claude Code: под полем ввода панель строк; в строке имя, статус, модель (с v2.1.242), у вложенных — дерево со счётчиком потомков (+N); Enter открывает транскрипт агента и позволяет писать ему; x останавливает; Esc возвращает фокус в ввод; Ctrl+B отправляет передний план в фон. В agent teams если простаивают больше трёх, лишние строки схлопываются в одну «N idle agents»; когда простаивают все, строки прячутся через 30 секунд и возвращаются на следующем ходе агента; Ctrl+T показывает общий список задач. Codex: панель Subagents со списками Active и Done; в CLI /agent переключает потоки; запрос одобрения от неактивного потока всплывает поверх, с меткой источника, клавиша o открывает поток-источник до решения.
- **Почему работает:** команда видна постоянно, но не занимает экран; провал вглубь — по требованию; одобрение всегда указывает, от какого агента оно пришло.
- **Применимость:** С4, С6. Ключевой образец «полосы команды».

**C2. Coordinator + панель Overview**
- **Кто:** Cursor Projects, Claude Projects, Factory Missions, Warp Oz, Kimi. [S38, S6, S49, S50, S65, S66] (П)
- **Что именно:** Cursor Projects (10.09.2026): координатор сам код не пишет — планирует, делегирует агентам-исполнителям и возвращает работу на проверку; проект живёт в левой навигации Agents Window, работает в облаке, любого запущенного агента можно открыть, чтобы следить или говорить с ним напрямую; «Listening»-плашка показывает активные подписки (Slack, PR, CI, расписание). Claude Projects: разговор-координатор запускает тред на задачу; Overview показывает треды по состояниям, вкладки Library (файлы), Pull requests, Routines; кнопка Overview показывает точку, когда кто-то ждёт ответа. Factory: после утверждения плана управление переходит в Mission Control — вид с фичами, вехами, назначенными воркерами и прогрессом. Warp Oz: единое окно запуска, отслеживания и управления агентами разных «харнессов»; присоединиться к живой сессии для аудита можно одним нажатием. Kimi K2.5: рой из до 100 субагентов и до 1500 вызовов инструментов; интерфейс отображения роя в прочитанных источниках не описан (Н).
- **Почему работает:** человек говорит с одним «лицом» (координатором), а состояние команды читает на отдельной панели; возможность «нырнуть» в любого исполнителя сохраняет прозрачность.
- **Применимость:** С4. «Оркестратор» как единственный собеседник + панель проекта (Overview) с потоками по состояниям.

**C3. Роль и модель на агента видны в строке**
- **Кто:** Claude Code, Codex, Factory. [S3, S4, S23, S49] (П)
- **Что именно:** Claude: строка задачи содержит тип агента, статус, описание, модель и уровень усилия; модель разрешается в порядке «параметр вызова → определение агента → переменная окружения → модель разговора»; тимейт наследует уровень усилия лидера. Codex: у пользовательского агента поле model. Factory: наблюдение, что ни одна модель не лучшая для всех ролей, оркестратору лучше разворачивать специализированные модели по ролям.
- **Почему работает:** пользователь видит, что за что платит и кто чем занят.
- **Применимость:** С4. В строке агента — роль, модель, усилие.

**C4. Иерархия и счётчик потомков**
- **Кто:** Claude Code, Devin, Copilot. [S3, S47, S64] (П)
- **Что именно:** Claude: вложенные субагенты в виде дерева с (+N); Devin: у родительской сессии значок дерева с доступом к дочерним из заголовка (23.09.2026), вложенное дерево подсессий в панели (21.08.2026), дочерняя сессия наследует контекст родителя через удаляемый чип в композере (25.09.2026); Copilot: работа субагентов свёрнута.
- **Почему работает:** иерархия читается сразу; унаследованный контекст виден и снимаем.
- **Применимость:** С4. Видимый «чип унаследованного контекста» — хороший приём против скрытых допущений.

**C5. Изоляция по умолчанию: worktree на параллельного агента**
- **Кто:** Cursor 2.0, Claude Agent View, Codex, Replit. [S34, S2, S28, S53] (П)
- **Что именно:** Cursor 2.0 (29.10.2025): до восьми агентов на один запрос, каждый в изолированной копии через worktree или удалённые машины. Claude Agent View: фоновые сессии автоматически уходят в worktree перед правкой; по завершении с изменениями коммитят, пушат ветку, открывают черновой PR, никогда не пушат в main/master и не делают force-push. Codex: worktree выбирается при создании чата; кнопка Hand off переносит чат между локальным чекаутом и worktree; хранится 15 последних; ветка может быть чекаутнута только в одном месте. Replit Agent 4: задачи в изолированных средах, «ничто не касается основного проекта без явного одобрения».
- **Почему работает:** параллельность безопасна; конфликт обнаруживается на этапе слияния, а не как порча файлов.
- **Антидоказательство:** у agent teams Claude изоляции нет — две правки одного файла перезаписывают друг друга; вендор советует делить работу по файлам (S4).
- **Применимость:** С4/С6. Изоляция по умолчанию, слияние — шлюз с одобрением.

**C6. Подписки и триггеры видимы**
- **Кто:** Cursor Projects, Claude Routines, Codex Automations. [S38, S13, S30] (П)
- **Что именно:** Cursor: плашка «Listening» с раскрытием событий, за которыми следит координатор; примеры: канал багов в Slack → делегирование при каждом новом баге. Codex: автоматизации по расписанию, результаты проверяются в очереди.
- **Применимость:** С6/С7. Фоновая активность без запроса пользователя должна быть постоянно видна и отключаема.

**C7. Оркестрация скриптом с фазами и тонким управлением**
- **Кто:** Claude Code dynamic workflows. [S5] (П)
- **Что именно:** карточка утверждения (Desktop) показывает имя workflow, список фаз и предупреждение о расходе токенов; действия Once / Always / Deny; в CLI: «Yes, run it», «Yes, and don't ask again», «View raw script» (прочитать скрипт до решения), «No». Панель прогресса: по каждой фазе число агентов, сумма токенов, прошедшее время; проваливание в фазу и в агента (промпт, недавние вызовы инструментов, результат; у агента может быть свой список задач); фильтр по статусу, пауза, остановка, перезапуск агента, сохранение скрипта как команды. В панели задач одна строка сводки. Ограничения: до 16 агентов одновременно по умолчанию, до 1000 на запуск; **нет ввода пользователя посреди запуска — для подписи между стадиями предписано запускать каждую стадию отдельным workflow**. Отчёт помечает непроверенные утверждения как «unverified», а не «опровергнутые».
- **Почему работает:** оркестрация — читаемый, повторяемый артефакт; «непроверенное» не выдаётся за «неверное».
- **Применимость:** С3/С4/С6. Стадийные ворота OMG совпадают с советом вендора: гейт = граница запуска.

**C8. Судейство параллельных результатов с объяснением**
- **Кто:** Cursor 2.2, Claude workflows. [S35, S5] (П)
- **Что именно:** Cursor (10.12.2025): при нескольких параллельных агентах результаты оцениваются автоматически, рекомендуется лучший, у выбранного агента комментарий «почему выбран». Claude workflows: независимые агенты перекрёстно проверяют друг друга до отчёта.
- **Применимость:** С4/С5. Показывать выбор победителя вместе с объяснением, оставляя решение человеку.

### Блок D. Длительные работы: статусы, прогресс, время

**D1. Миссия = вехи + проверка на каждой вехе**
- **Кто:** Factory Missions. [S49, S50] (П)
- **Что именно:** сначала диалог планирования, затем план из фич по вехам, утверждение, затем Mission Control. В конце каждой вехи воркеры-рецензенты проверяют накопленное, гоняют тесты, ищут регрессии и проверяют интеграцию; при проблемах оркестратор создаёт задачи-доработки. Статистика вендора: медианная миссия ~2 часа, 65% длятся больше часа, 37% больше 4 часов, 14% больше суток, самая длинная 16 дней. Роль человека — менеджер проекта: следит, разблокирует, меняет приоритеты; миссии «не fire-and-forget», можно поставить оркестратор на паузу и по-человечески объяснить проблему. Предупреждение о лимите повторов фичи. Наблюдения вендора: последовательное выполнение с точечным распараллеливанием лучше широкого параллелизма; на длинных планах накапливаются ошибки; оркестратор порой берёт слишком много; для лучших результатов нужна автоматическая проверка на уровне пользовательских сценариев.
- **Почему работает:** длительность разбита на проверяемые куски; у пользователя есть роль и точка вмешательства.
- **Применимость:** С6 — прямой аналог стадий OMG с воротами.

**D2. Цель с условием завершения и независимым оценщиком**
- **Кто:** Claude Code /goal; Cursor и Antigravity имеют команду /goal; Codex /goal (В). [S10, S42, S58, S32] (П/В)
- **Что именно:** Claude: условие завершения (до 4000 символов); после каждого хода малая модель выносит вердикт «не выполнено / выполнено / невозможно» с причиной; индикатор «goal active» показывает, как долго идёт; статус (команда /goal без аргументов) показывает условие, время, число оценённых ходов, расход токенов и последнюю причину. Ограничение по ходам или времени задаётся оговоркой в самом условии. Цель автоматически снимается при выполнении, при признании невозможной или при ошибке, которую нужно исправить (аутентификация, исчерпанный баланс, переполнение контекста, недоступная модель); при прочих ошибках — автоповтор с сообщением о причине или пауза с названием причины. При возобновлении сессии условие восстанавливается, но счётчики обнуляются. Фоновая работа откладывает оценку; при долгом ожидании — check-in через 30 минут с нарастающей паузой, максимум три «холостых» check-in подряд. В неинтерактивном режиме до конца работы ничего не печатается — вендор советует потоковый вывод. Codex /goal (В): цель хранится на уровне потока со статусом, токенами и временем, команды pause / resume / clear, токен-бюджет.
- **Почему работает:** «готово» определяет отдельный судья по проверяемому условию, а не сам исполнитель; при остановке всегда названа причина.
- **Применимость:** С6. Каждая стадия должна иметь условие завершения в проверяемой форме и видимый вердикт судьи.

**D3. Список задач как «пульс»**
- **Кто:** Claude Code, Devin, Antigravity, Lovable. [S4, S47, S56, S55] (П)
- **Что именно:** Claude: общий список задач (pending / in progress / completed, зависимости; Ctrl+T); вендор признаёт, что статус задач может отставать (тимейт не отметил выполнение). Devin: вкладка Tasks показывает последний список задач агента (17.07.2026). Antigravity: Task List — бегущий чек-лист. Lovable: карточки активности показывают текущий шаг, изменённые файлы, инструменты; Details — таймлайн всех шагов и изменений.
- **Применимость:** С6. Чек-лист стадии как первичный индикатор прогресса; помечать «статус мог устареть».

**D4. Ожидания по времени: диапазоны, счётчики и классы, не ETA**
- **Кто:** Claude workflows/goal, Devin, Replit, Factory. [S5, S10, S48, S52, S49] (П)
- **Что именно:** показывают прошедшее время, число агентов, токены (Claude workflows), число ходов и время цели (/goal), класс размера сессии XS–XL по расходу ACU постфактум (Devin Session Insights), максимум автономной работы до ~200 минут (Replit Agent 3), статистику длительности миссий (Factory). Прогноза «закончится в HH:MM» в прочитанных источниках не встретил.
- **Почему важно:** честность — агентская работа непредсказуема; пользователю помогают диапазоны и класс задачи.
- **Применимость:** С6. Вместо ETA — «прошло / потрачено / ходов / осталось пунктов чек-листа» и класс масштаба.

**D5. Предупреждение о масштабе без блокировки**
- **Кто:** Claude workflows. [S5] (П)
- **Что именно:** если запланировано больше 25 агентов или прогноз превышает 1,5 млн токенов, в строке прогресса появляется предупреждение «Large workflow», указывающее на панель, где можно остановить запуск; предупреждение рекомендательное. Пользователь задаёт ориентир масштаба (small — меньше 5 агентов, medium — меньше 10, large — меньше 50, unrestricted); вендор советует сначала запустить на малом срезе. При упоре в лимит подписки запуск не падает, а ждёт сброса и продолжается сам; в строке прогресса и заголовке видно время сброса (не более двух ожиданий за запуск, до 24 часов).
- **Применимость:** С6/С7. «Класс масштаба» задаётся до запуска; предупреждение рекомендует малый срез.

### Блок E. Подтверждения (approvals) и риски

**E1. Лестница автономии с понятными названиями**
- **Кто:** Claude (Manual → Accept edits → Plan → Auto → Bypass), Codex (read-only / workspace-write «Auto» / danger-full-access; on-request / never / granular), Antigravity (Request Review / Always Proceed), v0 (Ask / Auto / Full), Replit (Standard App Testing / Max Autonomy Beta). [S1, S7, S22, S57, S67, S52] (П)
- **Что именно:** Codex предлагает предустановку по контексту: в папке под git — Auto (запись в рабочей папке, спрос при выходе за неё или при сети), вне git — read-only; сеть по умолчанию выключена; повышенный риск помечен значком «ElevatedRisk» в документации. Claude Desktop: ни один режим не одобряет автоматически ряд действий (например, удаление критических путей); в Bypass остаются защитные проверки на внешних сайтах.
- **Почему работает:** пользователь выбирает не «параметр», а ступень с названием; разумный дефолт зависит от контекста.
- **Применимость:** С1/С6. Профиль автономии с названными ступенями и разными дефолтами для «в git / вне git».

**E2. Мониторинг + прерывание вместо поштучных одобрений**
- **Кто:** Anthropic (исследование и auto mode). [S17, S18, S1] (П)
- **Что именно:** пользователи Claude Code одобряют 93% запросов на разрешение (S18). Среди новых пользователей ~20% сессий идут с полным авто-одобрением; у опытных (750+ сессий) больше 40%; доля прерываний растёт с опытом: 5% ходов у новых и ~9% у опытных (S17). Claude сам останавливается чаще, чем его прерывают человеком: причины пауз — выбор между подходами 35%, сбор диагностики 21%, уточнение неясного запроса 13%, недостающие ключи 12%, запрос одобрения 11%. Вывод авторов: эффективный надзор не требует одобрять каждое действие, а требует возможности вмешаться. Самые длинные сессии выросли с <25 до >45 минут за три месяца (99,9-й перцентиль, окт. 2025 – янв. 2026). Auto mode: классификатор проверяет действия; по заявленным метрикам ложные срабатывания 0,4% на реальном трафике, пропуск опасных «излишне инициативных» действий 17%, пропуск синтетических попыток утечки 5,7%; при 3 подряд или 20 суммарных блокировках режим приостанавливается и снова спрашивает человека; заблокированное действие видно во вкладке Recently denied с повтором вручную. С v2.1.283 auto — стартовый режим интерактивных сессий. Вендор подчёркивает, что auto mode не гарантирует безопасность.
- **Почему работает:** внимание расходуется там, где решение неочевидно; предохранитель возвращает человека при повторных отказах.
- **Применимость:** С6. Проектировать «окно наблюдения» и быстрые прерывание/руление, а не бесконечные диалоги.

**E3. Карточка одобрения с областью действия**
- **Кто:** Claude Desktop, Claude workflows, Cowork. [S7, S5, S20] (П)
- **Что именно:** для внешних сайтов карточка предлагает «Allow once», «Always allow» (сохраняется для сайта на устройстве, включая поддомены отдельно) и «Deny»; для использования компьютера — «Allow for this session» или Deny, одобрения живут сессию, в сессиях от Dispatch — 30 минут. Карточка workflow: имя, фазы, предупреждение о токенах; Once / Always / Deny. Cowork: Claude просит явного разрешения перед безвозвратным удалением файлов и работает только в подключённых папках.
- **Почему работает:** пользователь решает и о действии, и о сроке доверия.
- **Применимость:** С6. Три кнопки + срок; карточка перечисляет, что будет сделано.

**E4. Необратимое и платное — всегда с подтверждением**
- **Кто:** Replit, Cowork, Claude, Codex, ChatGPT agent (Н). [S54, S20, S1, S22, S33] (П/Н)
- **Что именно:** Replit спрашивает подтверждение перед началом платного действия. Cowork — перед безвозвратным удалением. Claude Code: набор действий, которые не одобряются ни в одном режиме (например, удаление критических путей). Codex: сеть выключена по умолчанию. ChatGPT agent: по сниппетам поиска есть подтверждение перед значимыми действиями, режим «watch» на чувствительных сайтах и режим «takeover» для ввода секретов самим пользователем — не подтверждено (403).
- **Применимость:** С6. Список «всегда с подтверждением»: удаление, платное, внешняя публикация, секреты.

**E5. Одобрение маршрутизируется в единое место и называет источник**
- **Кто:** Claude subagents, Codex. [S3, S23] (П)
- **Что именно:** запрос разрешения фонового субагента всплывает в основной сессии и называет запросившего; отказ по Esc отклоняет один вызов, не останавливая субагента; выданное постоянное разрешение действует на всю сессию, включая субагентов. У Codex одобрение неактивного потока подсвечено меткой источника.
- **Антипаттерн рядом:** в Claude Projects одобрение можно дать только внутри самого треда; указание «продолжай» в разговоре проекта до треда не доходит (S6).
- **Применимость:** С4. Единая очередь одобрений с адресом источника; одобрение действует там, где показан запрос.

**E6. Границы, заданные словами, — сигнал для блокировки, но не гарантия**
- **Кто:** Claude auto mode. [S1] (П)
- **Что именно:** сказанное в разговоре («не пушь», «подожди моего ревью») классификатор считает сигналом блокировки и перечитывает из транскрипта при каждой проверке; граница может быть потеряна при сжатии контекста; для жёсткой гарантии нужно правило deny. Одобрение обычно покрывает одно названное действие.
- **Применимость:** С1/С6. Границы владельца хранить как явные правила, а не только фразы.

**E7. Агент-рецензент перед выполнением**
- **Кто:** Codex auto-review; Claude classifier. [S22, S18] (П)
- **Что именно:** Codex: рецензент-агент оценивает запросы на одобрение: проверяет на утечку данных, зондирование учётных данных, разрушительные действия; критический риск отклоняется, высокий требует авторизации пользователя; дополнительные вызовы моделей учитываются в расходе.
- **Применимость:** С5/С6. Ступень «проверка агентом» между «делай сам» и «спроси человека».

**E8. Разметка происхождения чужих сообщений**
- **Кто:** Claude subagents/teams/cross-session messaging. [S3, S4, S7] (П)
- **Что именно:** результат субагента приходит с пометкой, что инструкции в нём не имеют полномочий пользователя; в тексте, имитирующем служебные теги, экранируются символы; сообщение от другой сессии показывается карточкой с названием отправителя и ссылкой обратно; сообщения держатся, пока принимающая сессия занята; тимейт не может одобрить действие вместо пользователя.
- **Почему работает:** пользователь всегда видит, кто автор и что это не его распоряжение.
- **Применимость:** С4. В канале агентов у каждого сообщения — автор, роль и признак «не полномочие владельца».

### Блок F. Стоимость и риск

**F1. Цена показывается после факта, с лимитом и предупреждениями**
- **Кто:** Replit, Lovable, Devin, Claude, Cursor, Warp, Copilot. [S54, S55, S48, S47, S11, S39, S65, S63] (П)
- **Что именно:** Replit: стоимость каждого чекпойнта видна по наведению на значок использования; один чекпойнт на запрос; дашборд использования с задержкой до ~30 минут; оповещения по порогам и жёсткий лимит; режим Plan может тратить средства без изменений кода. Lovable: авансовой оценки в Build нет (стоимость зависит от найденной по ходу работы), «Credits used» видно во время работы и по итогу; остановка кнопкой Stop немедленная, списывается только выполненное, изменения остаются, пока не отменены. Devin: класс размера сессии XS–XL по ACU, вкладка Consumption по автоматизациям (22.07.2026). Claude: /usage показывает расход по сессии и плановые полосы; разбивку по навыкам, субагентам, плагинам, MCP-серверам; флаги поведения, если одно поведение даёт 10% и более недавнего расхода; строки по самым тяжёлым циклам /loop; при недоступности данных показывает «Showing last-known usage» с возрастом. Cursor Cloud Agents: тарификация по API, лимит расходов задаётся при первом запуске. Warp: кредитные лимиты на команду и на человека. Copilot: каждое сообщение-руление расходует кредиты.
- **Оценка:** ни один продукт из прочитанных не даёт надёжной авансовой оценки для открытой агентной работы; лучшая практика сочетает: класс масштаба до запуска, бегущий счётчик, лимит-предохранитель, разбивку по причинам.
- **Применимость:** С6. Бюджет стадии — обязательное поле; счётчик виден всё время.

**F2. Разбор после факта (Session Insights)**
- **Кто:** Devin. [S48] (П)
- **Что именно:** вкладки: Issue Timeline (проблемы с оценкой влияния и хронология событий), Actionable Feedback (улучшенный промпт и действия по окружению), Knowledge Usage (какие знания помогли или ввели в заблуждение); показывает число сообщений пользователя, класс размера, категоризацию.
- **Применимость:** С5/С7. Итоговый отчёт стадии с таймлайном проблем и «что улучшить».

### Блок G. Восстановление и передача между поверхностями

**G1. Супервизор: сессии переживают окно**
- **Кто:** Claude Agent View. [S2] (П)
- **Что именно:** фоновая служба-супервизор держит сессии независимо от терминала, перезапускает случайно вышедшие процессы, переживает автообновления; простаивающий процесс может остановиться примерно через час и возобновляется при взаимодействии; закреплённая сессия (Ctrl+T) держится всегда; удалённая из списка сессия возобновляется через `claude --resume`. Ограничения: только локально, при выключении компьютера останавливается.
- **Применимость:** С7. Процесс прогона должен жить вне окна харнесса; «простаивает-остановлен-возобновляется» видно явно.

**G2. Возобновление со состоянием и честными оговорками**
- **Кто:** Claude workflows/goal/Remote Control, Devin, Factory, Cursor. [S5, S10, S12, S47, S51, S37] (П)
- **Что именно:** workflows: запуск переигрывается, завершённые агенты возвращают сохранённые результаты, первый агент с изменившимся промптом и все после него выполняются заново, упавший агент перезапускает всех последующих; возобновление возможно только в той же сессии. Цель восстанавливается при resume, но счётчики обнуляются. Remote Control: диалог и прогресс субагентов/workflows синхронизированы между устройствами; при спящем ноутбуке или обрыве сети соединение восстанавливается автоматически. Devin: сессия «просыпается» при наборе текста (16.09.2026); действие «Reboot VM» появляется в боковой панели для заблокированных/упавших машин (11.09.2026). Factory Droid Computers: среда, файловая система, учётные данные и память процесса сохраняются между сессиями, простаивающие компьютеры засыпают, платится только время бодрствования. Cursor: облачный агент продолжает работу вне ноутбука.
- **Применимость:** С7. Возобновление — видимая операция с описанием, что будет пересчитано и что сохранено; действие восстановления привязывается к состоянию «блок».

**G3. Откат: контрольные точки с честным списком «что не откатывается»**
- **Кто:** Claude Code checkpointing, Cursor, Lovable, Copilot. [S9, S41, S55, S63] (П)
- **Что именно:** Claude: контрольная точка на каждый запрос, начавший ход (хранятся 100 последних; срок хранения по умолчанию около 30 дней); меню /rewind или двойной Esc предлагает: восстановить код и разговор / только разговор / только код / «Summarize from here» / «Summarize up to here» / «Never mind». Оговорки: изменения через Bash, правки субагентов и внешние правки не отслеживаются; символьные и жёсткие ссылки не откатываются; сообщения, вошедшие в идущий ход, точек не создают; чекпойнты — не замена git. Cursor: чекпойнты откатывают только файлы, не сообщения. Lovable: остановка сохраняет изменения. Copilot: «Stop session» прерывает запуск, сохраняя запушенные коммиты.
- **Применимость:** С7. Кнопка отката должна сама говорить, что не будет восстановлено.

**G4. Передача между поверхностями с ясными условиями**
- **Кто:** Claude, Codex, Cursor, Warp. [S13, S7, S26, S37, S65] (П)
- **Что именно:** Claude: Remote Control (телефон/браузер к локальной сессии), Dispatch (задача с телефона выполняется на десктопе; push при готовности или запросе «добра»; компьютер должен быть включён и приложение открыто), `--teleport`, `/desktop`, Slack. Desktop → Web: нужен чистый рабочий каталог; создаётся **новая** облачная сессия с сводкой и полным контекстом. Codex Remote: мониторинг и одобрения с телефона через QR-сопряжение, компьютер должен быть включён и онлайн. Cursor: передача облако ↔ локально в обе стороны. Warp: локально ↔ удалённо. Factory: управление Droid'ами через телефон.
- **Почему важно:** во всех случаях сказано, при каком условии работа идёт (компьютер включён, чистое дерево) и что «передача» создаёт новую сессию.
- **Применимость:** С7. Показывать состояние связи («хост онлайн/спит») как часть статуса.

**G5. Причина паузы всегда названа**
- **Кто:** Claude /goal, Linear, Devin. [S10, S60, S47] (П)
- **Что именно:** /goal печатает «Goal still active» с временем до повтора или «Goal paused» с названием причины; Linear автоматически ставит состояние `stale` и позволяет вывести из него новой активностью, требует первой реакции агента в течение 10 секунд, иначе агент показывается как не отвечающий, и продолжать активность до 30 минут; Devin: пропущенные вопросы отображаются как «skipped» в транскрипте и в Slack (16.09.2026).
- **Применимость:** С7. Состояние «пауза» без причины запрещено.

### Блок H. Дисциплина агента как участника

**H1. Шесть принципов Agent Interaction Guidelines (Linear)**
- **Кто:** Linear. [S60] (П)
- **Что именно (перефраз):** агент всегда раскрывает, что он агент; работает через нативные элементы платформы; мгновенно подтверждает получение запроса; прозрачно показывает внутреннее состояние (думает, ждёт ввода, выполняет, завершил) с возможностью осмотреть рассуждения; немедленно прекращает работу по просьбе и не возобновляет без ясного сигнала; не может нести ответственность — она остаётся на человеке. Типы активности: thought, action, elicitation (запрос уточнения), response, error; действие без результата означает «в работе», позже обновляется результатом.
- **Применимость:** С4/С6. Готовый словарь событий журнала агента.

**H2. Агент сам инициирует остановку — это первоклассная функция**
- **Кто:** Anthropic (S17), Linear (elicitation). (П)
- **Что именно:** из данных S17 следует, что паузы по инициативе агента (вопросы, выбор подхода) вдвое чаще прерываний человеком. Значит, вопрос агента должен быть первоклассным событием в интерфейсе (очередь, срочность, срок), а не «ещё одним сообщением».
- **Применимость:** С2/С4/С6.

**H3. Два глагола: «поставить в очередь» и «направить сейчас»**
- **Кто:** Cursor, Claude, Copilot, Lovable, Codex. [S41, S16, S9, S63, S55, S29] (П)
- **Что именно:** Cursor: Enter — в очередь до завершения задачи, Cmd+Enter — направить активный ход (сообщение прикрепляется к результатам инструментов). Claude: сообщения можно ставить в очередь во время работы; Esc прерывает ход, сохраняя сделанное, и очередь отправляется сразу; сообщение, вошедшее в идущий ход, не создаёт контрольной точки. Copilot: руление применяется после завершения текущего вызова инструмента и расходует кредиты. Lovable: сообщения во время сборки подхватываются в ближайшей естественной остановке. Codex CLI 0.159 (29.09.2026): опциональное `instant_interrupt` для руления посреди ответа.
- **Применимость:** С1/С6. Явный выбор «после текущего шага / прервать сейчас».

**H4. Побочный вопрос, не ломающий основную нить**
- **Кто:** Claude Desktop. [S7] (П)
- **Что именно:** боковой чат (Cmd+; или /btw) использует контекст сессии, но ничего не добавляет в основной разговор; закрывается и не сохраняется на диск.
- **Применимость:** С1/С6. Вопросы «что это значит» без вмешательства в ход исполнения.

**H5. Взять управление и вернуть**
- **Кто:** Cursor Cloud Agents, Devin, Warp, ChatGPT agent (Н). [S39, S44, S65, S33] (П/Н)
- **Что именно:** Cursor: можно взять управление удалённым рабочим столом агента, чтобы протестировать самому, и вернуть ему; Devin 2.0: у каждой сессии интерактивная облачная IDE, в которой можно править параллельно; Warp: присоединиться к живой сессии и вести или аудировать.

## Антипаттерны и провалы

Все пункты подтверждены документацией самих вендоров, если не указано иное.

1. **Усталость от одобрений.** 93% запросов разрешений одобряются, значит, поштучные диалоги превращаются в ритуал (S18). Ответ вендора — классификатор и режим auto, но он сам не безопасен: 17% пропуска излишне инициативных действий на замерах (S18).
2. **Молчаливый запуск.** Неинтерактивный /goal не печатает ничего до конца — «выглядит зависшим» (S10). Уход в фон без сигналов состояния неприемлем.
3. **Шок от стоимости.** У Replit Agent 3 эффективное ценообразование вызвало волну жалоб (вторичные источники сообщают о счетах порядка $1000 за неделю — не подтверждено первоисточником, В); в документации указано, что даже режим Plan может стоить денег без правки кода (S54). У Lovable нет авансовой оценки — тревога пользователя закладывается в дизайн (S55).
4. **Скрытое порождение агентов.** При включённых agent teams именованный субагент запускается как тимейт, и Claude Code не просит подтвердить запуск; панель сама по себе не показывает, команда это или субагенты (S4). Скрытая стоимость: команды расходуют существенно больше токенов (по S11 около 7× у тимейтов в plan mode).
5. **Шлюз, который не шлюз.** План тимейта автоматически утверждается лидером без просмотра пользователем (S4). Метка «утверждение плана» вводит в заблуждение.
6. **Отставание статусов задач.** Тимейты иногда не отмечают задачи выполненными, блокируя зависимые (S4). Нужен способ «сверить с действительностью».
7. **Исчезающие строки.** Строки простаивающих агентов прячутся через 30 секунд, строки завершённых субагентов пропадают сразу и остаются в /tasks 30 секунд (S3, S4). В документе есть отдельный раздел «строка исчезла — не остановлена», то есть пользователи путались (S4).
8. **Мёртвые «призраки» после возобновления.** In-process тимейты не восстанавливаются при resume, лидер может писать несуществующим агентам (S4).
9. **Одобрение не там.** В Claude Projects распоряжение в разговоре проекта не снимает запрос одобрения в потоке (S6).
10. **Общие файлы без изоляции.** Два тимейта правят один файл — перезапись; вендор предписывает делить работу по файлам (S4).
11. **Ложное чувство отката.** Контрольные точки не покрывают Bash, субагентов, внешние правки (S9).
12. **Границы «на словах» теряются.** Ограничение из разговора может исчезнуть при сжатии контекста (S1).
13. **«Запустил и забыл» для длинных работ.** Factory прямо называет миссии «не fire-and-forget»: длинные планы накапливают ошибки, оркестраторы иногда берут слишком много (S49, S50).
14. **Текучка терминологии и функций.** Ultraplan удалён из Claude Code (S15); у Lovable Agent/Chat переименованы в Build/Plan, документация в разных местах называет режимы по-разному (S55, В); Claude Desktop переименовал режимы (были Ask permissions, Auto accept edits, Plan mode) (S7); Antigravity 2.0 — отдельное приложение, а Inbox прежнего Agent Manager, судя по форумным жалобам, исчез (В, не подтверждено). Урок: не привязываться к чужим названиям.
15. **Сбой связи как невидимое состояние.** Dispatch и Codex Remote работают, только пока компьютер включён и приложение открыто (S19, S26). Если интерфейс не показывает «хост недоступен», пользователь считает, что «ничего не происходит».
16. **Смешение разных причин в одной группе.** «Waiting on you» у Claude Projects включает и ожидание ответа, и сбой (S6). Пользователь не отличает «нужно решение» от «сломалось».
17. **Пропуск оценки перед стоимостью.** Отсутствие авансовой оценки, наряду с невозможностью отменить оплаченное (Replit: usage-данные видны до 30 минут позже, S54).

## Критерии и чек-лист

Формулировки проверяемые: «да/нет» на конкретном экране.

**Ориентация (где я, что происходит)**
1. С любого экрана за 3 секунды можно ответить: проект, поток, режим, стадия. (А1, В1)
2. Активный режим всегда виден в постоянной полосе и не «залипает» (режим наблюдения/плана не сохраняется между сессиями по умолчанию). (В1)
3. Список потоков сгруппирован по состоянию; отдельная очередь «нужен человек» с счётчиком. (А2)
4. Словарь состояний ≤ 7; у каждого слово + значок формы + цвет; «сбой» и «жду решения» разведены. (А3, антипаттерн 16)
5. У каждого потока одна строка-резюме: что делает, а у блокированного — вопрос. (А4)
6. Есть три глубины: строка → быстрый просмотр с ответом → полный поток. (А5)
7. Оповещения разделены по причинам (нужен ты / готово / сбой) и настраиваются отдельно; есть тихий индикатор без всплывающих окон. (А6)

**Шлюзы и режимы**
8. План — редактируемый документ; утверждение — отдельное явное действие. (В2)
9. Утверждение фиксирует профиль автономии исполнения. (В3)
10. Комментарии привязаны к месту в артефакте; агент продолжает работу. (В5)
11. Каждая стадия сдаётся с отчётом и доказательствами. (В6)
12. Показана оценка уверенности с причиной и вопросами. (В7)

**Команда**
13. Панель команды: роль, модель, усилие, статус в каждой строке; вход в агента по одному действию. (С1, С3)
14. Единая очередь одобрений с адресом источника. (Е5)
15. У каждого сообщения агента виден автор и признак «не полномочие владельца». (Е8)
16. Параллельные агенты изолированы; слияние — шлюз с одобрением. (С5)
17. Создание агентов не происходит молча: видно, кто их создал, зачем и что это стоит. (антипаттерн 4)

**Длительная работа**
18. У стадии есть условие завершения в проверяемой форме и независимый вердикт. (D2)
19. Прогресс показан как пройденное/потраченное/осталось пунктов, без ложного ETA; есть класс масштаба. (D4, D5)
20. Любая остановка/пауза называет причину; статусы помечают возможное устаревание. (G5, D3)
21. Неинтерактивный или фоновый запуск не молчит: есть поток событий. (антипаттерн 2)

**Риск и стоимость**
22. Есть названные ступени автономии, дефолт зависит от контекста (в git / вне git). (Е1)
23. Карточка одобрения показывает действие, область (один раз / всегда / отказ) и срок доверия. (Е3)
24. Список «всегда с подтверждением»: удаление, платное, публикация наружу, секреты. (Е4)
25. Бюджет и бегущий счётчик расхода видны всегда; жёсткий лимит; предупреждение о масштабе не блокирует, но ведёт к остановке. (F1, D5)

**Восстановление**
26. Процесс переживает закрытие окна; состояния «простаивает/остановлен/возобновляется» видны. (G1)
27. Возобновление объясняет, что сохранено и что будет пересчитано. (G2)
28. Откат заранее перечисляет, что не будет восстановлено. (G3)
29. Статус связи хоста («онлайн / спит») — часть статуса. (G4, антипаттерн 15)
30. После сбоя рядом с состоянием «блок» лежит действие восстановления. (Блок I)

## Что не нашёл

- **Прогноз времени завершения (ETA).** Ни в одном прочитанном продукте. Это не доказывает отсутствие, а лишь то, что в первоисточниках я его не встретил (Н).
- **Как отображается рой Kimi Agent Swarm** (интерфейс). Есть только характеристики (100 субагентов, 1500 вызовов; в K2.6 по вторичным источникам 300 и 4000). Первичного описания UI не нашёл.
- **Perplexity Comet/Computer.** Страницы changelog, блог и help-center вернули 403. Из сниппетов поиска: страница Background Assistants в Comet объединяет запуск задач, подтверждения и уточнения; Computer работает как «всегда включённый» агент с подтверждением чувствительных действий, журналом аудита и аварийным отключением. Всё это не подтверждено полным чтением.
- **ChatGPT agent** (watch/takeover): справка OpenAI вернула 403; факты из сниппетов не подтверждены.
- **Анонс Codex app** (openai.com) вернул 403: дата 02.02.2026 и описание «командного центра» — из вторичных источников. Из документации не описаны: режим Plan в приложении, боковые чаты, вид Activity в деталях, статусы потоков в боковой панели (кроме перечня в Notifications/Pets). Goals в Codex подтверждены только вторичным источником (S32).
- **GitHub Copilot:** конкретные значения статусов сессий на прочитанных страницах не перечислены. Agent HQ: анонсировано участие агентов Anthropic, OpenAI, Google, Cognition и xAI через платные подписки — какие из них реально доступны на 30.09.2026, не проверял.
- **Cursor:** раздел «Needs Attention» в Agents Window упомянут только вторичным источником (S43); первичного подтверждения не нашёл.
