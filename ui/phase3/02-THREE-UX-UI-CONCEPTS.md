# Три концепции UX/UI Harness (Верстак 2026–2027): Номинанты премий

> **Стандарт подачи:** UX Design Awards (IDZ Berlin), iF Design Award, Red Dot Best of the Best, Webby Awards, Fast Company Innovation by Design.  
> **Миссия:** Задать индустриальный стандарт управления автономными моделями, где с первого взгляда понятны **7 инвариантов** и физически разделены **4 пространства (Проект · Обсуждение · Код · Продукт)**.

---

## Сравнительная таблица трёх концепций

| Критерий сравнения | Концепция 1: «Action Horizon» (Горизонт действий) | Концепция 2: «Spatial Quadrant» (Пространственный верстак) | Концепция 3: «Deterministic Gateway» (Рельсы истины) |
|:---|:---|:---|:---|
| **Главная метафора** | Пульт управления полётами (Air Traffic Control) | Инженерный верстак архитектора (Architect's Workbench) | Интерактивный бортовой формуляр (Stage-Gate Ledger) |
| **Домашний экран (Home)** | Экран **«Сейчас»** (Очередь решений + Ход работ) | **Квадрант 4 пространств** (Проект · Диалог · Код · Продукт) | **Живой документ этапа** со шлюзами допуска |
| **Где фокус внимания** | Момент принятия решения человеком | Синхронная связь архитектуры, кода и продукта | Неизменяемая цепочка доказательств и критериев |
| **Решение проблемы 7 инвариантов** | Плавающий бейдж инвариантов над каждой задачей | Постоянная статус-строка + подсветка в квадрантах | Инспектор шага в полях живого документа |
| **Как решается возврат (Рекап)** | Полноэкранный брифинг «Сводка визита» за 5 секунд | Подсветка изменённых узлов во всех 4 панелях | Маркеры правок на полях документа этапа |
| **Главная победная сила для жюри** | Радикальная экономия времени, нулевая усталость от ИИ | Пространственная наглядность, отсутствие потери контекста | Безупречная надежность, 0% галлюцинаций и молчаливых сбоев |
| **Целевая номинация** | **UXDA:** Outcome, Business Value & Usability | **iF / Red Dot / Awwwards:** Design Quality & IxD | **Fast Company / UXDA:** AI Responsibility & Trust |

## 1. Концепция 1: «Action Horizon / Горизонт действий» (Диспетчерская ответственности)

### 1.1 Архитектурная идея и философия
В эпоху десятков фоновых агентов главная проблема владельца — **паралич внимания**. Концепция «Action Horizon» строится вокруг принципа: *«Интерфейс беспокоит человека только тогда, когда цена решения максимальна, и делает принятие этого решения мгновенным»*.

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ СТРОКА СТАТУСА: [📁 OMG-Dev]  [Этап 3: Разработка]  [● 2 агента в работе]  [⏸ Ждёт вас: 1] [$1.80] │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────────────────────────────────────────────────────────┐ │
│ │ ⏸ ГОРИЗОНТ РЕШЕНИЙ (Очередь «Ждёт вас» — возраст старейшего: 4 мин)                         │ │
│ │                                                                                              │ │
│ │ [!] Задача: OAuth 2.0  •  Исполнитель: Claude 3.7  •  Риск: Средний (миграция БД)           │ │
│ │     Вопрос: «Добавить колонку google_id в таблицу users?»                                    │ │
│ │     [✓ Одобрить (Пробел)]   [👁 Посмотреть SQL-дифф (D)]   [✕ Отклонить (Esc)]               │ │
│ └──────────────────────────────────────────────────────────────────────────────────────────────┘ │
│ ┌──────────────────────────────────────────────────────────────────────────────────────────────┐ │
│ │ ФРОНТ РАБОТ И КОМАНДА (Что происходит прямо сейчас)                                          │ │
│ │ ─── Агент 1 (Архитектор): [✓ Завершил схему API] ──► Артефакт: openapi.yaml                 │ │
│ │ ─── Агент 2 (Кодер):      [● Пишет юнит-тесты auth_test.py] (прошло 42 сек, расход: $0.15)    │ │
│ │ ─── Агент 3 (Ревьюер):    [◷ Ждёт завершения тестов Кодером]                                │ │
│ └──────────────────────────────────────────────────────────────────────────────────────────────┘ │
│ ┌──────────────────────────────────────────────────────────────────────────────────────────────┐ │
│ │ НАВИГАЦИЯ 4 ПРОСТРАНСТВ:  [📁 Проект]   [💬 Обсуждение]   [💻 Код (2 правки)]   [🚀 Продукт] │ │
│ └──────────────────────────────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 UX-сценарии и ключевые экраны
* **Экран E1 («Сейчас»):** Очередь решений сгруппирована по срочности и цене простоя. Если всё тихо — экран отображает «Состояние покоя»: зелёный пульс, прогресс текущего этапа и сводку экономии времени.
* **Экран E5 («Чат → План»):** Момент перехода от разговора к делу. В чате появляется кнопка `[Сформировать план этапа]`. По нажатию открывается шлюз с 4 полями: Цель, Ожидаемый артефакт, Бюджетный лимит и Критерии приёмки.
* **Экран E11 («Сводка возвращения»):** При открытии ноутбука после паузы поверх всего экрана плавно появляется карточка «Что произошло за время отсутствия (2 ч 15 мин)»: 3 выполненных шага, 1 запрос решения, $0.85 потрачено.

## 2. Концепция 2: «Spatial Quadrant / Пространственный верстак» (Объектная среда)

### 2.1 Архитектурная идея и философия
Интерфейс уничтожает переключение вкладок. Все 4 сущности работы с продуктом (**Проект, Диалог, Код, Продуктовый результат**) сосуществуют на одном экране в гибкой пространственной связке с синхронным фокусом.

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ ВЕРСТАК ХАРНЕССА • [OMG-Dev / feature-oauth] • [7 Инвариантов: L5 Код • Тесты • ETA 2м • Низкий]│
├───────────────────────────────┬────────────────────────────────┬─────────────────────────────────┤
│ 📁 ПРОЕКТ (Архитектура)       │ 💬 ОБСУЖДЕНИЕ (Диалог)         │ 💻 КОД И ТЕСТЫ                  │
│                               │                                │                                 │
│ ▼ Этап 3: Разработка          │ Владелец:                      │ auth_service.py                 │
│   ├── [✓] Спецификация API    │ Сделай вход через Google.      │ @@ -12,6 +12,14 @@              │
│   ├── [●] Сервис авторизации  │                                │ +def verify_google_token(t):    │
│   │   └── L5: Юнит-тесты      │ Ассистент:                     │ +    payload = id_token.verify()│
│   └── [ ] UI экрана входа     │ Написал логику проверки токена.│ +    return payload['email']    │
│                               │ Запускаю 8 тестов.             │                                 │
│ [Инспектор задачи: 7 инвариан-│ [Поручение модели...      (↵)] │ [● 8/8 тестов: ОК (0.4с)]      │
│  тов отображаются здесь]      │                                │                                 │
├───────────────────────────────┴────────────────────────────────┴─────────────────────────────────┤
│ 🚀 ПРОДУКТ (Живое превью работающего сервиса / Webview: localhost:3000/login)                    │
│ [ Экран входа с появившейся синей кнопкой "Войти через Google" (активна, кликабельна) ]          │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 UX-сценарии и ключевые экраны
* **Интерактивная связность (Live Binding):** Когда модель правит `auth_service.py` в панели Кода, в панели Проекта узел «Сервис авторизации» подсвечивается зеленым ореолом, а в нижней панели Продукта страница авторизации мгновенно перезагружается с новой кнопкой.
* **Экран E7 («Карта проекта»):** Пространственная схема зависимостей (узлы и связи). Клик на узел подсвечивает историю его обсуждения и связанные коммиты.
* **Экран E4 («Комната обсуждения»):** Строка ввода объединена с пультом условий хода: выбор модели, лимит токенов, глубина рассуждений и кнопка «Только консультация / Применить к коду».

## 3. Концепция 3: «Deterministic Gateway / Рельсы истины» (Документ и шлюзы)

### 3.1 Архитектурная идея и философия
Опирается на традицию высоконадежной инженерии (авиастроение, космические миссии). Главный артефакт работы — не эфемерный чат, а **Инженерный документ этапа (Stage Specification)**. Модели предлагают структурированные патчи к документу и коду, а продвижение по конвейеру контролируется строгими математическими и человеческими шлюзами допуска.

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ ЭТАПЫ: [1. Исследование ✓] ──► [2. Архитектура ✓] ──► [3. Разработка ◐] ──► [4. Приёмка 🔒] ──► │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│ ДОКУМЕНТ ЭТАПА: «Спецификация интеграции OAuth 2.0» (Версия 1.4, статус: Исполнение)             │
│                                                                                                  │
│ 1. ЦЕЛЬ И ГИПОТЕЗА [✓ Подтверждено]                                                              │
│    Интеграция ускорит регистрацию на 40%. Источник: исследование аналитики воронки.              │
│                                                                                                  │
│ 2. ТРЕБОВАНИЯ И СВЯЗИ [✓ Зафиксировано]                                                          │
│    Использовать Google Identity Services SDK 2026. Запрет хранения refresh token в cookies.     │
│                                                                                                  │
│ 3. ХОД ИСПОЛНЕНИЯ [● Шаг 3 из 5: Написание тестов]                                               │
│    ┌────────────────────────────────────────────────────────────────────────────────────────┐    │
│    │ ПРЕДЛОЖЕНИЕ МОДЕЛИ #12: «Патч для auth_test.py (добавлено 3 негативных теста)»        │    │
│    │ Доказательство: Все 5 проходов самопроверки пройдены (Пути, Отсутствие, Маскарад).      │    │
│    │ [✓ Принять правку в документ и код]       [💬 Обсудить на полях]      [✕ Отклонить]   │    │
│    └────────────────────────────────────────────────────────────────────────────────────────┘    │
│                                                                                                  │
│ 4. КОНТРОЛЬНЫЙ ШЛЮЗ ВЫХОДА ИЗ ЭТАПА (Gate Condition to Phase 4):                                 │
│    [✓] 100% тестов пройдены без единого флака                                                   │
│    [✓] Расход этапа: $1.40 (в рамках лимита $3.00)                                              │
│    [ ] Личная подпись владельца: [ Подписать и открыть этап приёмки (Cmd+Enter) ]                │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 UX-сценарии и ключевые экраны
* **Экран E6 («Документ стадии»):** Редактируемый markdown-документ с интерактивными плашками статусов. Никаких «рассуждений ни о чём» — каждое предложение модели оформляется как конкретный пункт спецификации или блок кода.
* **Экран E10 («Расход и лимиты»):** Честный учёт каждого цента. График «Обещанный бюджет этапа vs Реальный факт». Если модель выходит за рамки сметы более чем на 15%, документ этапа автоматически блокируется до утверждения владельцем.
* **Экран E12 («Строки сбоя и восстановление»):** При любой ошибке создаётся «Акт сбоя»: точная причина падения, список неизменённых файлов и кнопка `[Откатить к контрольной точке L2]`.
