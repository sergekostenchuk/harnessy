## §0 Вердикт

1. Прототип показывает правильную **структуру** доверия (слова вместо приборов, «приписано?», «нет сигнала», «порог не задан»), но на **данных** лжёт молча: 1 203 из 1 271 числовых фрагментов (94,6 %) набраны руками, пометок «пример/макет» на экранах — 0; из 20 самых заметных чисел 13 выдуманы (65 %), и ещё 4 из 7 «живых» подписаны неверно (чисто только 3 из 20).
2. Самое опасное: вкладка «Исполнители» с процентами, которые противоречат данным в том же файле и арифметически невозможны, плюс кнопки «Выдать Fable» / «Сменить»; и «решения со следом» («вы · кнопкой · 21:40»), которых в реальных данных нет (`from=owner` — 0 из 2 234 строк канала).
3. Принципы 5 и 7 дизайн-системы нарушены самим прототипом: зелёным нарисованы «Готово к проверке» (×5) и «жив» (×8), а кнопка «Закрепить» даёт слово «Пройдено»; «счёт/оценка + возраст» выполнено полностью на одном экране из 26.
4. Доступность: из шести пунктов раздела «Доступность» ДС в разметке выполнен один (`--ink2` ≥ 4,5:1); при 200 % правая часть каждого экрана (паспорт) недоступна, `--ink3` (возраст, «нет данных») даёт 3,41 / 3,77 / 3,11, 0 `aria-*`, 119 интерактивных элементов вне порядка табуляции.
5. Окружение: «живая карта» работает только при http-раздаче `../data` и поднятом `:3000`; при сбое тихо подставляется вшитая копия под шапкой «живая карта проекта OMG», а при данных старше 14 суток лестница не рисуется вовсе («Cannot read properties of undefined»).

## §5 Что сделано сильно

1. **«Нет сигнала» вместо «Идёт» там, где не уверены** (П4, П7): строка Kimi в `s-sens` («Нет сигнала · окно вендора, журнал не менялся 2 ч · жив ли — неизвестно») и в `s-team` («Тихо 2 ч · нет данных»); в бенчмарке Kimi — «нет данных», «нет сигнала».
2. **Идея «приписано?»** (R18, EV-04): отдельная вкладка «От вашего имени», красная строка «источник не найден · оркестратор сослался на вас, вашей реплики нет», кнопки «Это моё» / «Не моё — вернуть». Механизм верный, нужны только данные (R-04).
3. **«Порог не задан — открыт с 21.09»** (`s-p-sp3`, `s-set`): честное видимое отсутствие решения вместо молчаливого значения по умолчанию.
4. **Раздел «нет данных — почему»** в `s-p-doc` §7 («Исследование блоков (R1) не запускалось. Появится после перехода») и «не начата» в `s-p-sp1` — образец для всех паспортов.
5. **Квитанции применения** (`s-set`): «✓ применено везде · 04.10 04:50 · действует со следующего хода каждой роли» и «изменено · ещё не применено — Применить везде»; в `s-roles` «изменения не действуют, пока состав не подписан».
6. **Сигнал утечки путей и «лежит в чужой папке»** (`s-art`): «Наружу: нет · содержит пути к вашим папкам», «лежит в чужой папке · 3 места». Детектор правильного класса.
7. **Инвентарь после перезагрузки** (`s-p-return`, R34): «Снимки ревью круга 2 · в /tmp → потеряны при перезагрузке → пересобрать» — честно называет потерянное.
8. **Прогноз с названным допущением** (`s-prov`): «Codex кончится раньше сброса: при темпе 25 M входных токенов в день … упрётся в 100 % около 15:00 завтра», и **возраст + источник** в строках «данные: 3 мин назад · из rate_limits» — единственное место, где П3 выполнен.
9. **Сведение ответов других инструментов** (`s-res`): «DeepSeek: «да», без ссылки → не подтверждено», «1 утверждение подтверждено · 2 не проверены» — образец R22 по смыслу.
10. **Обратный вид «что агент видит сейчас»** (`s-p-window`): рядом снимок и слова агента с расхождением («по снимку карта пуста, агент считает её открытой») — прямой ответ на 16 реплик «экран говорит одно, агент другое».
11. **Права идут за ролью, не за моделью** и «стоп-случаи — всегда спрашивают вас, даже при «только сообщать»» (`s-set`, `s-roles`) — правильная модель; не хватает только механизма принуждения (R-06, R-20).
12. **Живой слой честного типа**: KPI «111 / 123», «48 %», подпись «Последнее событие: 04.10 04:39 МСК» берутся из реальных файлов, и запасной путь на случай сбоя существует (недостаток — тихий, R-11).
13. **Цена хода в композере с ярлыком «оценка»** («ход ≈ 0,3 % · оценка»; «вопрос ≈ 0,2 % · оценка») — правильная форма Принципа 5, нужен только возраст.
