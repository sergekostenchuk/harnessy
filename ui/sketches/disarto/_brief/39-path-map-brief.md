# Бриф: скетч 39 «Путь · карта» — путь проекта как карта, а не экраны

Слово владельца 21.10.2026: «я не увидел карты (схемы)». Экраны 28–38 — это карточки и списки; владелец ждал КАРТУ: стадии — карточки с входом →
действием → выходом, стадия раскрывается во внутренние узлы, связи стрелками с подсветкой, точки владельца отмечены на узлах. Правило владельца:
«карта OM — карта (граф карточек), не дашборды». Экраны 28–38 НЕ выбрасываются: они становятся содержимым карточек, открывающихся по клику на узел.

### Верхний уровень: 8 карточек-стадий строго из `~/OMG/src/pipeline/contracts.ts` STAGES
discovery · concept · operation-map · specification · features · om-g2 · compilation · execution — в этом порядке, слева направо (со змейкой на узком экране).
Перед discovery — маленький узел «Вход» (поручение владельца; в карте прохода это не стадия — так и подписать: «не стадия»). Подписи по-русски, кодовое имя мелко.
У каждой карточки стадии: вход → действие → выход (одной строкой каждое), статус (принята · идёт · впереди), число точек владельца внутри, счётчик «ждёт вас».
Связи между стадиями — по выходу/входу (см. `io` стадий в `39-path-map-nodes.txt`): стрелка с подписью артефакта (например «досье реального мира» → концепция).

### Второй уровень: внутренние узлы стадии — СТРОГО из `_brief/39-path-map-nodes.txt`
Это выгрузка данных карты прохода OMG (`~/OMG/PREPARATIONS/OMG-MAP-SCHEME/omg-pass-map-2026-10-14.html`, массив STAGES → `subs` и `links`). Соответствие стадий:
discovery = `ndisc` (d0–d8, k) · concept = `con` (c1–c7) · operation-map = `map` (m1–m7) · specification = `spec` (p1–p7) · features = `feat` (f1–f7) ·
om-g2 = `om` (r0, l1, b1, r1, l2, r2, l3, m8, s) · compilation = узел `om.c` «Передача и компиляция» (одна карточка-стадия с одним узлом, вход «ready M8» → выход «план задач») ·
execution = `run` (a, tasks, phase, t, k, r, c, f, s). Узел `disc` (OLD Discovery) не рисовать. Узлы с `who=1` — точки владельца: бейдж «владелец» на узле. Статусы `st`:
yes → «есть», part → «частично», no → «нет» (на узле — плашка, как в этапах A/B; для Discovery «нет» = «макет», «part» = «есть в коде, выключено», см. бриф 28).
Связи внутри стадии — из `links` (подпись в скобках — на стрелке). Не выдумывать узлов и связей сверх выгрузки; если связь в выгрузке обрезана «…» — взять из карты прохода.
У узла: вход → выход (из `io`), имя, бейджи. Больше текста на узле не нужно — подробности в карточке поверх.
