## Что такое OM (факты, не выдумывать)
OM — машина, которая ведёт проект без постоянного участия человека: проход сверху вниз
R0 (дискавери) → L1 замысел → R1 → L2 блоки и договоры → R2 → L3 работы (будущие задачи) → дверь атомарности → реализуемость → компиляция → ПЛАН (задачи) → ИСПОЛНЕНИЕ (задача: реализация моделью в отдельной копии → проверки → ревью → коммит).
Шаг прохода: routes, evaluate, close, apply, bases, open, register, lines, obligations, packet, cycle (= вызов модели), readiness, works. Фаза: шаг / ожидание (с причиной) / завершён / не может / переоткрыт.
Цепочка продолжений: модель отвечает «нужен источник» → движок досылает → следующее звено. Это и есть «по кругу»: 19 таких вызовов выглядели как работа.
Слово владельца: «OM без владельца — машина пишет код и выдаёт готовые задачи, владелец только чтобы срочно остановить»; «вопросы решает модель, факты — код, владелец выбирает из предответов».

## Что владелец спрашивает чаще всего (каждый вопрос — кадр или явный ответ на экране)
1. Что с живым проходом? 2. Где мы, на каком месте? 3. По кругу или к цели? 4. Сколько стоит (факт против прогноза и лимитов)? 5. Что делает движок и почему затык (что модель просит и почему)? 6. Что дальше?
Плюс действия: срочно остановить; продолжить; выбрать из предответов на блокирующий вопрос; переоткрыть работы (L3) своей командой; посмотреть план и почему задача не проходит.

## ЗАПРЕТЫ
- Никаких идентификаторов, ревизий, хэшей, токенов стопа, pid перед глазами (n-state → «Состояние»; model-call:… нет).
- Прогресс НЕ по числу вызовов — по сути: сколько ступеней/блоков/работ сделано и движется ли к цели.
- Без простыней: подписи 2–5 строк. Без церемоний и «проверок проверок». «Выбор горизонта владельцем» — нет.
- Скетч — спецификация: КАЖДЫЙ блок кадра имеет реальный источник ИЛИ явную пометку «макет» (pill). Ничего не скрывать и не выдумывать цифр — только из снимка выше.
- Принцип экранов: обзор → раскрытая карточка поверх (из кликнутого), один экран — одно дело.
