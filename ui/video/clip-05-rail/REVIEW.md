# REVIEW — клип №5 «Рейка-режимы» (ru / en)

## Что это и как собрано
- Сюжет A «Одна рейка — четыре двери» (STORY.md): один непрерывный дубль окна Harnessy (скетч 40, кадр A2 → A1·i → A2·p → «Команда» → A2 отпущена → A2); камера ходит между всем окном (1.0×), обзором ленты (1.2×) и крупным планом рейки с панелью (2.2×); каждый следующий кадр вызван курсором; финал — клик по знаку в шапке рейки → карточка Harnessy · alpha · «рейка-режимы».
- 21,9 с, 657 кадров, 1920×1080, 30 fps. Подписи-титры в нижней полосе (Inter 600 52 px, одно слово коньяком, ≤ 5 слов каждая), плашка «alpha» в правом нижнем углу весь клип (кроме финала, где «alpha» — в лок-апе).
- Визуал — статичный DOM скетча `ui/sketches/disarto/40-sidebar.html`: рейка 56 px (railA2: Новый чат · Найти · Чаты · Входящие 2 · Проект · Команда · кольцо лимитов 64 % · аватар), панель режима 280 px (modeHead: «режим · Alpha-Test ▾ · булавка · ×»), режим «Чаты» (modeChats), режим «Проект» (modeProj: карточка проекта, разделы, Другие проекты), экран «Входящие» (mainInbox, шесть карточек) с CSS `sidebar-v2.css` (база — композиция clip-01/03, :hover → управляемые классы, переходы убраны). Знак финала — `assets/img/harnessy-icon.png` из clip-01.
- Режим «Команда» в скетче 40 не нарисован (в railA2 есть только пункт рейки). Собран из строк дизайн-кода sidebar-v2-spec («Команда агентов: 2 роли — состав, назначение и статусы ролей»; роли Оркестратор · Исполнитель, статусы «идёт ход» / «ждёт вас» — точки .busy/.wait строки чата) и названий экранов скетча 41 («Полотно команды», «Конструктор команды»). Ничего, чего нет в скетчах или дизайн-коде, не добавлено.
- Пункты «План · карта» и «Путь» с плашкой «макет» из modeProj не показаны: дизайн-код — «пункт с «макет» не рисуется вовсе», бриф серии запрещает слово «макет» в кадре.
- Механика «отпустить»: клик по «×» в шапке панели (скетч: title «Отпустить панель») → панель уезжает под рейку (transform x −280), рабочая область расширяется (сдвиг содержимого 140 → 0, шапки 280 → 0 — transform, не width); клик по «Команда» в рейке возвращает её зеркально.
- Два языка: все 112 строк ui + 6 подписей + финал — переменные `data-var-text` (словарь `tools/vars.mjs`); `node tools/vars.mjs en|ru` переключает набор хостов перед рендером (как в clip-01/03). Проект оставлен в ru.

## Творческие решения и что не строилось
- Кадр 0 — панель закреплена в режиме «Чаты» (как нарисовано в A2), а не отпущена: первый клик показывает «Входящие» как экран-ленту (по скетчу «Входящие» в A2 — пункт рейки + экран, не панель), и зритель сразу видит «рейка + панель рядом».
- После отпуска панели пункт «Команда» в рейке гаснет (режим не открыт); при возврате загорается снова — так клик читается как «открыть», а не «переключить».
- Экран «Входящие» остаётся в рабочей области до конца — при отпуске панели видно, как колонка ленты сдвигается в центр расширенной области.
- Сюжеты B («было тесно — стало просторно», split screen) и C («композер растёт», бесконечный отъезд) не строились — причины в STORY.md.

## Самый слабый кадр и что изменить при наличии времени
- Сцена 5 (10.0–12.0 с, панель «Команда»): панель заполнена на треть (две роли и два экрана) — честно по данным «2 роли», но пусто. Вариант: когда в скетче 40 появится кадр режима «Команда», заменить содержимое на него.
- Сцена 3 (2.75–5.3 с, обзор 1.2×): текст карточек 15 px — зритель видит две группы и кнопки, читает только заголовки групп (как в clip-03).
- Шов ui→end: один чёрный кадр между затемнением и знаком — читается как намеренный dip; можно сократить затемнение до 50 %.

## Предупреждения, оставленные намеренно
- `text_below_floor` (UI продукта), `line_unread` (UI в полёте камеры / ниже порога) — см. выше.
- Плашка «alpha» в углу всего клипа — требование владельца.

- Студия: `npx hyperframes preview --background --port 3025` → http://127.0.0.1:3025/ (или HyperFrames desktop app).
- Тексты: `tools/vars.mjs` (словарь ru/en) → `node tools/vars.mjs ru|en` → `npx hyperframes render --quality delivery --output renders/Harnessy-rail-<ru|en>.mp4`.
