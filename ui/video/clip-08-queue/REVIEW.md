# REVIEW — клип №8 «Очередь задач» (ru / en)

## Что это и как собрано
- Сюжет A «Одна задача — от очереди до карточки» (STORY.md): курсор делает работу, один непрерывный дубль окна Harnessy; каждая смена кадра вызвана курсором (клик по заголовку очереди, «+ задача», подъём и перенос строки, клик по знаку).
- 19,0 с, 570 кадров, 1920×1080, 30 fps. Подписи-титры в полосе 168 px (Inter 600 52 px, одно слово коньяком), плашка «alpha» справа внизу (кроме финала).
- Одна задача идёт через весь клип: №14 «TS-37 · перетаскивание задачи на роль» (QUEUE0 скетча 41) — в очереди без исполнителя → поднята → на карточке Воркера 2 → «Воркер 2 · у воркера 2» в списке и «№14 назначена: …» в карточке → Воркер 2 «пишет · №14».
- Визуал — DOM и CSS скетча 41, снятые headless-Chrome при ширине окна 1600 (кадр 01 «Работа команды»: оркестратор со встроенным чатом, пять карточек ролей, оргсхема, живая стрелка, очередь внизу; кадр 04 «Очередь задач»: фильтры, крупные строки, цели справа), панель A1 и полоска вкладок — скетч 40 (как в clip-01/02). Плашки «макет» скетча сняты (слово владельца).
- Два языка: 222 строки — переменные `data-var-text`, словарь `tools/vars.mjs` (скопирован из clip-02, заполнен заново); `node tools/vars.mjs en|ru` → рендер. В EN «№14» → «#14».
- Переходы (4 вида, все с причиной): наезд камеры на действие курсора; blur-swap на одной сцене (полотно → очередь крупно по клику); панорама камеры вслед за переносимой строкой; зум сквозь знак в панели → финальная карточка.

## Что измерено, что только просмотрено
- `npx hyperframes check --json`: ok=true, 0 ошибок в обеих версиях (lint / runtime / layout / contrast / motion). Оставленные предупреждения: `line_unread` для реплики оркестратора в чате (UI продукта, 2,6 с) и для строк панели/вкладок в момент полёта камеры в знак (16.0–16.1); `text_below_floor` для плашки «есть» (7,5 px — UI продукта); `text_occluded` info при 7.4 с — заголовок очереди и строка №14 под поднятым клоном (по замыслу). Намеренные opt-out: `data-layout-allow-occlusion` на строках `.l3` карточек (многоточие по CSS, проверка меряет полный текст), `data-layout-allow-overlap` на списке строк (абсолютные слоты) и полотне, `data-layout-ignore` на стрелках и клоне.
- `snapshot --review`: 9 битов (0.3 / 0.6 / 3.6 / 6.5 / 8.075 / 9.3 / 12.5 / 16.45 / 17.575), шов ui→end (15.95), телефонная ширина — просмотрены; подписи читаются при 360 px, UI продукта — нет (ожидаемо, как в clip-01/02).
- Точечные снимки: 0.5 / 2.0 / 3.6 / 5.0 / 7.0 / 7.7 / 8.2 / 8.6 / 9.0 / 11.0 / 13.5 / 15.5 / 17.5 — курсор на цели (положения считаются при сборке по DOM: #ui-qtitle, #ui-add, #ui-r14b, #ui-w2, #ui-logo), имя №17 печатается с кареткой, строка поднята с подсказкой, билет ложится по центру карточки, цель пунктиром с «назначить воркера 2», кольцо «получено», перестановка строк (№15 первая), «пишет · №14».
- Рендеры: `renders/Harnessy-queue-ru.mp4`, `renders/Harnessy-queue-en.mp4` — ffprobe 19.000 с каждый, h264 1920×1080 30 fps + AAC, ≈3 МБ. Кадры декодированы из mp4 (`renders/frames/`): 3.6 / 8.2 / 13.5 с.

## Творческие решения и что не строилось
- Вход в крупную очередь — клик по заголовку «Очередь задач» внизу полотна (в скетче нарисована только обратная кнопка «К полотну»).
- Порядок строк в крупной очереди — порядок очереди (в очереди → в работе → на ревью → готово), не по номерам: после сброса №14 уходит вниз к задачам в работе, №15 поднимается первой — «следующая поднимается первой» видно буквально.
- Цели справа — две колонки карточек (окно 1600 вместо 1440 в скетче), чтобы список не растягивался; список стянут к левому краю.
- Поднятая строка через 0,3 с сжимается до билета «№ · имя» (380 px) — полная строка 878 px закрывала бы и карточку-цель, и соседей.
- Сюжеты B («Утро оркестратора», назначение через чат) и C («Номер как нить», бесконечный зум) не строились — причины в STORY.md.

## Самый слабый кадр и что изменить при наличии времени
- 12.2–14.8 с (1.0×, «Видно, у кого что»): нижняя половина рабочей области пуста — так в скетче (список на 7 строк), но в кадре 1.0× это дыра. Вариант: наезд 1.4× на верхнюю часть (список + карточки) вместо 1.0×, или вернуть «К полотну» кликом и показать назначение на полотне.
- 7.0–7.4 с: клон появляется полной строкой и тут же сжимается — читается как два движения; можно начать перенос сразу билетом.

## Предупреждения, оставленные намеренно
- `line_unread` (реплика оркестратора — UI; строки, уходящие из кадра в полёте в знак), `text_below_floor` («есть» 7,5 px), `text_occluded` info при подъёме строки — см. выше.
- Плашка «alpha» в углу весь клип — требование владельца.
