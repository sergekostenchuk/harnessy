# Дизайн-система «Верстак 2026–2027» (Harness Design System Spec)

> **Стандарт:** Премии UXDA Berlin, iF Design, Red Dot, Awwwards.  
> **Ключевой принцип:** «Тихий интерфейс высокой плотности» (Calm High-Density) — эстетика точного инженерного инструмента, где ИИ не является декоративным элементом, а работает как прозрачный механизм.

---

## 1. Токены дизайн-системы (Tokens Architecture)

Дизайн-система построена на строгой 4-уровневой иерархии токенов:
`Базовые значения (Primitive) ──► Семантические (Semantic) ──► Компонентные (Component) ──► Состояния (State)`

### 1.1 Цветовая палитра и семантика (WCAG 2.2 AAA Compliant)

| Токен | Светлая тема | Тёмная тема | Смысл в интерфейсе | Коэффициент контраста |
|:---|:---|:---|:---|:---|
| `surface-bg-base` | `#F5F5F7` (Apple Gray) | `#0E0F12` (Deep Charcoal) | Фоновое полотно экрана | — |
| `surface-card-base`| `#FFFFFF` | `#16181D` | Карточки, панели, модальные окна | > 12:1 к фону |
| `surface-quad-active`| `#EBF3FE` | `#1C2638` | Активное пространство (Проект/Код) | > 7:1 |
| `text-primary` | `#111827` (Near Black) | `#F3F4F6` (Pure White-Gray)| Заголовки, ключевые статусы | 14.5:1 (AAA) |
| `text-secondary` | `#4B5563` (Slate) | `#9CA3AF` (Muted) | Пояснения, цель, метаданные | 7.2:1 (AAA) |

### 1.2 Семантические цвета 4 Пространств (Spatial Quad Tokens)

* 📁 **Проект (Project Space):** `accent-project` (`#0284C7` / `#38BDF8`) — строгий лазурный.
* 💬 **Обсуждение (Chat Space):** `accent-dialogue` (`#D97706` / `#FBBF24`) — тёплый янтарный.

* 🚀 **Продукт (Product Space):** `accent-product` (`#7C3AED` / `#A78BFA`) — благородный фиолетовый.

## 2. Грамматика состояний: «Формула 12 статусов»

> **Железное правило доступности:** Ни один статус **никогда** не передаётся только цветом.  
> Обязательная формула отображения: `[Символ / Пиктограмма] + [Понятное русское слово] + [Контекстный хвост]`.

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│  СИМВОЛ        СЛОВО               ЦВЕТ           ХВОСТ (Пояснение / Возраст)    │
│  ────────      ────────────────    ──────────     ─────────────────────────────  │
│  [ ● ]         Идёт работа         Синий          «Пишет тесты для auth.py (18с)»│
│  [ ⏸ ]         Ждёт вас            Оранжевый      «Подтвердить коммит (12 мин)»  │
│  [ ✓ ]         Успешно             Зелёный        «Все 16 тестов пройдены»       │
│  [ ✘ ]         Сбой                Красный        «Ошибка сборки в строке 42»    │
│  [ ⊘ ]         Защитная пауза      Бордовый       «Превышен лимит сессии $5.00»  │
│  [ ⟳ ]         Проверяется         Бирюзовый      «Линтер и сборка (3 сек)»      │
│  [ ◌ ]         Нет данных          Серый          «Оценки времени нет: 1-й запуск»│
└──────────────────────────────────────────────────────────────────────────────────┘
```

### Полная матрица 12 состояний системы:

1. **Готов к работе `[ ○ Готов ]`:** Исполнитель свободен, ожидает вашего поручения.
2. **Идёт работа `[ ● Работает ]`:** Активное выполнение шага (с указанием текущего файла и секундомера).
3. **Ждёт вас `[ ⏸ Ждёт вас ]`:** Работа приостановлена, требуется ваше решение. В карточке всегда указан **возраст ожидания** (например: `ждёт 4 мин`).
4. **Проверяется `[ ⟳ Проверка ]`:** Автоматический прогон тестов, линтеров, сборки или верификации ссылок.
5. **Успешно завершено `[ ✓ Готово ]`:** Шаг выполнен, критерии успеха удовлетворены на 100%.
6. **Выполнено с замечаниями `[ ◐ Принято с оговоркой ]`:** Код работает, но есть предупреждения линтера или некритичный долг.
7. **Сбой в работе `[ ✘ Ошибка ]`:** Ошибка компиляции, рантайм-исключение или падение теста с указанием зоны ошибки.
8. **Защитная пауза `[ ⊘ Остановлено ]`:** Сработал автомат защиты (лимит бюджета, 3 ошибки подряд, попытка затронуть секреты).
9. **Остановлено вами `[ ■ Прервано ]`:** Ручная отмена владельцем кнопки «Стоп» с безопасным сохранением всех артефактов.
10. **Спит / На паузе `[ ◷ Пауза ]`:** Плановое ожидание внешнего события (например, запуск по расписанию через 2 часа).
11. **Нет связи / Потерян `[ ⚠ Нет сигнала ]`:** Фоновый процесс не отвечает более 60 секунд. Кнопка «Перезапустить».
12. **Нет данных `[ ◌ Нет данных ]`:** Честная фиксация отсутствия информации без домыслов и галлюцинаций.

## 3. Типографика и информационная плотность

### 3.1 Шрифтовая иерархия
* **Основной интерфейсный шрифт:** Системный стек Apple/Inter (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`). Чистый, строгий, с прекрасной читаемостью кириллицы.
* **Шрифт кода и чисел:** Моноширинный (`"SF Mono", "JetBrains Mono", Menlo, Consolas, monospace`). Используется для путей, коммитов, сумм расхода, таймкодов и статусов.

### 3.2 Режимы плотности интерфейса (Density Modes)

Интерфейс поддерживает 3 переключаемых режима отображения под разный стиль работы:
1. **Компактный (Инженерный / High-Density):** Высота строк 24px, шрифт 12–13px, максимум строк кода и данных на экране без скролла. Для глубокой разработки.
2. **Стандартный (Рабочий — дефолт):** Высота строк 32px, шрифт 14–15px, сбалансированные отступы. Для ежедневного взаимодействия.
3. **Просторный (Обзорный / Презентационный):** Высота строк 44px, шрифт 16px, акцент на карточки решений и итоговые графики. Идеален для ревью с планшета или демонстрации стейкхолдерам.

## 4. Ключевые компоненты дизайн-системы

### 4.1 Компонент «Универсальная строка состояния» (Status Bar)
Закреплена в верхней части экрана. Не исчезает при скролле. Закрывает 7 инвариантов за 1 взгляд:
```
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [📁 OMG-Dev / oauth-flow]  [● Этап 3: Код (L5)]  [⏸ Ждёт вас: 1]  [💰 $1.42 / $5.00]  [С визита: +2]  │
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 Компонент «Карточка решения» (Decision Card)
Единый паттерн для всех вопросов модели к человеку:
```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ ⏸ ЖДЁТ ВАШЕГО РЕШЕНИЯ  •  возраст: 3 мин  •  цена ожидания: $0.00                    │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ ЗАДАЧА:    Включение провайдера Google OAuth в конфигурацию                            │
│ ВОПРОС:    Требуется обновить схему базы данных: добавить поле `google_id`.             │
│ РИСК:      Миграция обратима, данные пользователей не затронуты.                       │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ [ Применить миграцию (Space) ]   [ Посмотреть SQL-дифф (D) ]   [ Отклонить (Esc) ]     │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.3 Компонент «Шлюз этапа» (Stage-Gate Checklist)
Блокирует переход к следующему этапу проекта до выполнения обязательных критериев:
```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ ШЛЮЗ ДОПУСКА: Переход к этапу «Приёмка и Релиз»                                        │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ [✓] 1. Все 5 проходов самопроверки пройдены без замечаний                              │
│ [✓] 2. 100% интеграционных тестов завершились успешно (34/34)                          │
│ [✓] 3. Расход за этап ($2.80) находится в пределах сметы ($5.00)                       │
│ [ ] 4. Личная подпись владельца проекта                                                │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ [ Подписать и открыть этап релиза (Cmd+Enter) ]             [ Вернуться к доработке ]  │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 5. Доступность (Accessibility & Ergonomics)

1. **Горячие клавиши первого уровня:**
   * `1` — Пространство «Проект»
   * `2` — Пространство «Обсуждение»
   * `3` — Пространство «Код»
   * `4` — Пространство «Продукт»
   * `Пробел` — Резолв верхней карточки решения
   * `Cmd+K` — Палитра быстрых команд
   * `Esc` — Отмена / Закрытие шторки
2. **Поддержка экранных дикторов:** Все иконки снабжены `aria-label`, интерактивные регионы размечены ARIA Live Regions (`aria-live="polite"` для хода работы, `aria-live="assertive"` для защитной паузы).
3. **Режим сниженной анимации (prefers-reduced-motion):** Плавные переходы и спиннеры заменяются на статические индикаторы состояния.
