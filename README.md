# Простой чат с моделями Anthropic по подписке

Одна страница в браузере, два независимых окна чата и маленький сервер на Node.
Сервер ходит не в API, а в локальный Claude Code CLI (`claude -p`), который
залогинен твоей подпиской Claude (Max). Ключ API не нужен, отдельный счёт не
открывается.

Зависимостей нет. Нужен Node 22+ и установленный `claude`.

## Запуск

```bash
cd /Users/kostenchuksergey/projects/simple-claude-chat
node server.mjs
```

Открыть: http://localhost:3777. Другой порт: `PORT=4000 node server.mjs`.

## Вход по подписке (один раз)

Сервер использует вход CLI, а не приложения Claude. Если вверху страницы жёлтая
полоса «Вход по подписке не выполнен» — в Терминале:

```bash
claude login
```

Проверить: `claude auth status` должен показать `"loggedIn": true`.

## Что на странице

- **Папка проекта** сверху, общая для обоих окон. Полный путь, «Применить».
  В этой папке оба агента работают: читают и правят файлы, запускают команды.
  Если в папке есть CLAUDE.md, Claude Code подхватит его как свои инструкции,
  страница об этом предупреждает.
- **Два окна**, у каждого своё: модель (Sonnet 5, Fable 5.1, Opus 5, Haiku 4.5),
  режим доступа к папке, список разговоров этой папки, кнопка «Новый».
  Окна работают одновременно и независимо, можно дать им разные модели и
  роли текстом: одному «ты кодер», другому «ты ревьюер».
- **Действия агента** видны в ленте строками `▸ Read: файл`, `▸ Edit: файл`,
  `▸ Bash: команда`; ошибки инструментов — красным.
- Ответ приходит потоком; внизу ответа модель, время, токены.

## Окна пишут друг другу

У каждого агента есть инструмент `send_to_other`: отправить текст агенту в
соседнем окне и дождаться его ответа. Сосед получает текст как обычное
сообщение в своей текущей сессии, с текущей моделью и режимом доступа, и
отвечает; ответ возвращается отправителю как результат инструмента. Агент
пользуется этим сам, когда ты просишь «спроси соседа», «поручи соседу»,
«передай ревьюеру».

Что видно на странице: у отправителя строка `▸ сообщение соседу: …` и
`↩ ответ соседа: …`, у получателя сиреневый пузырь «Сообщение от левого окна»
и его ответ. Пока сосед отвечает на чужое сообщение, его поле ввода заперто.

Правила, чтобы не зациклилось: занятый сосед сразу отвечает «занято», а не
ждёт; цепочка сообщений между окнами не длиннее трёх; чужое сообщение прав не
расширяет, сосед работает в своём режиме.

Как устроено: `bin/pane-mcp.mjs` — крошечный MCP-сервер, который приложение
подключает к каждому запуску `claude` (файл `.mcp-panes.json` пишется при
старте); инструмент шлёт `POST /api/relay` в сервер чата, сервер прогоняет ход
соседа и транслирует его события в окно соседа по `GET /api/events/<окно>`.

## Режимы доступа к папке

Окна «разрешить?» в фоновом режиме нет, поэтому режим заранее говорит, что
агенту можно без вопросов:

| Режим | Что может |
|---|---|
| Только чат | ничего в папке, чистый разговор |
| Чтение папки | Read, Glob, Grep; правок не делает |
| Правки и команды | все инструменты Claude Code; правки файлов принимаются автоматически; из команд без вопросов только git, ls, cat, pwd, find, grep, rg, head, tail, wc, npm test, npm run, node, python3 — остальное отклоняется |
| Всё без вопросов | все инструменты и любые команды без ограничений (опасно: как `--dangerously-skip-permissions`) |

## Где журналы разговоров

Их пишет сам Claude Code, один `.jsonl` на разговор, в папку по имени папки
проекта: `~/.claude/projects/<путь, где всё кроме букв и цифр заменено на «-»>`.
Например для `/Users/Shared/chat-test` это
`~/.claude/projects/-Users-Shared-chat-test/`. Путь показан справа от кнопки
«Применить». Список разговоров в окнах строится из этой папки, поэтому там же
видны разговоры, начатые в терминале в той же папке.

## Что здесь отключено нарочно

Хуки, MCP-серверы и настройки пользователя в чат не попадают: сервер запускает
`claude` с `--strict-mcp-config` и `--setting-sources ""`. Папка по умолчанию
`/Users/Shared/simple-claude-chat` лежит вне домашней папки, чтобы не
подхватывать `/Users/kostenchuksergey/CLAUDE.md`; для своих проектов укажи
папку проекта явно.

## Как это устроено

`server.mjs`: `GET /` отдаёт `index.html`; `GET /api/status` вход, модели,
режимы; `GET /api/dir?cwd=` проверка папки; `GET /api/sessions?cwd=` и
`GET /api/sessions/<id>?cwd=` разговоры папки; `POST /api/chat` один ход
`claude -p --output-format stream-json --resume <сессия>` в папке проекта и
поток событий (текст, вызов инструмента, ошибка инструмента, итог).
`index.html`: вся страница, без сборки; выбор окон хранится в браузере.

Переменные: `PORT`, `CHAT_WORK_DIR` (папка по умолчанию), `CLAUDE_BIN` (путь
к claude, если не найден сам). Список моделей и режимов — в начале
`server.mjs`.
