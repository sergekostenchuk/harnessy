# Чат по подпискам: Claude + Claude + Codex над одной папкой

Одна страница в браузере, три окна: два с моделями Anthropic и одно с Codex.
Все три работают в одной папке проекта, у каждого своя модель, режим доступа и
свой разговор. Окна пишут друг другу, а владелец разрешает или запрещает
опасные действия кнопками прямо в колонке.

Ходит по подпискам, а не по API-ключам:

- Claude — через **Claude Agent SDK (Python)** поверх локального Claude Code,
  который залогинен командой `claude login` (подписка Max).
- Codex — через **официальный Python SDK openai-codex**: двусторонний JSON-RPC
  с `codex app-server`, вход по подписке ChatGPT из `~/.codex/auth.json`.

## Запуск

```bash
cd /Users/kostenchuksergey/HARNESS
./run.sh            # = .venv/bin/python -m app.server
```

Открыть: http://localhost:3777. Другой порт: `PORT=4000 ./run.sh`.

Окружение уже создано (`.venv`, Python 3.14). Пересоздать:

```bash
python3 -m venv .venv && ./.venv/bin/pip install openai-codex claude-agent-sdk aiohttp
```

Вход (один раз, в Терминале): `claude login` для Claude, `codex login` для
Codex. Жёлтая полоса вверху страницы говорит, у кого вход не выполнен.

## Что на странице

- **Папка проекта** сверху, общая для трёх окон. В ней агенты читают и правят
  файлы. Если там есть CLAUDE.md или AGENTS.md, страница об этом предупредит:
  Claude Code и Codex подхватят их как свои инструкции.
- **Три окна**: левое и правое — Claude (Sonnet 5, Fable 5.1, Opus 5,
  Haiku 4.5), третье — Codex со списком моделей его аккаунта (gpt-6-astra,
  gpt-5.6-sol/terra/luna, gpt-5.3-codex-spark, а также облачные deepseek, qwen,
  kimi, glm). У каждого окна: модель, режим доступа, список разговоров этой
  папки, «Новый», галочка «видит соседей», кнопка «Стоп».
- **Действия агента** видны строками `▸ Bash: …`, `▸ Edit: …`,
  `▸ panes.send_to: …`; ошибки инструментов красным.
- **Карточки «разрешить / отказать»**: когда агент хочет сделать то, что режим
  не разрешает сам, в колонке появляется карточка с командой или файлом и
  причиной. Пока владелец не ответил, агент ждёт; через 15 минут — отказ.
  Карточки видны во всех открытых копиях страницы, кто нажал — пишется в лог
  сервера.

## Режимы доступа

| Режим | Claude | Codex |
|---|---|---|
| Только чат | без инструментов | песочница только чтение, инструкция не трогать файлы |
| Чтение папки | Read, Glob, Grep | песочница только чтение |
| Спрашивать | инструменты работы в папке; правки и команды — карточкой | запись в папке проекта; всё вне её и сеть — карточкой |
| Правки без вопросов | правки файлов сами; git/ls/cat/npm/node/python без вопросов; остальное карточкой | то же, что «Спрашивать» (правки в песочнице и так без вопросов) |
| Всё без вопросов | все инструменты без ограничений (опасно) | полный доступ без песочницы (опасно) |

Инструмент связи между окнами разрешён во всех режимах.

## Окна пишут друг другу

У каждого агента два инструмента: `send_to(окно, текст)` — написать другому
окну и дождаться ответа, и `read_pane(окно, N)` — прочитать его последние
реплики. Адресат получает текст как обычное сообщение в свою сессию и режим,
отвечает, ответ возвращается отправителю результатом инструмента. У Claude эти
инструменты живут внутри сервера (встроенный MCP Agent SDK), у Codex — мост
`bin/pane-mcp.mjs`, который ходит в сервер по HTTP. Занятый адресат сразу
отвечает «занято», цепочка не длиннее трёх.

## «Видит соседей»

Если галочка включена (у Codex — по умолчанию), перед каждым ходом агент
получает сводку: что нового в двух других окнах с его прошлого хода, с
подписью, кто это и какой моделью, не длиннее 6000 символов. Так Codex в курсе,
что делают окна Claude, не читая их разговоры целиком. В истории разговора
сводка не показывается.

## Spark по требованию

В тредах Codex подключён твой MCP-роутер `~/.codex/tools/sol-spark-router`
(модель gpt-5.3-codex-spark с откатом на Terra, Luna, Sol). Его записывающие
инструменты стоят в режиме «спросить»: запрос приходит карточкой в окно Codex,
как и любой другой вызов чужого MCP-сервера. Вызовы собственного моста между
окнами разрешаются без вопросов.

## Где журналы разговоров

- Claude: `~/.claude/projects/<путь папки, где всё кроме букв и цифр заменено
  на «-»>/<id>.jsonl`, например `~/.claude/projects/-Users-Shared-chat-test/`.
- Codex: `~/.codex/sessions/ГГГГ/ММ/ДД/rollout-…-<id>.jsonl`; список по папке
  даёт сам app-server.

## Что выключено нарочно

В треды Codex не попадают твои хуки, плагины, memories и MCP-серверы из
`~/.codex/config.toml` (они выключаются на старте треда), в ходы Claude — хуки,
настройки и MCP-серверы пользователя. Папка по умолчанию
`/Users/Shared/simple-claude-chat` лежит вне домашней, чтобы не подхватывать
`/Users/kostenchuksergey/CLAUDE.md`.

## Устройство

- `app/server.py` — aiohttp: страница, `/api/status`, `/api/dir`,
  `/api/panes/<окно>`, `/api/events/<окно>` (поток событий окна),
  `/api/chat`, `/api/approve`, `/api/interrupt`, `/api/sessions`,
  `/api/relay` и `/api/pane_transcript` для моста.
- `app/panes.py` — реестр окон, карточки разрешений, стенограммы, сводка.
- `app/claude_provider.py` — Claude Agent SDK: один ход = один клиент с
  продолжением сессии, `can_use_tool` → карточка, `interrupt` → «Стоп».
- `app/codex_provider.py` — openai-codex: один app-server на окно, тред на
  разговор, `approvalPolicy` по режиму, обработчик запросов сервера → карточка.
- `app/bridge.py` — инструменты связи окон для Claude и общая передача.
- `bin/pane-mcp.mjs` — те же инструменты для Codex (MCP stdio, Node).
- `index.html` — вся страница, без сборки.

Переменные: `PORT`, `CHAT_WORK_DIR` (папка по умолчанию), `CLAUDE_BIN`,
`NODE_BIN`, `CHAT_DEBUG=1` (печатать все события Codex).
