# DSH (DeepSeek Harness, «lite»): журнал работы агента и композер — разбор по трём снимкам пользователя

Дата: 30.09.2026 ~20:00 МСК. Источник: три снимка, присланные пользователем в чат WORKER-N8N-OMG; копии — `evidence/screens/dsh/dsh-01…03.webp`. Всё в §1 — наблюдаемое на снимках; §2–§4 — предложения, помечены [предложение]. Код DSH не открывался.

## 1. Что видно (факты)

### 1.1 Каркас окна
- Слева: рабочие пространства (Workspaces) как папки: OMG, kostenchuksergey, PREPARATION, DeepSeek Harness, TASKPLAN PRO V3, Ungrouped; под папкой — сессии с возрастом (1min, 26d, 1mo) и «Show 1 more sessions». Кнопки: New Session, поиск, фильтр, новая папка; внизу Settings.
- Шапка сессии: название («Проверка присутствия асс…»), тег профиля «lite», две вкладки **Chat / Trajectory**, справа «Session log ⬇» (выгрузка) и два переключателя панелей.
- Композер внизу: «Message or run a task… / commands, @ files or sessions».

### 1.2 Вкладка Trajectory (журнал работы агента)
- Три режима шкалы: **Duration · Turns · Calls**; поиск по траектории.
- **Мини-карта из трёх дорожек** по времени: Input / Model / Tools (фиолетовая полоса — доля времени модели; на снимке ход почти целиком «Model»).
- Список событий: `SYSTEM Initial System Prompt` → `Turn 1 · USER «ты здесь?»` → свёрнутая строка `… 1 step · 0 tool calls`. Слева вертикальный маркер хода (Turn 1).
- Панель деталей справа: вкладки **System Prompt / Tools**. System Prompt — текст целиком. Tools — список инструментов с описанием, раскрываемый до JSON-схемы (`list_sessions`, `mcp__web__web_fetch`, `mcp__web__web_search`, `read_session` — «читать другую сессию того же workspace, UNTRUSTED snapshot», `scheduler_create/delete/list/update`, `search_sessions`, «send a message to ANOTHER session…»).
- **Строка метрик** под композером: `1 turns · 1 steps | LLM 1.9s | TTFT avg 1.7s · 46 tok/s | Cache hit 0% | Input 4.4K tok · Output 12 tok`.

### 1.3 Композер и настройки хода
- Слева направо: `+` (вложение), **Full access ▾** (уровень доступа/автономии), **Local ▾** (среда исполнения), **Speed · Standard** (режим скорости), **GPT-5.6-Terra · Medium ▾** (модель + усилие), индикатор-кольцо (без подписи), кнопка отправки.
- Подсказка ввода различает «message» и «run a task»; `/` — команды, `@` — файлы **или сессии** (адресация другой сессии из строки ввода).

### 1.4 Что на снимках отсутствует (наблюдение, не упрёк)
- Нет слова состояния сессии/агента (идёт / ждёт вас / готово / сорвалось); индикатор-кольцо без подписи.
- Нет дорожки «ожидание человека» и маркеров вопросов/одобрений на мини-карте (три дорожки — только машина).
- Нет остатка лимита/бюджета (ни % недели, ни денег); есть только токены хода.
- Нет режима работы (чат / план / команда / наблюдение) — только модель, доступ, среда, скорость.
- Нет «что изменилось с прошлого визита» и возраста данных.
- Метрики — за сессию целиком, без разбивки по ходам/шагам и без сравнения между сессиями.

## 2. Можно ли сделать то же в Workbench [предложение]
Да — данные есть без нового движка:
- Claude Code: `*.jsonl` сессий — `message.usage` (input/output/cache_read/cache_creation), `tool_use`/`tool_result` с временем, компакции, `permission-mode`; Codex: `token_usage_record`, `rate_limits.used_percent`, `turn_context`; Hermes/Kimi: `StatusUpdate.token_usage`, `StepInterrupted`; канал OMG (`channel.ndjson`), `backend-runs.ndjson`; OM-VIEW уже держит курсор по времени и дорожки (`Player`, `DevTrack`).
- Реализация — четвёртая секция/вкладка у разговора: **Chat / Trajectory / Metrics**; траектория — та же мини-карта дорожек + список ходов/шагов + панель деталей.

## 3. Какую аналитику добавить [предложение], привязка к свидетельствам
Три слоя, каждый отвечает на один из «шести вопросов» (state-visibility §Сводка) и на боль из evidence.

### 3.1 Ход / шаг (как у DSH, плюс человек)
| Метрика | Зачем (боль) | Источник |
|---|---|---|
| Длительность шага; доля модель / инструменты / **ожидание человека** / **ожидание канала** | «тишина = поломка»; два вида ожидания неотличимы (r2-waiting F10) | штампы сообщений, tool_use/result, вопросы-карточки |
| TTFT, tok/s | ощущение «завис» (порог 4–5 мин, r2-waiting F9) | как у DSH |
| Токены: свежие вход / кэш / выход | «видно 15 млн за прогон, не видно какой ход сколько съел» (reports-memory) | usage по сообщению |
| Число вызовов инструментов, самый долгий вызов, ошибки по **зоне** (наша / провайдера / сеть / ваша) | сырые ошибки без зоны ответственности (r2-screenshots F4) | tool_result, коды ошибок |
| Заполненность контекста, компакции | 75 компакций / 2 769 сжатий; восстановление как норма (сигнал 9) | context %, события compact |

### 3.2 Сессия / задача
| Метрика | Зачем | Источник |
|---|---|---|
| Время до первого доказательства (тест, снимок, ссылка) | «заявлено ≠ проверено» (сигнал 10) | события артефактов |
| Круги ревью, возвраты, «оценка из 10» с дельтой | 52 % возвратов; оценка без критериев (критик-2 §6 п.5) | канал, вердикты |
| Вопросы о состоянии («где мы / ты здесь?») — счётчик | каждая четвёртая реплика (сигнал 1) | регэксп по репликам |
| Время «ждёт вас» с возрастом; сколько вопросов закрыто пусто/по тайм-ауту | карточки решения закрываются пустыми (r2-waiting F2–F4) | карточки/вопросы |
| Стоимость задачи = сумма ходов × повторы; **цена правильного результата** | критерий владельца (сигнал 7) | usage × круги |

### 3.3 Проект / неделя
| Метрика | Зачем | Источник |
|---|---|---|
| Расход недельного лимита по сессиям и ролям, прогноз сброса, возраст снимка | единица пользователя — % недели; CodexLimitBar как спецификация (сигнал 5, 7) | `rate_limits`, get_usage |
| Дельта с прошлого визита: влито / возвращено / рост плана / новые вопросы | «к цели или по кругу» как дельта, не абсолют (сигнал 6) | git, канал, план |
| Карта тишины: типы (по решению / лимит до … / жду вас / сеть / мёртв) по времени | восемь причин тишины выглядят одинаково (r2-touchpoints N3) | события + эвристики |
| Сравнение исполнителей (Claude / Codex / Kimi / Devin): круги, время, цена на задачу | выбор исполнителя вслепую (omg-process 2.2) | канал + usage |
| Активность по часам (ночь как рабочее время, окно отсутствия 06–13) | доставка в дайджест «к возвращению» (критик-2 §6 п.3) | штампы |

## 4. Как показать визуально [предложение]
1. **Мини-карта дорожек** как у DSH, но пять дорожек: Ввод · Модель · Инструменты · **Вы** (ожидание вашего ответа, жёлтым, с возрастом) · **Внешнее** (лимит/сеть/канал, серым с причиной). Маркеры на оси: вопрос ✚, одобрение ⚑, ошибка ▲ с зоной, компакция ▮, доказательство ✓.
2. **Полоса стоимости хода** под каждым ходом: стек «свежий вход / кэш / выход» в токенах и в % недели; при наведении — тариф и возраст числа.
3. **Строка метрик** внизу — как у DSH, плюс `ждёт вас 12 мин` и `неделя 94 % · сброс пт 23:00`; числа со значком «оценка/счёт».
4. **Вкладка Metrics** сессии: три карточки (ход · задача · проект) с дельтой к прошлому визиту; графики — только спарклайны (tok/s, кэш, контекст), без круговых диаграмм.
5. **Панель деталей** справа — как у DSH (System Prompt / Tools), добавить вкладки **Состояние** (паспорт: где · что · зачем · когда · что ожидаем · критерии · риски) и **Происхождение** результата (кто, по какому плану, на каких данных).
6. Композер как «строка условий хода»: режим (чат / план / команда / наблюдение) · адресат (сессия/роль через `@`) · модель + усилие · доступ · среда · **остаток недели** · ожидаемая цена хода (диапазон, «оценка»). DSH уже держит четыре из этих полей — сохранить компактность, не добавлять вторую строку контролов.
7. Индикатор без подписи → слово состояния + форма + цвет (state-visibility H1); анимация только у нетерминальных состояний.
