# Базовый архитектурный фундамент (Фаза 3): разрешение 7 блокеров и устранение жаргона

> **Статус:** Утверждённый фундамент концепций UX/UI Harness 2026–2027.  
> **Основание:** Снятие блокеров отчёта `_critic-phase2.md §9`, внедрение «Правила 7 инвариантов» и «4 пространств».

## 1. Унифицированная модель: Этап (Конвейер) · Лестница (Шаги) · Режим (Фокус)

Ранее в документах возникла путаница терминов (CR-03, CR-04), когда словом «стадия» называли и фазу проекта, и ступень выполнения, и режим экрана. Вводим строгое трёхуровневое разделение:

```
УРОВЕНЬ 1: ЭТАП ПРОЕКТА (Конвейер жизненного цикла)
[1. Исследование] ──► [2. Замысел и План] ──► [3. Разработка] ──► [4. Приёмка] ──► [5. Релиз]
                                  │
                                  ▼
УРОВЕНЬ 2: ЛЕСТНИЦА ЗАДАЧИ (Прогресс текущего прогона: L0…L8)
[L0: Старт] → [L1: Контекст] → [L2: План] → [L3: Код] → [L4: Сборка] → [L5: Тесты] → [L6: Ревью] → [L7: Финал]
                                  │
                                  ▼
УРОВЕНЬ 3: РЕЖИМ РАБОЧЕЙ СРЕДЫ (Текущий фокус внимания пользователя)
(•) Обсуждение (Чат)    (•) План и Задачи    (•) Команда исполнителей    (•) Наблюдение (Ход)
```

1. **Этап проекта (Project Stage):** Где глобально находится проект в жизненном цикле. Виден в строке статуса проекта.
2. **Лестница шагов (Task Ladder):** Где находится текущая активная задача внутри этапа. Видна как горизонтальный шагомер (L0…L8).
3. **Режим рабочей среды (Workspace Mode):** Какой инструмент сейчас активен на экране. Переключается без потери контекста.

## 2. Человеческий словарь без жаргона (Замена ~25 технических терминов)

Интерфейс разговаривает с владельцем на чистом, уважительном и ясном русском языке. Никаких англицизмов, машинных аббревиатур и псевдовоенного жаргона:

| Было (жаргон / англицизм) | Стало в интерфейсе | Где используется | Смысл для пользователя |
|:---|:---|:---|:---|
| **Харнесс (Harness)** | **Пульт / Верстак** | В шапке и названии | Ваше рабочее место управления моделями |
| **Пайплайн / Стейджи** | **Этапы проекта** | Навигация проекта | Последовательность достижения цели |
| **Стейт / Состояние** | **Статус / Что происходит** | Индикаторы состояния | Физическое состояние исполнителя прямо сейчас |
| **Гейт / Шлюз** | **Проверка допуска** | Переходы между этапами | Условия, без которых нельзя идти дальше |
| **Воркер / Сабагент** | **Исполнитель / Помощник** | Список команды | Модель, выполняющая порученную задачу |
| **Рекап / Визит** | **Сводка возвращения** | Экран после паузы | Что изменилось, пока вас не было у экрана |
| **Стоп-случай / Breaker** | **Защитная пауза** | Алерт-панель | Система остановилась, чтобы сберечь данные или бюджет |
| **Паспорт места** | **Свойства задачи** | Боковая панель | Путь к папке, лимиты, доступы и правила |
| **Блюпринт / Спецификация** | **Схема процесса** | Документ этапа | Как связаны действия человека и моделей |
| **Диффы / Чанки** | **Правки в коде** | Панель кода | Наглядное сравнение «было / стало» |
| **Промпт / Инпут** | **Поручение / Сообщение** | Поле ввода | Текст вашей задачи или вопроса |
| **Ревью / Апрув** | **Проверка / Согласование** | Кнопка решения | Ваша личная подпись под результатом |
| **Кеши / Токены** | **Расход памяти / Ресурс** | Строка затрат | Сколько ресурса модели израсходовано |
| **Лейбл / Тег** | **Метка** | Фильтры и списки | Категория задачи или заметки |
| **Фоллбек / Роллбек** | **Откат к точке сохранения**| Панель восстановления | Безопасный возврат к проверенной версии |

## 3. Стандарт «7 Инвариантов на каждом экране»

Каждый экран системы обязан за **первые 3 секунды** отвечать на 7 ключевых вопросов без необходимости нажимать кнопки или разворачивать спойлеры:

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 1. ГДЕ:          [Проект: OMG-Dev]  /  [Этап: Разработка]  /  [Задача: Авторизация OAuth]       │
│ 2. ЧТО:          Исполнитель Gemini пишет тесты  [● Идёт работа]                                │
│ 3. ЗАЧЕМ:        Закрыть сценарий входа через Google для бета-тестеров                         │
│ 4. КОГДА:        Завершение через ≈ 2 мин (или «Оценки нет: первая сборка»)                     │
│ 5. ЧТО ОЖИДАЕМ:  Зелёный прогон 8 тестов и готовый коммит                                      │
│ 6. РИСКИ:        Низкие (работа в отдельной ветке, файлы вне git не затрагиваются)              │
│ 7. КРИТЕРИИ:     Успех: 100% тестов пройдены. Провал: ошибка сборки или таймаут > 5 мин        │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 4. Разделение 4 Пространств (Spatial Quad)

Интерфейс исключает «кашу» из чата, кода и планов. Пространства визуально и функционально разграничены:

1. **📁 Проект (Архитектура и Замысел):**
   * *Что содержит:* Цели, этапы, дорожную карту, принятые решения, документацию, структуру файлов.
   * *Цветовой акцент / символ:* Спокойный синий / графит.
2. **💬 Обсуждение (Диалог и Понимание):**
   * *Что содержит:* Диалог с ведущей моделью, рассуждения, постановка гипотез, уточнения.
   * *Цветовой акцент / символ:* Тёплый нейтральный / бежево-серый.
3. **💻 Код (Инженерия и Изменения):**
   * *Что содержит:* Файлы, диффы правок, терминальный вывод, логи компиляции, стек-трейсы.
   * *Цветовой акцент / символ:* Моноширинный / бирюзово-зелёный.
4. **🚀 Продуктовая среда (Результат):**
   * *Что содержит:* Живой интерфейс, веб-превью, запущенное приложение, работающий сервис.
   * *Цветовой акцент / символ:* Фиолетово-индиговый / яркий статус готовности.

## 5. Доступность (Accessibility WCAG 2.2 AA/AAA)

Для соответствия критериям жюри **UX Design Awards / iF / Red Dot**:
* **Клавиатурная навигация 100%:** Все действия (решения, переход между пространствами, откат, стоп) доступны через горячие клавиши (`1..4` — пространства, `Space` — решение, `Esc` — закрыть/назад, `Cmd+K` — быстрые действия).
* **Монохромная безопасность (Colorblind / High Contrast):** Ни один статус не передаётся только цветом. Обязательна формула: `Слово + Иконка/Символ + Цвет`.
* **Масштабирование:** Плавная адаптивность до 200% без потери функциональности и обрезания текстов.
* **Честное «Нет данных»:** Если система не знает время (ETA) или цель задачи, выводится явная плашка: `Оценки нет: мало статистики` вместо пустых прочерков или случайных цифр.

## 6. Границы хост-модели (Host Boundary)

* Харнесс выступает **Координатором и Надзорным органом**.
* Он читает журналы локальных и облачных агентов (Claude, Codex, Gemini, OpenClaw, Cursor).
* Действия агентов классифицируются по степени риска:
  * **Зелёный (Чтение / Поиск):** Полная автономия без запроса подтверждения.
  * **Жёлтый (Создание файлов / Ветка git):** Автономно с журналированием и возможностью отката.
  * **Красный (Удаление, перезапись вне git, расход > $5, доступ к секретам):** Строгая защитная пауза с подтверждением владельца.
