# Как работать над Harnessy

Репозиторий приватный; `main` — рабочая ветка владельца, в неё ничего не пушится напрямую.

1. **Только ветки и PR.** Новая ветка от свежего `main` (`git switch -c <тема>`) или форк. Готовое — Pull Request в `main`. Вливает владелец.
2. **Один PR — одна задача.** Описание: что было → что стало, как проверить.
3. **Перед PR:** `npm ci`, затем `npm test` — ноль упавших. Тесты лежат рядом с кодом (`packages/*/src/*.test.ts`). Правка окна (`ui/deploy`, `ui/sketches`) — пересобрать `python3 ui/deploy/build.py` и проверить экран при ширине 1440.
4. **Новые элементы окна** — сначала в дизайн-коде `ui/sketches/disarto/00-design-code.html`, потом на экранах.
5. **Секреты** (ключи, пароли, токены) не попадают в репозиторий: ключи — в связке ключей macOS.
6. **История `main` не переписывается:** без force-push и без удаления веток владельца.

Карта пакетов и правила ядра — `packages/README.md`; общий обзор — `README.md`.
