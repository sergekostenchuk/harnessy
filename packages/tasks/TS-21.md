## Как это сделано в DeepSeek Harness (~/REFERENCES/deepseek-harness, 5badb15)
- Свой слой вызова моделей, а не чужие агенты-программы: `packages/llm/llm` — провайдер-нейтральный сервис одного вызова модели (поток чанков, сообщения/блоки, отказы с устойчивыми кодами, учёт токенов); договор адаптера — `docs/subsystems/llm-streaming.md` (разделы «The adapter contract», «Service and provider contracts», «The model request»).
- Адаптер на библиотеке pi-ai — `packages/llm/llm-pi-ai` (src: config.ts, provider.ts, stream.ts, catalog.ts, discovery.ts, auth.ts, login.ts, models.ts): каталоги провайдеров pi-ai (адрес, протокол, модели по умолчанию) + вручную объявленные шлюзы (любой OpenAI-совместимый или иной протокол, свой адрес).
- Конфигурация — словарь `providers`: ключ = маршрут; поля `displayName`, `apiKeyEnv` (ссылка на учётные данные, секрет в конфиг не попадает, разрешается на каждый запрос), `api` (протокол провода), `baseURL`, `models` (замещает каталог; каждое поле по умолчанию из установленной модели), `modelOverrides`, `compat` (переключатели совместимости), `reasoningEfforts`, `defaultContextWindow`, `defaultMaxTokens`, `retryPolicy`.
- Обнаружение моделей: маршрут из каталога — без сети; свой адрес — запрос к эндпоинту провайдера.
- Строгая проверка маршрута при сохранении (нужны api, baseURL и непустой models для маршрута вне каталога); отказы с устойчивыми кодами; изменение маршрутов на лету.
- Агентный цикл и инструменты — свои (`packages/core/agent-loop`, `fs`, `shell`, `sandbox`, `mcp`).

## Решение для Harnessy
Модели по API обслуживает сам движок: свой сервис вызова моделей на pi-ai и свой агентный цикл с инструментами Harnessy. Чужие программы (Codex и др.) для API-моделей не используются. TS-20f (ключи API через Codex) — путь хода ОТМЕНЁН; её хранилище ключей в связке macOS, маска/дата, замена/удаление, owner_only — переиспользуются. Так как инструменты выдаёт сам движок, у API-моделей работают ВСЕ режимы места (чтение / правка / полный доступ), в отличие от программ без изоляции.
