# TS-17 — Читаемый ответ модели: Markdown, таблицы, код и артефакты (картинки, видео, файлы) в ленте чата

Статус: слово владельца 11.10.2026 22:40 (снимок: ответ оркестратора с «## Цель проекта» и таблицей состава из «|» выведен сырым текстом, нечитаем). Исполнитель — codex-worker2 после TS-12.3 (раньше TS-15b). Код сразу, одно ревью. Оркестратор: claude-orch.

| № | Что | Решение |
|---|-----|---------|
| 228 | разметка ответа | ответы моделей и записи канала рендерятся как Markdown в типографике дизайн-кода 00-design-code: заголовки, абзацы, списки, жирный/курсив, ссылки, цитаты, `код` и блоки кода с подсветкой языка и кнопкой «копировать», таблицы (`|…|`) как таблица дизайн-кода с прокруткой по ширине, разделители, чек-листы. Сырой HTML из текста модели не исполняется никогда (экранирование), ссылки только http(s)/mailto и внутренние пути проекта |
| 229 | артефакты в тексте | модель собирает ответ с вложениями: файлы, созданные ходом в папке проекта (`artifacts/`, `docs/` — по событиям записи файлов в следе хода) и явные ссылки на пути проекта в тексте рендерятся карточками дизайн-кода: изображение — превью в ленте (ленивая загрузка, предел размера, клик → полный размер), видео — встроенный плеер (mp4/webm), PDF/документы — карточка с именем, размером и «открыть», CSV/MD — таблица/текст по клику; пути проверяются realpath внутри проекта (как документы TS-09b2), чужие пути не отдаются |
| 230 | отдача файлов | `GET /api/project/file?path=…` (или существующий маршрут разделов TS-09a) отдаёт файлы проекта с правильным типом, без листинга каталогов, с границей проекта и пределом размера; без кэша на ошибках |
| 231 | договор с моделью | во вводные ролей (context/onboarding) добавляется короткое правило: «артефакты клади в `artifacts/` проекта и ссылайся на них относительным путём; таблицы — Markdown» — чтобы модели сами собирали читаемые ответы с вложениями |
| 232 | тесты и проверка | DOM: таблица из снимка владельца (состав команды) → табличная разметка; код; ссылки; экранирование `<script>`; картинка/видео/PDF из фикстур; путь вне проекта → отказ; снимок ленты рядом с текстом модели |

Пути: `ui/deploy/{live.js,cx.js,proto.css}`, `ui/sketches/disarto/00-design-code.html` (элементы: таблица, код, карточка артефакта, превью), `packages/api/src/*` (маршрут файла, тесты), `packages/context/src/onboarding.ts`. Без новых зависимостей, если рендер Markdown умещается в свой модуль (~300 строк); иначе — `question` с кандидатом и причиной.
