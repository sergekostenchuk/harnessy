# TS-19.1 — БЛОКЕР: перенос контекста отвергает законную историю повышенного чата и останавливает ход

Статус: **ВЛИТА** 12.10.2026 01:25 (ts/TS-19.1 c49a5178, codex-worker, вердикт 9/10 №686, ворота 1317/1317 в одиночном прогоне; при четырёх параллельных были 2 таймаута чужих тестов). Исходно: факт владельца 11.10.2026 23:18. Оркестратор: claude-orch.

## Причина (факты)
`packages/runtime/src/chats.ts:49`: снимок контекста берёт записи журнала по recordSeqs сообщений чата и бросает `context_binding_invalid` (409), если у записи `to` не содержит текущее место и не `*`. Чат оркестратора `c1a12c338d01b57c` повышен из разговора «без роли» (TS-09b2): ранние записи адресованы `room`. Проверка от подмены (TS-19 №626) сработала на законной истории; ошибка не отфильтровала записи, а остановила ход владельца.

| № | Что | Решение |
|---|-----|---------|
| 255 | законная родословная | записи, адресованные прежнему месту чата по сохранённой операции повышения (`chat.promotion.source` → pane `room`/прежний sid) и `*`, — законные; проверка привязки сравнивает по идентификатору чата/операции, а не только по текущему pane |
| 256 | отказ ≠ блок хода | любой отказ сборки снимка (`context_binding_invalid`, повреждённые источники, предел) не останавливает ход владельца: ход идёт без переноса (или с частичным — только проверенные записи), в ленте отметка «контекст не передан: <причина>», событие в status/SSE; настоящая подмена (чужой проект/чат) по-прежнему исключается из снимка — но тоже без блокировки сообщения владельца |
| 257 | очередь | сообщение, застрявшее в очереди из-за отказа, уходит со следующим ходом без повторной ошибки (регрессия на живом сценарии: повышенный чат, смена вендора, две записи до повышения) |
| 258 | тесты | повышенный чат (записи room → orchestrator) → смена вендора → ход идёт, контекст передан, отметка без ошибки; чужая запись (другой чат/проект) → исключена из снимка, ход идёт, отметка с причиной; прежние пробы №626/№654 не сломаны |

Пути: `packages/runtime/src/chats.ts`, `promotion.ts` (чтение source), `runtime.ts` (отказ → отметка, не исключение), `packages/context/src/session.ts` (по вопросу воркера №667: необязательное `failure:{code,reason}` и честная подпись transferLabel), `packages/runtime/src/pane.ts` (перенос failure в компактный contextTransfer статуса, чтобы причина доходила до GET /api/status), тесты рядом (session-transfer.test.ts).
