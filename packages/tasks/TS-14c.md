Статус: слово владельца 11.10.2026 19:15; после TS-12 тому же исполнителю (codex-worker2). Код сразу по строкам (CODE FIRST), одно ревью на коде. Оркестратор: claude-orch.

## Слово владельца
«Там была хорошая инфографика, хорошая настройка, всё было понятно. Сейчас прочерки и прайс-лист. Откуда мне брать цены токенов из подписки? Прайс-лист можно оставить как донастройку, но это не главный экран расходов и лимитов».

| № | Что | Решение |
|---|-----|---------|
| 204 | главный экран 05-spend | как скетч ui/sketches/disarto/05-spend.html: карточки подписок с процентом, шкалой, окном и сбросом (данные TS-12), пороги-переключатели, роутер моделей с графом, «История ходов», «Платежи и сбросы»; раскладка и размеры скетча |
| 205 | данные вместо образца | где движок данные отдаёт (/api/spend: ходы, токены, кэш, время, по вендорам/моделям/дням; /api/limits) — показывать их в той же графике; где не отдаёт — образец скетча с пометкой «макет», не прочерк |
| 206 | прайс-лист | убрать с главного экрана; остаётся в Настройках → «Прайс-лист» (set.js уже есть) и доступен из 05-spend одной ссылкой «цены моделей (донастройка)» внизу; стоимость в деньгах показывается только там, где прайс заполнен, иначе — токены |
| 207 | откат строк TS-14 | строки 162/177 (TS-14.md) в части «нет данных → пустая карточка» отменяются явно; тесты spend-ui.test.ts, ожидающие прочерки/«нет данных», переписываются с докладом «было → стало» |
| 208 | проверка | снимок страницы рядом со скетчем (как делал Kimi в UX-SKETCH-AUDIT): каждый блок скетча присутствует и подписан «живое/частично/макет»; ни одного блока с прочерком |
| 209 | названия и блоки | только из скетча 05-spend и дизайн-кода 00-design-code: никаких выдуманных карточек («Роутер провайдеров», «остаток API» — убрать); подключение `router` движка показывается только внутри блока «Роутер моделей» скетча (граф), не как подписка; третий слот подписок — провайдер по ключу API, как «Qwen · ключ API» в скетче, только если подключён (слово владельца 11.10 20:30) |
