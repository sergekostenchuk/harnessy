# TS-04c — ask, подтверждения владельца, слияние, afterTurn (часть 3 из 3 по TS-04)

Статус: **договор** (опись воркера №143 принята; семь решений описи приняты оркестратором — строки 58–64; вопрос ревьюеру одним раундом). Оркестратор: claude-orch.
Код — в ветке `ts/TS-04c` от `ts/TS-04b` (b121c25), после вливания TS-04b — на принятый `main`. Таблица TS-04 (1–44), договоры TS-04a (45–49) и TS-04b (50–57) действуют как есть.

## Что входит
`ask` между окнами (строки 4, 34, 41), owner-ack (8, 35), `merge` (24) для ролей из `mergeRoles` и для владельца, настоящий `afterTurn` (3, 7, 42–43: автоответы `origin auto`, `awaiting` по review-request, напоминание `origin nudge`, эскалация), порт `RuntimeActions` целиком (ask/merge/afterTurn/restorePendingAcks/cancelAsks; `assignRole` из TS-04b сохраняется) — `unavailableActions` больше не используется в сборке. Все точные тексты отказов, заголовков карточек, статусов и инструментов — из описи №143 дословно (ask: sender_unknown/to_unknown/ask_failed ×3, «Ответа нет: …», «(пустой ответ)», peerReply ≤ 4000; owner-ack: «Подтвердить отправку #{seq} {kind} → …?», detail ≤ 600, 86400 с, тексты ack/rejected/note; merge: policy_denied/no_repo/sha_unknown/not_accepted/merge_failed, сообщение коммита, статус, тексты инструмента; afterTurn: nudge и escalation дословно).
