# TS-09b3.1 — Инструменты предложения состава отклоняются Codex при approval=never (блокирует главный сценарий)

Статус: факт владельца 11.10.2026 22:40 (снимок чата «Юристы 4114», проект реальный): оркестратор на gpt-6-luna составил предложение из пяти ролей, но «зарегистрировать через propose_seats не удалось: MCP отклонил вызов, поскольку он требует approval, а политика системы — approval=never; proposalId и version не получены; отправить статус владельцу через MCP также не удалось по той же причине». Исполнитель — codex-worker, СРАЗУ после круга 2 TS-14c (раньше TS-09b4). Код сразу, одно ревью. Оркестратор: claude-orch.

| № | Что | Решение |
|---|-----|---------|
| 224 | причина | все режимы мест Codex задают `approvalPolicy: 'never'` (packages/providers/src/modes.ts:6–12, provider.ts:84); инструменты pane-mcp (`propose_seats`, `create_seats`, и по словам модели — статус владельцу) Codex считает требующими подтверждения и при never отклоняет. Установить точное правило Codex app-server (аннотации MCP-инструментов readOnlyHint/destructiveHint, список инструментов без подтверждения, либо отдельная политика для MCP) на дублёре app-server — и закрепить тестом |
| 225 | исправление | инструменты Harnessy (`send`, `ask`, `merge`, `assign_role`, `propose_seats`, `create_seats`, статус) никогда не должны требовать подтверждения Codex: подтверждение владельца живёт в карточке Harnessy (TS-09b3), а не в Codex. Объявить их в `tools/list` с нужными аннотациями (например `annotations:{readOnlyHint:false, destructiveHint:false, openWorldHint:false}` или что требует правило из 224) и/или передавать в `turn/start` политику, разрешающую MCP-инструменты Harnessy без подтверждения, не ослабляя sandbox/approval для файлов и команд |
| 226 | проверка на живом | после слияния — повтор сценария владельца на :3777 в проекте «Юристы 4114»: оркестратор вызывает `propose_seats`, получает proposalId/version, карточка подтверждения появляется у владельца (ход модели — с разрешения владельца, один вызов) |
| 227 | тесты | дублёр app-server: вызов `propose_seats` при approvalPolicy never проходит; инструменты файлов/команд при never по-прежнему ограничены sandbox; регрессия на `ask`/`send` |

Пути: `packages/providers/bin/pane-mcp.mjs`, `packages/providers/src/{modes.ts,tools.ts,schemas.ts}`, `packages/providers/src/codex/{provider.ts,overrides.ts}` и тесты рядом.
