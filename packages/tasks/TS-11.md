# TS-11 — Мерцание макета: при переходе между страницами на долю секунды видна демонстрационная начинка

Статус: задача (слово владельца 11.10.2026 06:20 по снимку: при переключении папок и открытии чата из другой папки мелькает «Оркестратор · OMG · прогон H1.5», проценты 62 %/94 %, «проекты — из движка»). Класс повторяется на всех страницах. Оркестратор: claude-orch. Очередь: после TS-07.2, до TS-09a (мелкая, общий механизм).

## Класс дефекта (проверено по исходникам)
Каждая страница окна — отдельный HTML-скетч с **зашитой демонстрационной начинкой** (`ui/sketches/disarto/01-chat.html`: разговор «Оркестратор · OMG», прогон H1.5, решения; виджет «Использовано» с процентами; `cx.js:9` — папка по умолчанию `OMG`). Переход между страницами — **полная загрузка** другой страницы (`proto.js:74–76`: `location.href = PAGES[k]`). Живой слой стирает макет только **после ответа движка** (`live.js:172` `hConnect` → `/api/status` → `applyStatus`), то есть через сетевой круг после первой отрисовки. Между первой отрисовкой и ответом виден макет. Имя класса: **мерцание макета** (flash of demo content). Частный случай той же причины — Kimi: «нарисованное показано как настоящее» (TS-10/113, 119), но здесь макет виден даже там, где живой слой его потом стирает.

## Исходы (141–143)
| № | Ситуация | Исход |
|---|---|---|
| 141 | первая отрисовка любой страницы при подключённом движке | до ответа движка демонстрационная начинка не видна: один общий механизм — всё демонстрационное помечено `data-demo` (или общий контейнер), корневой атрибут `html[data-live-pending]` выставляется **синхронно** первым скриптом в `<head>` (до первой отрисовки), CSS скрывает `[data-demo]` при `data-live-pending`; живой слой снимает атрибут после первой отрисовки настоящих данных, показывая скелет/пустое состояние вместо макета. Движок недоступен → через предел ожидания (например, 1,5 с) макет показывается с общей подписью «макет» (конвенция TS-10/113). |
| 142 | переход между страницами и смена проекта/чата | последний живой снимок (`/api/status`, список чатов, текущий проект) сохраняется в окне (sessionStorage) и рисуется **до** ответа движка, затем уточняется ответом; снимок другого проекта не показывается (привязка к проекту); папка по умолчанию `OMG` из `cx.js` не используется при подключённом движке. |
| 143 | регрессия класса | тест через дубль DOM: загрузка страницы с задержанным `/api/status` → в DOM нет видимых `[data-demo]` до ответа; после ответа — настоящие данные; при недоступном движке — макет с подписью. Проверка на всех страницах прототипа (цикл по `PROTO_PAGES`), не только на чате. |
