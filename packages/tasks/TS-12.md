# TS-12 — Виджет лимитов провайдеров в сайдбаре: настоящие остатки подписок, «подробнее», переход к расходу

Статус: задача (слово владельца 11.10.2026 06:25). Оркестратор: claude-orch. Опись → договор → код. Очередь: после TS-09a (или раньше по слову владельца).

## Слово владельца
«Куда делся виджет с остатками лимитов провайдеров? Там должны быть минимум три основные подписки, которыми пользуется пользователь, с возможностью раскрытия всех. Чтобы у него перед глазами всегда были лимиты, а при нажатии «подробнее» показать все лимиты с гиперссылкой перехода на страницу со статистикой расходов.»

## Факты
- Виджет «Использовано» (`proto.js:52`, блок `.limits` внизу сайдбара) при подключённом движке заменён на «Расход · открыть» (`live.js:844`) 09.10 по находке Kimi (путь 5): проценты были нарисованными, движок лимитов не отдаёт. Виджет нужно вернуть с настоящими данными.
- Движок сегодня не ловит лимиты ни у одного провайдера (`packages/providers` — нет `rate_limits`/`usage`). Codex app-server присылает лимиты подписки в событиях `token_count` (поле `rate_limits`: окна с `used_percent`, `window_minutes`, `resets_in_seconds` — в транскриптах чатов Codex они есть; точную форму для нашего моста установить в описи). Claude: окно Claude Code показывает «5-hour», «Weekly · all models», «Weekly · <модель>» через OAuth-сервис использования под входом по подписке — для движка путь установить в описи (без печати и копирования токенов; только чтение процентов и времени сброса); если без токена нельзя — честно «лимиты Claude движок не читает» с объяснением.
- Состав виджета — слово владельца 11.10 06:40: только подключённые провайдеры, не больше трёх самых активных, либо столько, сколько есть.

## Слово владельца 11.10.2026 19:15 (приоритет выше всей очереди; исполнитель — codex-worker2, сразу код по строкам)
Было в скетче 05-spend и в сайдбаре: карточка подписки с большим процентом и шкалой — «Claude Max · 62,4 % недели · 18 % пятичасового окна», «Codex · 94 % пятичасового», «Qwen/Kimi · ключ/месяц»; пороги «переключать при лимите», «предупреждать при 80 %». Сейчас: прочерки и «макет · нет данных» — это та же ошибка класса «удалил нарисованное», только в виде пустоты. Лимиты = подписки и их окна: Claude и Codex — пятичасовое и недельное, Kimi — месячное. Цены моделей и прайс-лист к лимитам подписки отношения не имеют и на главном экране не живут.
