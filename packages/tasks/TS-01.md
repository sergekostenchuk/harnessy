# TS-01 — Адаптеры провайдеров: пакет `packages/providers`

Статус: таблица на сверке у ревьюера (codex-reviewer); воркер (codex-worker) делает опись без кода. Код — после договора.
Оркестратор: claude-orch. Образец поведения: `core/app/claude_provider.py` (232 строки), `core/app/codex_provider.py` (359), контракт
событий окна `core/app/panes.py` (`publish`, `ask_approval`, `APPROVAL_TIMEOUT_SEC = 15 мин`), мост `core/app/bridge.py` (`sdk_server`),
внешний мост Codex `core/bin/pane-mcp.mjs`, окружение маршрута `core/app/connections.py::proxy_env`.

## Цель
Один пакет с общим интерфейсом провайдера и двумя адаптерами, которые ходят по подписке, без API-ключей:
- **Claude** — `@anthropic-ai/claude-agent-sdk` (TypeScript): один ход = один `query()` в режиме потокового ввода
  (нужен для `interrupt()` и `streamInput()`), разговор продолжается через `resume`.
- **Codex** — `codex app-server` (JSON-RPC 2.0 по stdio, JSONL), **только документированный протокол**: `initialize`/`initialized`,
  `thread/start`, `thread/resume`, `thread/read`, `thread/list`, `turn/start`, `turn/steer`, `turn/interrupt`, `model/list`, учётная запись.
  Python-адаптер цеплял обработчик разрешений через внутреннее поле SDK — в новом так нельзя.

Ядро (другие пакеты) получает от провайдера только события и текст хода; провайдер не знает о журнале, чатах и команде.

## Границы
Пути: `packages/providers/**` (свой `package.json` с `"name": "@harnessy/providers"`, `tsconfig.json` от `tsconfig.base.json`, `src/`, `bin/`).
Зависимости: `@anthropic-ai/claude-agent-sdk`, `zod` (схемы инструментов MCP). Другие — только через `question`.
Внешние процессы: бинарь Claude Code пользователя (`CLAUDE_BIN` или `~/.local/bin/claude` → `pathToClaudeCodeExecutable`; вход
по подписке `claude login`, переменная `ANTHROPIC_API_KEY` из окружения вырезается, как и `CLAUDECODE`, `CLAUDE_CODE_SIMPLE`),
`codex app-server` из `PATH` (вход ChatGPT из `~/.codex/auth.json`; файл не читать).
Мост между окнами для Codex: `core/bin/pane-mcp.mjs` копируется в `packages/providers/bin/pane-mcp.mjs` как есть (он ходит
по HTTP в ядро: `/api/send`, `/api/ask`, `/api/merge`, `/api/assign_role`, `/api/pane_transcript`; эти маршруты даст пакет `api`).

## Сущности и интерфейсы (`src/types.ts`)
```ts
export type Mode = 'chat' | 'read' | 'check' | 'web' | 'ask' | 'edit' | 'all';
export type Vendor = 'claude' | 'codex';
export interface Seat {                 // срез места, нужный провайдеру (Pane в Python)
  id: string; vendor: Vendor; label: string; model: string; mode: Mode; cwd: string;
  sessionId: string | null; writePaths: string[]; worktree: string | null;
}
export type TurnEvent =
  | { type: 'delta'; text: string }
  | { type: 'tool'; name: string; detail: string }
  | { type: 'toolError'; text: string }
  | { type: 'approval'; id: string; title: string; detail: string }
  | { type: 'approvalResolved'; id: string; decision: 'allow' | 'deny' | 'timeout' }
  | { type: 'done'; sessionId: string | null; model: string; durationMs: number; usage: Usage }
  | { type: 'error'; text: string };
export interface Usage { input: number | null; output: number | null; cacheRead: number | null }
export interface PeerTools {            // мост к ядру; провайдер только пробрасывает (реализация — в ядре, в тестах — дублёр)
  send(args: Record<string, unknown>): Promise<ToolResult>; ask(args): Promise<ToolResult>; readPane(args): Promise<ToolResult>;
  merge(args): Promise<ToolResult>; assignRole(args): Promise<ToolResult>;
}
export interface TurnContext {
  publish(ev: TurnEvent): void;
  askApproval(title: string, detail: string): Promise<boolean>;     // карточка владельцу; таймаут 15 мин = false
  setHandle(h: TurnHandle): void;                                   // interrupt/steer текущего хода
  env: Record<string, string>;                                      // маршрут провайдера (прокси) — поверх окружения процесса
  roleNote: string;                                                 // инструкции роли + политика + корень проекта (даёт ядро)
  peers: { id: string; label: string; vendor: Vendor }[];           // соседние окна — для текстов и схем инструментов
  tools: PeerTools; relayDepth: number; projectDir: string | null; appUrl: string;  // appUrl — для bin/pane-mcp.mjs
}
export interface TurnHandle { interrupt(): Promise<void>; steer(text: string): Promise<void> }
export interface Provider {
  readonly vendor: Vendor;
  runTurn(seat: Seat, message: string, ctx: TurnContext): Promise<{ text: string; sessionId: string | null }>;
  listSessions(cwd: string): Promise<{ id: string; title: string; updated: number }[]>;
  sessionMessages(cwd: string, sessionId: string): Promise<{ role: 'me' | 'ai'; text: string }[]>;
  auth(): Promise<{ loggedIn: boolean; [k: string]: unknown }>;
  models(): Promise<{ id: string; label: string }[]>;
  reset(): Promise<void>;   // закрыть процессы мест (смена маршрута); сессии остаются
  close(): Promise<void>;
}
```
Тексты системных заметок (`SYSTEM_CHAT`, `team_note`, `peer_note`, хвосты режимов, `CHAT_INSTRUCTIONS`, `approval_title`)
переносятся дословно из Python: это поведение, которое видят модели.

## Граф подзадач
```
A types.ts (интерфейсы, события, таблица режимов как данные)
├─ B claude.ts: options(seat, ctx) по таблице · runTurn · MCP panes (createSdkMcpServer: send/ask/read_pane/merge/assign_role → ctx.tools) · listSessions/sessionMessages · auth
├─ C codex/: client.ts (spawn, JSONL, initialize, запросы/уведомления/серверные запросы) · provider.ts (thread, turn, approvals, interrupt/steer, model/list, auth, overrides) · bin/pane-mcp.mjs
└─ D дублёры и тесты: claude — инъекция `queryFn` (сценарный поток сообщений SDK); codex — инъекция транспорта (фейковый app-server: очередь уведомлений, серверные запросы, ответы)
Порядок: A → B и C параллельно → D. Опись (E) — до всего.
```

## Тесты (сценарии; каждый с названным риском; `node:test`, без сети, без настоящих провайдеров и ключей)
1. Режим → права (строки 1–8): для каждого режима опции/параметры ровно ожидаемые. Риск: расширение прав молча.
2. Разрешение (9–10): запрос → `approval` → allow/deny/таймаут → правильный ответ SDK/сервера; таймаут = отказ. Риск: действие без владельца.
3. Поток (11–13): дельты → `done` с usage и sessionId; без стрима — один `delta` с полным текстом. Риск: пустой ответ в чате (урок 08.10).
4. Ошибка (14): `is_error` / `failed` → `error` с текстом и исключение. Риск: окно «думает…» навсегда (урок 08.10).
5. Прерывание (15): после `interrupt` ровно один `done`/`error`. Риск: двойной конец хода.
6. Смена папки (20): отказ во время хода, новый процесс после. Риск: ход в чужой папке.
7. Overrides (21) и окружение (19): строки `-c` и env как в таблице; служебные переменные Claude вырезаны, прокси подставлен. Риск: чужие MCP и утечка ключа в процесс.
8. Списки (22): `strip_digest`, слияние подряд идущих ответов. Риск: сводка соседей в истории.
Тестов «ради тестов» нет: каждый — строка таблицы или пойманный дефект.

## Что воркер проверяет в описи (до кода)
- Имя пакета и точные опции TS SDK: `pathToClaudeCodeExecutable` против встроенного бинаря SDK — ход должен идти по подписке
  пользователя, как в Python (вход `claude login`), не по API-ключу; потоковый ввод для `interrupt`/`streamInput`.
- app-server: где в `turn/start`/`thread/start` живут `developerInstructions` (в Python — параметр `thread/start`; документация
  показывает `collaborationMode.settings.developer_instructions`), имена `sandbox` vs `sandboxPolicy`, метод учётной записи,
  форма ответов на `item/*/requestApproval` и `mcpServer/elicitation/request`, формат `-c` overrides при запуске.
- Что из Python-кода опирается на внутренние поля SDK (`_client._sync._approval_handler`, `_client.request`) и чем это заменяется.
