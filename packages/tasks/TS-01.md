# TS-01 — Адаптеры провайдеров: пакет `packages/providers`

Статус: сверка завершена (круг 1 №5 — 7 пунктов, круг 2 №8 — 2 пункта; все внесены; ревьюер рекомендовал разрешить реализацию, решение оркестратора 09.10 ~01:30). Код — после описи воркера и договора.
Оркестратор: claude-orch. Образец поведения: `core/app/claude_provider.py` (232 строки), `core/app/codex_provider.py` (359), контракт
событий окна `core/app/panes.py` (`publish`, `ask_approval`, `APPROVAL_TIMEOUT_SEC = 15 мин`), мост `core/app/bridge.py` (`sdk_server`),
внешний мост Codex `core/bin/pane-mcp.mjs`, окружение маршрута `core/app/connections.py::proxy_env`.

## Цель
Один пакет с общим интерфейсом провайдера и двумя адаптерами, которые ходят по подписке, без API-ключей:
- **Claude** — `@anthropic-ai/claude-agent-sdk` (TypeScript): один ход = один `query()` в режиме потокового ввода
  (нужен для `interrupt()` и `streamInput()`), разговор продолжается через `resume`.
- **Codex** — `codex app-server` (JSON-RPC 2.0 по stdio, JSONL), **только документированный протокол**: `initialize`/`initialized`,
  `thread/start`, `thread/resume`, `thread/read`, `thread/list`, `turn/start`, `turn/steer`, `turn/interrupt`, `model/list`, учётная запись.
  Python-адаптер цеплял обработчик разрешений через внутреннее поле SDK — в новом так нельзя.

Ядро (другие пакеты) получает от провайдера только события и текст хода; провайдер не знает о журнале, чатах и команде.

## Границы
Пути: `packages/providers/**` (свой `package.json` с `"name": "@harnessy/providers"`, `tsconfig.json` от `tsconfig.base.json`, `src/`, `bin/`).
Зависимости: `@anthropic-ai/claude-agent-sdk`, `zod` (схемы инструментов MCP). Другие — только через `question`.
Внешние процессы: бинарь Claude Code пользователя (`CLAUDE_BIN` или `~/.local/bin/claude` → `pathToClaudeCodeExecutable`; вход
по подписке `claude login`, переменная `ANTHROPIC_API_KEY` из окружения вырезается, как и `CLAUDECODE`, `CLAUDE_CODE_SIMPLE`),
`codex app-server` из `PATH` (вход ChatGPT из `~/.codex/auth.json`; файл не читать).
Мост между окнами для Codex: `core/bin/pane-mcp.mjs` переносится в `packages/providers/bin/pane-mcp.mjs` **с исправлениями**
(находка ревьюера, дефект исходного моста): тело запроса собирается как `{ ...args, from: PANE_ID }` — отправитель всегда своё
место, аргумент `from` из вызова модели его не подменяет (в `core` уже исправлено, коммит 09.10); аргументы проверяются по
`inputSchema` (неизвестные поля, не тот тип, не тот kind — отказ инструмента без запроса в ядро); каждый запрос несёт заголовок
`X-Pane-Token` из env `PANE_TOKEN` — **секрет процесса моста** (решение круга 2): провайдер создаёт его (32 случайных байта)
при запуске app-server вместе с мостом, кладёт в env MCP-сервера `panes`, сообщает ядру `ctx.registerProcessToken(token)`;
при закрытии клиента (`reset`, `close`, смена cwd) — `ctx.revokeProcessToken(token)`. Ядро (пакет `api`) принимает вызов моста
только с зарегистрированным токеном этого места И пока у места идёт ход; токен не пишется в логи и не уходит в чат.
Так один процесс обслуживает несколько ходов без перезапуска, а процесс, переживший своё место, теряет полномочия.
Маршруты ядра: `/api/send`, `/api/ask`, `/api/merge`, `/api/assign_role`, `/api/pane_transcript`.

## Сущности и интерфейсы (`src/types.ts`)
```ts
export type Mode = 'chat' | 'read' | 'check' | 'web' | 'ask' | 'edit' | 'all';
export type Vendor = 'claude' | 'codex';
export interface Seat {                 // срез места, нужный провайдеру (Pane в Python)
  id: string; vendor: Vendor; label: string; model: string; mode: Mode; cwd: string;
  sessionId: string | null; writePaths: string[]; worktree: string | null;
}
export type TurnEvent =
  | { type: 'delta'; text: string }
  | { type: 'tool'; name: string; detail: string }
  | { type: 'toolError'; text: string }
  | { type: 'approval'; id: string; title: string; detail: string }
  | { type: 'approvalResolved'; id: string; decision: 'allow' | 'deny' | 'timeout' }
  | { type: 'done'; sessionId: string | null; model: string; durationMs: number; usage: Usage }
  | { type: 'error'; text: string };
export interface Usage { input: number | null; output: number | null; cacheRead: number | null }
export type ToolResult = { ok: true; text: string } | { ok: false; error: string; code?: string };
export type Kind = 'task'|'status'|'question'|'answer'|'review-request'|'verdict'|'blocker'|'escalation'|'note'|'stop'|'resume'|'digest'|'proposal'|'decision'|'report';   // ровно KINDS из core/app/journal.py; служебные (protocol, rejected, policy, ack) агенту недоступны
export interface SendArgs { to: string; kind: Kind; text: string; thread?: string; reply_to?: number; evidence?: string[]; score?: number; round?: number; sha?: string }
export interface AskArgs { to: string; text: string; thread?: string }
export interface ReadPaneArgs { pane: string; last_n?: number }
export interface MergeArgs { sha: string; message?: string }
export interface AssignRoleArgs { role: string; model?: string; mode?: Mode }
export interface PeerTools {            // мост к ядру, УЖЕ связанный ядром с местом и ходом: провайдер никогда не передаёт «from»
  send(a: SendArgs): Promise<ToolResult>; ask(a: AskArgs): Promise<ToolResult>; readPane(a: ReadPaneArgs): Promise<ToolResult>;
  merge(a: MergeArgs): Promise<ToolResult>; assignRole(a: AssignRoleArgs): Promise<ToolResult>;
}
export type RouteEnv = Partial<Record<'HTTPS_PROXY' | 'HTTP_PROXY' | 'ALL_PROXY' | 'https_proxy' | 'http_proxy' | 'all_proxy', string>>;
export const FORBIDDEN_ENV = { claude: ['ANTHROPIC_API_KEY', 'CLAUDECODE', 'CLAUDE_CODE_SIMPLE'], codex: ['OPENAI_API_KEY'] } as const;  // вырезаются ПОСЛЕ слияния с RouteEnv
export interface TurnContext {
  signal: AbortSignal;                                              // отмена с самого начала runTurn: до запуска процесса → отказ `cancelled` без запуска
  publish(ev: TurnEvent): void;
  askApproval(title: string, detail: string): Promise<boolean>;     // карточка владельцу; таймаут 15 мин = false; при abort — сразу false, карточка закрыта ядром
  session(id: string): void;                                        // сессия известна → ядро сохраняет НЕМЕДЛЕННО (до исхода хода)
  setHandle(h: TurnHandle | null): void;                            // interrupt/steer текущего хода; null — по окончании хода (очистка)
  env: RouteEnv;                                                    // только переменные прокси (маршрут из ядра); ничего другого
  roleNote: string;                                                 // инструкции роли + политика + корень проекта (даёт ядро)
  peers: { id: string; label: string; vendor: Vendor }[];           // соседние окна — для текстов и схем инструментов
  tools: PeerTools; relayDepth: number; projectDir: string | null; appUrl: string;   // appUrl — для bin/pane-mcp.mjs
  registerProcessToken(token: string): void; revokeProcessToken(token: string): void;   // полномочия процесса моста Codex (см. «Границы»)
  writableRoots: string[];                                          // Codex sandbox: рассчитаны ядром (evidence своего git, общий .git у worktree; без своего git — пусто)
}
export interface TurnHandle { interrupt(): Promise<void>; steer(text: string): Promise<void> }
export type ErrorCode = 'no_binary' | 'not_logged_in' | 'session_missing' | 'model_unsupported' | 'protocol' | 'transport_lost'
  | 'cancelled' | 'busy' | 'cwd_changed' | 'turn_failed' | 'unknown_request' | 'models_unavailable';
export class ProviderError extends Error { code: ErrorCode; vendorText: string; sessionId: string | null }   // типизированный отказ: код общий, текст вендора отдельно
export interface Provider {
  readonly vendor: Vendor;
  runTurn(seat: Seat, message: string, ctx: TurnContext): Promise<{ text: string; sessionId: string | null }>;   // отказ — только ProviderError
  listSessions(cwd: string): Promise<{ id: string; title: string; updated: number }[]>;
  sessionMessages(cwd: string, sessionId: string): Promise<{ role: 'me' | 'ai'; text: string }[]>;
  auth(): Promise<{ loggedIn: boolean; [k: string]: unknown }>;   // независимо от models(): ошибка каталога НЕ означает «не вошёл»
  models(): Promise<{ id: string; label: string }[]>;             // ошибка → ProviderError('models_unavailable'); запасной список решает ядро
  reset(): Promise<void>;   // закрыть процессы мест (смена маршрута); сессии остаются
  close(): Promise<void>;
}
```
Тексты системных заметок (`SYSTEM_CHAT`, `team_note`, `peer_note`, хвосты режимов, `CHAT_INSTRUCTIONS`, `approval_title`)
переносятся дословно из Python: это поведение, которое видят модели.

## Отмена и жизненный цикл хода (правило, не пожелание)
1. Владелец карточек разрешений и событий `approval`/`approvalResolved` — ядро (`TurnContext`); провайдер только ждёт `askApproval`.
2. `runTurn` начинается с проверки `ctx.signal.aborted` (→ `cancelled`) и снимка `Seat`; `setHandle` вызывается ДО первого ожидания
   процесса; при любом исходе (успех, ошибка, отмена) — `setHandle(null)`, `publish` ровно одного терминального события.
3. Остановка ядром: сначала отклонить все ожидающие разрешения места, затем `handle.interrupt()`; поздний `allow` — пустая операция.
4. Смена настроек места (cwd, модель, режим, права) во время хода на ход не действует; параллельный запуск — `busy`.

## Граф подзадач
```
A types.ts (интерфейсы, события, таблица режимов как данные)
├─ B claude.ts: options(seat, ctx) по таблице · runTurn · MCP panes (createSdkMcpServer: send/ask/read_pane/merge/assign_role → ctx.tools) · listSessions/sessionMessages · auth
├─ C codex/: client.ts (spawn, JSONL, initialize, запросы/уведомления/серверные запросы) · provider.ts (thread, turn, approvals, interrupt/steer, model/list, auth, overrides) · bin/pane-mcp.mjs
└─ D дублёры и тесты: claude — инъекция `queryFn` (сценарный поток сообщений SDK); codex — инъекция транспорта (фейковый app-server: очередь уведомлений, серверные запросы, ответы)
Порядок: A → B и C параллельно → D. Опись (E) — до всего.
```

## Тесты (сценарии; каждый с названным риском; `node:test`, без сети, без настоящих провайдеров и ключей)
1. Режим → права (строки 1–8): для каждого режима опции/параметры ровно ожидаемые. Риск: расширение прав молча.
2. Разрешение (9–10): запрос → `approval` → allow/deny/таймаут → правильный ответ SDK/сервера; таймаут = отказ. Риск: действие без владельца.
3. Поток (11–13): дельты → `done` с usage и sessionId; без стрима — один `delta` с полным текстом. Риск: пустой ответ в чате (урок 08.10).
4. Ошибка (14): `is_error` / `failed` → `error` с текстом и исключение. Риск: окно «думает…» навсегда (урок 08.10).
5. Прерывание (15): после `interrupt` ровно один `done`/`error`. Риск: двойной конец хода.
6. Смена папки (20): отказ во время хода, новый процесс после. Риск: ход в чужой папке.
7. Overrides (21) и окружение (19): строки `-c` и env как в таблице; служебные переменные Claude вырезаны, прокси подставлен. Риск: чужие MCP и утечка ключа в процесс.
8. Списки (22): `strip_digest`, слияние подряд идущих ответов. Риск: сводка соседей в истории.
9. Обрыв и чужой терминал (24–25): EOF до `result`, `turn/completed` чужого `turnId`, двойной терминал → `transport_lost` / один `done`. Риск: ядро сдвигает очередь за невыполненную работу.
10. Отмена (26–27) и `busy` (28): abort до запуска — нет процесса; abort во время ожидания разрешения — deny + прерывание; поздний allow — ничего; второй `runTurn` — `busy`. Риск: действие после «стоп».
11. Снимок места (29): смена cwd после старта не меняет процесс и его `cwd`. Риск: ход в чужой папке.
12. Сессия при ошибке (30): сессия создана → ход упал → следующий ход продолжает ту же сессию. Риск: потеря памяти модели.
13. Неизвестный запрос и маскарад elicitation (31–32): чужой `serverName`, нет `_meta`, не тот kind → вопрос владельцу; неизвестный метод → отказ без вопроса. Риск: действие под видом своего моста.
14. Мост panes (bin): `from` всегда `PANE_ID` при любом аргументе; аргументы вне `inputSchema` — отказ до HTTP; заголовок `X-Pane-Token`. Риск: подмена инициатора (воспроизведено ревьюером на исходном мосте).
15. Коды отказов (33) и изоляция (34–35): каждому коду — свой вход; `settingSources`/`strictMcpConfig` в опциях; `RouteEnv` не возвращает запрещённые ключи. Риск: чужие настройки и ключ в процессе.
16. Токен процесса (36): регистрация при запуске, отзыв при закрытии/`reset`/смене cwd, токен в env моста и ни в одном логе; отсутствие токена в env → мост не отправляет запрос. Риск: мост, переживший место, действует от его имени. (Сверка токена с местом и ходом — тест пакета `api`.)
17. Виды записей: `report` принимается схемой инструмента и типом `Kind`, `ack` отклоняется. Риск: расхождение с протоколом журнала.
Тестов «ради тестов» нет: каждый — строка таблицы или пойманный дефект.
