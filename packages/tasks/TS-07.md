# TS-07 — Дверь владельца при незавершённом ходе: смена проекта, ошибка SSE без кода, повтор предупреждений

Статус: таблица на оценку ревьюеру; опись воркера → договор → код. Оркестратор: claude-orch.
Источник: замечания владельца №1 и №6 от 10.10.2026 (чат WORKER-HARNESSY, 18:52 и 19:13) и инцидент INCIDENT-SSE-RECONNECT (канал №200, 09.10 23:48).
Класс дефекта (конституция владельца, п.4): строгость без двери восстановления — владелец заперт в проекте.

## Факты (проверено оркестратором 11.10.2026 00:30)
- `/Users/Shared/chat-test/.harness/state/attempts.json`: `executor {turnInstanceId f96dac88…, recordSeqs [36], status "uncertain"}` — ход начат 09.10 23:35, итог неизвестен после перезапуска ядра.
- `packages/runtime/src/runtime.ts:89` `projectSet` → `reserve(p, все места)`; `operations.ts:21` `free()`: `pane.status!=='idle'` → `RuntimeError('uncertain'|'recovering', «ответ модели сохранён; завершается восстановление доставки», 409)`.
  То же у `projectCreate` (:94), `paneSet` (:281), `openSession` (:303). Окно показывает «Проект не открылся: …» (`ui/deploy/cx.js:178`), «Не вышло: …» (`cx.js:166`, `ctx.js:53`).
- Единственная дверь — скрытая: запись владельца этому месту снимает `uncertain` (`runtime.ts:126` → `clearUncertain` :129). Из окна это неочевидно; владелец исполнителю не писал.
- Инцидент SSE: `runtime.ts:131` `report()` даёт `code: undefined` для любой ошибки кроме `RuntimeError`; `packages/journal/src/compat-json.ts:13` бросает `TypeError` на `undefined`;
  `packages/api/src/sse.ts:23` пишет через этот сериализатор → поток `all` закрывается. Снимок шины при новой подписке (`runtime.ts:59`) повторяет `recoveryError`/`recoveryNote`; `ui/deploy/live.js:102` добавляет note в чат без дедупликации.

## Цель
Владелец никогда не заперт: незавершённый ход одного места не мешает открыть, создать или сменить проект; у каждого отказа «ожидание итога» есть видимая дверь; одно несериализуемое событие не рвёт поток окна.
