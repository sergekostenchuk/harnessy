# TS-22 — Сетевой маршрут провайдеров: прокси, VPS, запасные выходы

Статус: решения владельца 12.10.2026 ~16:50 (ответы на вопросы оркестратора). Оркестратор: claude-orch.

## Решения владельца
- Роутинг = **сетевой маршрут** провайдеров (не роутер моделей): «нужны настройки для подключения провайдеров proxy, ips, vps и ручная настройка; после этого проверка на реальных провайдерах моделей и самих моделях».
- VPS — **оба способа**: «прокси по адресу» (http/https/socks5, например прокси на VPS) и «VPS по SSH» (движок сам поднимает SSH-туннель ключом владельца из ~/.ssh и следит за ним; на VPS ничего не меняется).
- Запасной выход: **лимит (429), сбой (ошибка соединения, 5xx), молчание (нет ответа N с)** → следующий выход в списке провайдера, ход повторяется, в чате карточка «ход ушёл через запасной выход»; ошибка входа выход не переключает.
- Маршрут действует на **все места** этого провайдера.
- Если упали все выходы — **напрямую запрещено**, если «напрямую» не вписан в список явно: ход останавливается карточкой с причиной, настоящий IP не уходит провайдеру.

## Что уже есть (main 03d7081)
`packages/projects/src/connections.ts`: один маршрут на провайдера (direct / proxy / iface), только claude и codex; прокси — переменными HTTPS_PROXY/ALL_PROXY процесса программы; iface — только проверка выхода; проверка выхода — внешний IP (api.ipify.org), страна (ipapi.co), ожидаемый IP. API-модели TS-21 (packages/llm) и остальные программы маршрут не используют.

Тесты на дублёре ssh. |
