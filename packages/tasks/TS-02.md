## Цель
Один пакет `@harnessy/journal` с четырьмя частями и без знания об окнах, процессах и провайдерах:
- **Journal** — файл обмена `.harness/state/channel.ndjson` (только дописывание, одна запись JSON на строку, `fsync`), курсоры доставки
  `.harness/state/cursors.json`, состояние окон `.harness/state/panes.json` (чтение/запись атомарно: tmp + rename), выборки, ответы.
- **Policy** — `.harness/comms-policy.yaml`: маршруты по ролям и видам, триггеры `owner-ack` и `reply-to:<kind>`, границы раундов,
  наблюдение чужих разговоров, текст сводки для инструкций места; перечитывание по mtime.
- **Evidence** — свидетельства `.harness/evidence/<тред>/r<раунд>/report.md` по контракту Ran / Skipped / Planned / Manual.
- **Channel** — единственная точка записи для агентов и владельца: проверки формы, политика, триггеры, границы, отказы с записью
  `rejected` владельцу, состояние тредов (раунды, принято, sha, merged), ожидание подтверждения владельца (owner-ack) как состояние.
  Channel не доставляет записи окнам: он **публикует события** (`record`, `rejected`, `pendingAck`, `delivered`), на которые подпишется `runtime` (TS-04).

## Границы
Пути: `packages/journal/**`. Зависимости: разбор YAML (`yaml` — версию проверит опись); остальное — встроенные модули Node.
Роли мест и подписи Channel не знает: получает функции `roleOf(seatId) → role | null`, `labelOf(seatId) → string` и список живых мест от ядра.
Проверка SHA коммита для `review-request` — функция `resolveSha(sha) → fullSha | null` от ядра (пакет `projects`); в тестах — дублёр.
Вопрос владельцу при owner-ack задаёт `runtime` (карточка); Channel хранит состояние «ждёт подтверждения» и даёт `confirmAck(seq)` / `rejectAck(seq)`.

## Сущности и интерфейсы (`src/types.ts`)
```ts
export const KINDS = ['task','status','question','answer','review-request','verdict','blocker','escalation','note','stop','resume','digest','proposal','decision','report'] as const;
export const SYSTEM_KINDS = ['protocol','rejected','policy','ack'] as const;
export const REPLY_KIND = { question: 'answer', task: 'status', 'review-request': 'verdict' } as const;
export interface Record_ { seq: number; id: string; ts: string; from: string; to: string[]; kind: string; thread: string | null; reply_to: number | null;
  text: string; evidence: string[]; policy: number; score?: number; round?: number; origin?: string; accepted?: boolean; bounds?: object | null;
  ack?: 'pending'; sha?: string; merged?: string; version?: number; kinds?: string[] }   // поля и имена — как в Python, байт в байт
export type JournalCode = 'kind_unknown'|'to_invalid'|'to_unknown'|'self_addressed'|'text_empty'|'text_too_long'|'reply_to_missing'|'evidence_invalid'
  |'score_invalid'|'round_invalid'|'reply_to_required'|'sha_required'|'sha_unknown'|'evidence_required'|'evidence_outside'|'evidence_missing'|'evidence_contract'|'policy_denied';
export class JournalError extends Error { code: JournalCode }
export interface Journal { lastSeq; append(fields): Record_; get(seq); read({since,limit,thread,kinds}); repliesTo(seq); pendingFor(seat); advance(seat, seq);
  markAcked(seq); savePanes(data); loadPanes(); readonly channelPath; readonly cursors }
export interface Decision { allow: boolean; pending: boolean; reason: string; route: Route | null; bounds; trigger }
export interface Policy { version; default; routes; observe; load(); maybeReload(): boolean; routeFor(from,to,kind); allowedKinds(from,to); checkSend(from,to,kind): Decision;
  canObserve(role, targetRole): boolean; summaryFor(role, seatRoles, labels): string }
export interface Channel { post(input: PostInput): Record_;   // отказ — JournalError; запись rejected владельцу при отказе политики/границ
  confirmAck(seq): Record_ | null; rejectAck(seq): void; threads: Map<string, ThreadState>; on(event, handler) }
```

## Таблица исходов (строки = тесты)
| № | Ситуация | Исход |
|---|---|---|
| 1 | пустой файл обмена | первая запись `seq 0` от `harness` всем: `kind protocol`, `version 1`, `kinds` — текст протокола дословно из Python |
| 2 | `append` | `seq` = последний + 1 (сквозной, переживает перезапуск: `_load` читает файл, битые строки пропускаются), `id` = `hex(ms)-6hex`, `ts` ISO с миллисекундами и смещением |
| 3 | вид не из KINDS∪SYSTEM_KINDS | `kind_unknown` с подсказкой списка |
| 4 | `to` не строка/список непустых строк | `to_invalid`; строка → список |
| 5 | текст пуст / > 100 000 | `text_empty` / `text_too_long` |
| 6 | `reply_to` на отсутствующую запись | `reply_to_missing`; ответ без `thread` наследует тред цели; `reply_to = 0` → «нет ответа» (не ноль-запись), запись `protocol` не цель |
| 7 | `evidence` не список строк | `evidence_invalid` |
| 8 | `pendingFor(seat)` | записи с `seq` > курсора места, адресованные месту или `*`, не от самого места, без SYSTEM_KINDS, без `ack: pending` не подтверждённых |
| 9 | `advance(seat, seq)` | только вперёд; курсоры в `cursors.json` атомарно; после перезапуска курсоры и `seq` продолжаются (`test_reload_continues_seq_and_cursors`) |
| 10 | `read` | фильтры `since` (seq >), `thread`, `kinds`, `limit` (последние N; 0 — все) |
| 11 | `post`: адресат | `*` → все живые места кроме отправителя + owner (если отправитель не owner); неизвестное место → `to_unknown`; самому себе → `self_addressed` |
| 12 | `post`: verdict | `score` целое 0..10 (не bool) иначе `score_invalid`; `round` ≥ 1 иначе `round_invalid`; `reply_to` обязателен (`reply_to_required`); только ответ на `review-request` |
| 13 | `post`: review-request при git | `sha` обязателен (`sha_required`), `resolveSha` → полный SHA или `sha_unknown` |
| 14 | `post`: verdict и свидетельства | `evidence` обязателен (`evidence_required`); путь внутри проекта (`evidence_outside`); отчёт по контракту Ran/Skipped/Planned/Manual (`evidence_contract`), нет файла → `evidence_missing`; `sha` берётся из цели |
| 15 | `post`: report | каждое свидетельство существует, иначе `evidence_missing` |
| 16 | политика: owner и harness | политика не применяется |
| 17 | политика не читается | агенту `policy_denied` + запись `rejected` владельцу «политика связи не читается» |
| 18 | маршрута нет | `policy_denied` с подсказкой «<роль> может писать <роль> только: …» или «нет маршрута»; запись `rejected` владельцу; событие `rejected` (runtime покажет отправителю `toolError`) |
| 19 | триггер `reply-to:<kind>` | цель должна быть того вида И от того адресата, иначе отказ с текстом как в Python |
| 20 | триггер `owner-ack` | запись ложится с `ack: 'pending'`, НЕ доставляется (событие `pendingAck`); `confirmAck` → запись `ack` от owner с `reply_to`, `markAcked`, событие `delivered`; `rejectAck` → `rejected` владельцу + `note` отправителю «владелец не подтвердил» |
| 21 | границы вердикта | `round > max_rounds` → отказ «эскалируй владельцу» + `rejected`; `accepted = score ≥ accept_score`; `bounds` в записи |
| 22 | состояние тредов | по вердикту: `rounds = max`, `lastScore`, `accepted → sha`; при открытии проекта восстанавливается из истории (вердикты и `status origin merge` с `merged`) |
| 23 | `rejected` | всегда `from harness`, `to [owner]`, текст «<from> → <to> <kind>: <причина>», `policy` = версия |
| 24 | Policy.load | нужен список `routes`; маршрут — таблица; неизвестный вид → ошибка; триггер только `owner-ack` или `reply-to:*`; `bounds` таблица; `version`, `default`, `observe` (`*` или список) |
| 25 | `routeFor`/`allowedKinds`/`checkSend` | первый подходящий маршрут; `kinds: "*"` = все; подсказка допустимых видов |
| 26 | `canObserve` | owner — всегда; `*`; список ролей; иначе нет |
| 27 | `summaryFor` | текст дословно как в Python (маршруты по местам, триггеры в скобках, owner, кого читать) |
| 28 | `maybeReload` | изменился mtime → перечитать; ошибка чтения → прежняя политика и исключение не теряется |
| 29 | панель состояния | `savePanes`/`loadPanes` атомарно; битый JSON → `{}` |
| 30 | одновременные `append` | сериализуются (очередь), `seq` без дыр и дублей |
