# TS-19 — Передача контекста разговора при смене вендора/модели в одном чате

Статус: факт владельца 12.10.2026 00:20 (снимки чата «Оркестратор · Юристы 4114»): после переключения gpt-6-luna → gpt-6-sol (тот же Codex) контекст сохранился; после переключения на claude-haiku-5-5 новая модель разговор не получила («предметная вводная лежит в журнале повышения, которого я не вижу»). **ВЛИТА** 11.10.2026 23:35 (ts/TS-19 9969242, codex-worker, круг 2, вердикт 9/10 №654/№657, ворота 1249/1249). Оркестратор: claude-orch.

## Причина (факты кода)
`packages/runtime/src/pane.ts:59`: при смене `vendor` → `sessionId=null`, `sessionEpoch++` — новая сессия провайдера начинается пустой; стенограмма чата (`pane.transcript`) хранится в Harnessy только для окна и в первый ход новой сессии не передаётся. Смена модели внутри вендора сессию не сбрасывает (поток Codex/сессия Claude продолжаются — контекст цел). Ручной «Передать контекст» (handoff.ts) работает между чатами, но не при переключении вендора. Принцип «модели помнят через свои сессии, ядро хранит идентификаторы» — верен, но при смене вендора нужен автоматический перенос.

| № | Что | Решение |
|---|-----|---------|
| 245 | автоперенос при смене вендора | когда у места сбрасывается сессия (смена vendor; а также потеря/истечение сессии провайдера, уже ловимая как recovering), первый ход новой сессии получает блок «Контекст этого разговора» перед сообщением владельца: вводная роли и память проекта (как сейчас) + стенограмма чата: последние N сообщений дословно (по умолчанию 12) + более ранняя часть сжато детерминированно (заголовки/первые строки сообщений, без вызова модели) в пределах бюджета токенов (по умолчанию 20 000); формат — цитируемая стенограмма с ролями и временем, чтобы модель не приняла её за инструкции |
| 246 | состояние операций | в блок входят незавершённые сущности чата: ожидающее предложение состава (proposalId/version/состав), прикреплённые документы, ожидающие подтверждения владельца, последнее поручение — из сохранённого состояния, не из текста |
| 247 | видимость владельцу | в ленте чата отметка «контекст передан новой модели: N сообщений · ~K токенов · остальное сжато» с раскрытием содержимого; в status/SSE — событие переноса; стоимость хода учитывает переданный контекст (TS-14 расход) |
| 248 | настройки и предел | в Настройках владельца: число дословных сообщений и бюджет токенов переноса; при превышении — сжатие, не отказ; выключатель «не переносить» (тогда отметка «контекст не передан по настройке») |
| 249 | тесты | дублёры обоих провайдеров: смена Codex→Claude даёт первый ход с блоком и именно последние N сообщений; смена модели внутри вендора — без блока и без сброса сессии; потеря сессии → тот же перенос; бюджет превышен → сжатие; подделанная стенограмма (чужой проект/чат) не попадает; отметка и событие в ленте; ручной «Передать контекст» не сломан |
