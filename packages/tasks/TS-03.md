Статус: таблица на сверке у ревьюера; воркер — после TS-01 круг 2 и кода TS-02 (опись → договор → код). Оркестратор: claude-orch.
Образец поведения: `core/app/team.py` (манифест, шаблоны, `ensure_line`, `seed_orchestrator`), `core/app/gitops.py` (131 строка),
`core/app/connections.py` (120), `core/app/server.py`: `open_project` (git-часть 160–178, `_writable_roots` 113–120), `_init_project`,
`_no_project`, `_projects_root`, `_default_model`, `project_slug`, `_project_name_from`, `api_projects`, `project_create`, `project_set`,

Тесты-источники: `test_policy_team.py` (team: 66, 82, 110), `test_git_flow.py` (49, 71; 82/96/122 — runtime), `test_project_init.py` (все),
`test_pins.py`, `test_settings.py`, `test_connections.py`.

## Цель
**`@harnessy/team`** — манифест команды и роли, без знания о процессах и журнале:
- `loadTeam(harnessDir)`: `team.yaml` → `Team { version, project, integrationBranch, seats, harnessDir, mergeRoles, warnings }`; `Seat { id, role,
  label, vendor, model, mode, digest, writePaths, instructions, worktree }`; проверки и тексты ошибок дословно (`TeamError`); место с вендором не из
  `claude|codex` пропускается с предупреждением, не валит команду; пустая модель = модель вендора по умолчанию; `write_paths` — относительные без `..`;
  `worktree` — относительный внутри проекта; `instructions` по умолчанию `roles/<role>.md`, если есть.
- `ensureLine(projectDir)`: `.harness/{roles,state}`, `team.yaml` из `team-empty.yaml` (новая папка — без ролей), `comms-policy.yaml`, `roles/*.md`,
  `MEMORY.md` с подстановкой `{name}`/`{date}`; существующее не трогать. Шаблоны — файлы пакета `templates/` (копия из `core/templates`).
- `seedOrchestrator(harnessDir, vendor, model, mode)`: единственная роль по умолчанию, только если мест нет; заголовок `TEAM_HEADER` дословно.
- `addSeat(harnessDir, {role, label, vendor, model, mode, instructions})`: запись места в `team.yaml` (как `create_seat`/`assign_role`: `sid` = role или
  `role{n}`, label `{label} {n}`, `digest: false`, `instructions` при наличии файла, заголовок дословно); отказ, если `sid` уже есть.
- `instructionsFor(seat)`, `roleOf`, `ROLE_CATALOG` (orchestrator, assistant, architect, executor×, reviewer×, tester, researcher; `multi` у executor и reviewer),
  `MODE_IDS` (chat, read, check, web, ask, edit, all), `MODES` с подписями — как в Python.

**`@harnessy/projects`** — папка проекта и всё вокруг неё:
- `gitops`: `run`, `isRepo`, `ownRepo`, `repoRoot`, `head`, `currentBranch`, `branchExists`, `commitExists`, `resolveSha`, `ensureExclude`,
  `ensureWorktree(root, seat, relPath, baseBranch) → { path | null, note | null }`, `mergeCommitFor`, `mergeInto(root, sha, branch, message)` —
  тексты ошибок дословно; всё через `git` подпроцессом с таймаутом 60 с, ошибки словами.
- `openProjectGit(projectDir, seats, integrationBranch)`: `repoRoot` только для своего репозитория (внутри чужого — «без git» + предупреждение
  дословно), `evidence/` и `ensureExclude` для `.harness/state/`, `.harness/evidence/`, `.harness/digests/`, `.harness/logs/`, worktree мест с
  `seat/<id>` → `{ repoRoot, cwdBySeat, worktreeBySeat, branchBySeat, lineErrors }`.
- `writableRoots(repoRoot, hasWorktree)`: `[<root>/.git?, <root>/.harness/evidence]` как `_writable_roots`.
- `initProject(path, { git, model, orchestrator }, deps)`: папка → `git init` если не свой репозиторий (внутри чужого — свой вложенный) → `ensureLine` →
  `seedOrchestrator` → `{ created, git, orchestrator, memory }`; `projectSlug(text)` и `projectNameFrom(transcript)`; `projectsRoot(settings)`;
  уникальное имя `-2`, `-3`.
- Реестр: `~/.harness-projects.json` (список путей, `indent 1`), `~/.harness-last-project`, `listProjects(current)` как `api_projects`
  (`{path, name, hasTeam, seats, git, current}`; счёт мест из `team.yaml` закрытого проекта), `rememberProject` (не в тестах: `HARNESS_NO_LAST`),
  `validDir`.
- Закреплённые `~/.harness-pins.json` (realpath; kind folder|chat; чат — только открытой папки, поля из записи чата через функцию `chatMeta` от ядра).
- Настройки: `~/.harness-settings.json` (owner) и `.harness/state/settings.json` (project); `effective = project поверх owner`; `SETTINGS_APPLIES`
  (`defaultMode`, `projectsRoot`); проверка ключей/значений и `defaultMode ∈ MODE_IDS` дословно; `null` удаляет ключ.
- Подключения `~/.harness-connections.json`: `get/setRoute/proxyEnv/check` как `connections.py` (маршруты direct·proxy·iface, регулярки, состояния
  not_checked·checked·changed·failed·matches·mismatch, `curl` подменяемый). `proxyEnv(vendor) → RouteEnv` для `providers`.

## Границы
Пути: `packages/team/**`, `packages/projects/**`. Зависимости: `yaml 2.9.1` (как TS-02, тот же режим PyYAML); остальное — встроенные модули и `git`.
Что НЕ здесь: назначение роли как действие (журнал, вводная, чат) — `runtime`; `merge` как инструмент (право по `mergeRoles`, принятый sha из тредов) —
`runtime` вызывает `gitops.mergeInto`; чаты и `chats.json` — `runtime`; HTTP — `api`.

## Таблица исходов
| № | Ситуация | Исход |
|---|---|---|
| 1 | `team.yaml` без `seats` / не таблица | `TeamError` «нужен раздел seats (таблица мест; может быть пустой)» |
| 2 | имя места не по `^[a-z][a-z0-9_-]{0,30}$` или owner/harness/all/* | `TeamError` «недопустимое имя места …» |
| 3 | вендор не claude/codex | предупреждение «место …: вендор … здесь не ведётся …», место пропущено; все пропущены при непустом списке → `TeamError` «нет ни одного места…» |
| 4 | режим не из MODE_IDS / write_paths с `..` или `/` / worktree абсолютный | соответствующие `TeamError` дословно |
| 5 | `merge_roles` не список строк | `TeamError` |
| 6 | пустая модель | модель вендора по умолчанию подставляет реестр (здесь — пустая строка сохраняется) |
| 7 | `ensureLine` на пустой папке | полный набор файлов; повторный вызов ничего не перезаписывает; `MEMORY.md` с именем папки и датой |
| 8 | `seedOrchestrator` при непустом `seats` | `false`, файл не тронут |
| 9 | `addSeat` повторной одиночной роли | отказ «роль … в этой папке уже есть» решает вызывающий по `ROLE_CATALOG.multi`; `sid` занят → отказ |
| 10 | папка внутри чужого git | `ownRepo=false`, `repoRoot=null`, предупреждение «папка лежит внутри чужого git-репозитория (…)»; `initProject` делает свой `git init` |
| 11 | worktree места: нет базовой ветки | `(null, «нет ветки main: сделай первый коммит, потом worktree появятся»)`; путь существует и не worktree → замечание |
| 12 | worktree создан | ветка `seat/<id>`, `exclude` первого сегмента пути, `cwd`/`worktree`/`branch` места |
| 13 | `mergeInto`: корень не на интеграционной ветке / грязное дерево / нет коммита / конфликт | тексты дословно; при конфликте `merge --abort` |
| 14 | `mergeCommitFor` | первый merge-коммит на пути `sha..branch`, иначе сам `sha`; не предок → `null` |
| 15 | `initProject` | `created`, `git`, `orchestrator`, `memory`; модель места — переданная или первая claude/codex из каталога (функция от ядра) |
| 16 | `projectSlug` | до 4 значимых слов, стоп-слова, транслит, `[a-z0-9-]`, ≤ 40; пусто → `proekt-ДДММ-ЧЧММ` |
| 17 | реестр проектов | уникальные пути, несуществующие пропускаются в `listProjects`; `HARNESS_NO_LAST` отключает запись |
| 18 | закреплённые | `kind` не folder/chat или нет `path` → 400-отказ; папки нет → 404; чат не открытой папки → отказ; переключение без `on`, явно с `on` |
| 19 | настройки | `scope` не owner/project, `patch` не объект → отказ; ключ не `[A-Za-z0-9_]{1,40}` → отказ; значение не строка/число/флаг/список → отказ; `defaultMode` вне MODE_IDS → отказ; project без открытой папки → отказ; `null` удаляет |
| 20 | подключения | `setRoute`: вендор `[a-z][a-z0-9_-]{1,30}`, маршрут из трёх, прокси по регулярке, интерфейс `utun4|en0`, ожидаемый IP; смена маршрута сбрасывает `lastCheck`; `proxyEnv` только при `proxy`; `check` → состояния по таблице Python (с подменным curl) |
| 21 | пути во всех файлах владельца | `realpath` для закреплённых; `~` раскрывается; файлы с `indent 1`, `ensure_ascii False` |

## Граф подзадач
```
team:     A types/catalog → B manifest (load/validate) → C templates + ensureLine + seedOrchestrator + addSeat → тесты (test_policy_team 66/82/110, test_project_init)
projects: D gitops → E openProjectGit + writableRoots (test_git_flow 49/71) → F initProject/slug/registry (test_project_init) → G pins/settings/connections (test_pins, test_settings, test_connections)
team и projects независимы; projects.initProject зависит от team.ensureLine/seedOrchestrator (импорт @harnessy/team).
```
Тесты: временные папки и настоящий `git` (локально, без сети); файлы владельца — через переменные `HARNESS_*_FILE`/инъекцию путей, никогда настоящие `~/.harness-*`.

## Сдача и приёмка
`npm test` зелёный; `git status` чист; таблица «строка → тест»; тексты ошибок и предупреждений дословно (их читает владелец в окне).
