## Цель
**`@harnessy/team`** — манифест команды и роли, без знания о процессах и журнале:
- `loadTeam(harnessDir)`: `team.yaml` → `Team { version, project, integrationBranch, seats, harnessDir, mergeRoles, warnings }`; `Seat { id, role,
  label, vendor, model, mode, digest, writePaths, instructions, worktree }`; проверки и тексты ошибок дословно (`TeamError`); место с вендором не из
  `claude|codex` пропускается с предупреждением, не валит команду; пустая модель = модель вендора по умолчанию; `write_paths` — относительные без `..`;
  `worktree` — относительный внутри проекта; `instructions` по умолчанию `roles/<role>.md`, если есть.
- `ensureLine(projectDir)`: `.harness/{roles,state}`, `team.yaml` из `team-empty.yaml` (новая папка — без ролей), `comms-policy.yaml`, `roles/*.md`,
  `MEMORY.md` с подстановкой `{name}`/`{date}`; существующее не трогать. Шаблоны — файлы пакета `templates/` (копия из `core/templates`).
- `seedOrchestrator(harnessDir, vendor, model, mode)`: единственная роль по умолчанию, только если мест нет; заголовок `TEAM_HEADER` дословно.
- `addSeat(harnessDir, {role, label, vendor, model, mode, instructions, specialization?})`: запись места в `team.yaml` (как `create_seat`/`assign_role`:
  `sid` = role или `role{n}`, label `{label} {n}`, `digest: false`, `instructions` при наличии файла, заголовок дословно); отказ, если `sid` уже есть.
  **Специализация** (аннотация владельца №1 к плану, задел под 0.3 без переделки ядра): необязательное `specialization: { title, text }` — текст
  инструкций предметной специализации (например, «юрист по договорам») пишется в **`roles/seats/<sid>.md`** (путь формирует код; общий шаблон роли
  `roles/<role>.md` не трогается — у первого места `sid == role`, и совпадение файлов изменило бы инструкции остальных мест этой роли, п.3 круга 2);
  `instructions` места указывает на файл места, вводная = шаблон роли + специализация; права — только за каталожной ролью; `label` = `title`, если задан.
- `instructionsFor(seat)`, `roleOf`, `ROLE_CATALOG` (orchestrator, assistant, architect, executor×, reviewer×, tester, researcher; `multi` у executor и reviewer),
  `MODE_IDS` (chat, read, check, web, ask, edit, all), `MODES` с подписями — как в Python.

**`@harnessy/projects`** — папка проекта и всё вокруг неё:
- `gitops`: `run`, `isRepo`, `ownRepo`, `repoRoot`, `head`, `currentBranch`, `branchExists`, `commitExists`, `resolveSha`, `ensureExclude`,
  `ensureWorktree(root, seat, relPath, baseBranch) → { path | null, note | null }`, `mergeCommitFor`, `mergeInto(root, sha, branch, message)` —
  тексты ошибок дословно; всё через `git` подпроцессом с таймаутом 60 с, ошибки словами.
- `openProjectGit(projectDir, seats, integrationBranch)`: `repoRoot` только для своего репозитория (внутри чужого — «без git» + предупреждение
  дословно), `evidence/` и `ensureExclude` для `.harness/state/`, `.harness/evidence/`, `.harness/digests/`, `.harness/logs/`, worktree мест с
  `seat/<id>` → `{ repoRoot, cwdBySeat, worktreeBySeat, branchBySeat, lineErrors }`.
- `writableRoots(repoRoot, hasWorktree)`: `[<root>/.git?, <root>/.harness/evidence]` как `_writable_roots`.
- `initProject(path, { git, model, orchestrator }, deps)`: папка → `git init` если не свой репозиторий (внутри чужого — свой вложенный) → `ensureLine` →
  `seedOrchestrator` → `{ created, git, orchestrator, memory }`; `projectSlug(text)` и `projectNameFrom(transcript)`; `projectsRoot(settings)`;
  уникальное имя `-2`, `-3`.
- Реестр: `~/.harness-projects.json` (список путей, `indent 1`), `~/.harness-last-project`, `listProjects(current)` как `api_projects`
  (`{path, name, hasTeam, seats, git, current}`; счёт мест из `team.yaml` закрытого проекта), `rememberProject` (не в тестах: `HARNESS_NO_LAST`),
  `validDir`.
- Закреплённые `~/.harness-pins.json` (realpath; kind folder|chat; чат — только открытой папки, поля из записи чата через функцию `chatMeta` от ядра).
- Настройки: `~/.harness-settings.json` (owner) и `.harness/state/settings.json` (project); `effective = project поверх owner`; `SETTINGS_APPLIES`
  (`defaultMode`, `projectsRoot`); проверка ключей/значений и `defaultMode ∈ MODE_IDS` дословно; `null` удаляет ключ.
- Подключения `~/.harness-connections.json`: `get/setRoute/proxyEnv/check` как `connections.py` (маршруты direct·proxy·iface, регулярки, состояния
  not_checked·checked·changed·failed·matches·mismatch, `curl` подменяемый). `proxyEnv(vendor) → RouteEnv` для `providers`.
