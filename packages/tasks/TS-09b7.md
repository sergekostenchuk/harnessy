# TS-09b7 — Добавление мест к подтверждённому составу: идентификатор выдаёт движок, отказы говорят, что делать

Статус: живой дефект 12.10.2026 05:50 в проекте владельца «Юристы 4114» (трасса seq 1053–1065): оркестратор хотел добавить налогового юриста к подтверждённому составу p72fc6404… v1; вызвал `propose_seats` с выдуманным `proposalId:"p-tax-lawyer-2026-10"` → `proposal_invalid` «нужны proposalId и положительная целая version» (на деле — формат id не из движка); затем с другим id → `proposal_not_found`. Модель сдалась и спросила владельца. Исполнитель — codex-worker2, малая ветка от main, ПЕРЕД подготовкой TS-20e.

## Причина (класс ОТСУТСТВИЕ + «вопросы решает модель, факты — код»)
Описание инструмента «После подтверждения нужен новый proposalId» читается моделью как «придумай новый id сам». Идентификаторы — факт движка, не модели. Отказы не содержат действия.

| № | Что | Решение |
|---|-----|---------|
| 1 | договор `propose_seats` | новый состав = вызов БЕЗ `proposalId`/`version` — движок выдаёт `proposalId` (p+hex) и `version:1` в ответе; обновление ожидающего состава — `proposalId`+`version` из ответа; после подтверждения владельцем состав не редактируется — для добавления мест новый состав без `proposalId`, в `seats` только новые места (существующие не трогаются). Описание в `packages/providers/src/schemas.ts` переписать ровно так; схема: `proposalId` необязателен |
| 2 | отказы с действием | id не формата движка → `proposal_invalid` «proposalId не из ответа движка; для нового состава не передавай proposalId»; id подтверждённого состава → `proposal_confirmed` «состав <id> уже подтверждён и создан; для добавления мест вызови propose_seats без proposalId, перечислив только новые места»; не найден → «предложение не найдено: возьми proposalId из ответа propose_seats или не передавай его»; `version` без `proposalId` → отдельный текст |
| 3 | create_seats на новом составе с одним местом | создаёт только его; существующие места и чаты не меняются; карточка «Предложено в разговоре» (TS-09b5) показывает добавление как «+1 место к составу» |
| 4 | тесты | сценарий из трассы (выдуманный id → текст с действием; id подтверждённого → proposal_confirmed; без id → новое предложение, подтверждение, create_seats → +1 место, прежние 5 нетронуты); МАСКАРАД: чужой id формата p+hex → not_found с подсказкой, без утечки чужих составов; ОКНА: два новых предложения подряд → два разных id, подтверждение одного не трогает другое |
