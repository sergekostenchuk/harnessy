# Выходы и цепочки провайдеров

`Settings.network()` читает область `network` владельца. `NetworkSettings` выполняет миграцию, запись выходов и цепочек под той же блокировкой файла, что и настройки TS-21. Поле `network` недоступно через общий PATCH настроек; проект не может переопределить его.

`NetworkExit` экспортируется из `@harnessy/projects` (`src/network-config.ts`):

- Общие поля: `id`, `label`, необязательный `expectedIp` (IPv4/IPv6).
- `type: 'direct'`.
- `type: 'proxy'`: `url` (`http`, `https`, `socks5h`, без userinfo/пути/параметров), необязательный `login`. Сохранённый пароль представлен только `passwordRef` (= id выхода) и `passwordGeneration`.
- `type: 'ssh'`: `host`, `port`, `user`, `keyPath` (абсолютный путь внутри `~/.ssh` либо запись `~/.ssh/...`, без `..`). Содержимое ключа не читается. При сохранении проверяются существование файла и realpath внутри ~/.ssh; ссылка наружу или отсутствие файла → `400 ssh_key_invalid`. Содержимое не читается. При запуске транспорт TS-22b повторяет проверку.

Пароли используют `MacKeyStore({purpose:'proxy-password'})`: тот же backend Security.framework, отдельный service от ключей API. Каждая запись создаёт неизменяемое поколение. Конфигурация с адресом и ссылкой публикуется атомарно, затем прежнее поколение удаляется. При отказе публикации новое поколение удаляется. В HTTP доступны только наличие, полная маска и дата. Внутренний `resolvePassword(exit)` читает поколение захваченного выхода.

## HTTP (только владелец)

| Метод | Путь | Тело / ответ |
|---|---|---|
| GET | `/api/network/exits` | `{ok, exits:[{config,revision,password:{present,mask,updatedAt}}]}` |
| POST | `/api/network/exits/:id/save` | `{config,revision,password?}` → `{ok,config,revision,password:{present,mask,updatedAt}}` |
| GET | `/api/network/exits/:id/removal` | `{ok,id,label,revision,networkRevision,chains,changes}` — последствия удаления |
| POST | `/api/network/exits/:id/delete` | `{revision,confirmation?:{networkRevision,chains}}` → `{ok}` |
| GET | `/api/network/providers/:id` | `{ok,provider,configured,exits,revision}` |
| POST | `/api/network/providers/:id` | `{exits:[id,...],revision}` → тот же снимок цепочки |

`revision` обязателен: `null` при создании, полученная строка при изменении/удалении. Несовпадение под блокировкой → `409 network_conflict`. Поле `password` при сохранении: строка заменяет пароль, `null` удаляет, отсутствие сохраняет прежнее поколение. Клиент не может выбрать чужую версию пароля.

Id программы совпадает с каталогом, включая `ollama`; API-маршрут имеет id `api:<id маршрута TS-21>`. Порядок `exits` сохраняется. Неизвестные и повторные ссылки отвергаются. Удаление используемого выхода без подтверждения → `409 exit_in_use`. TS-23a: `/removal` возвращает квитанции затронутых провайдеров и последствия для каждого. После подтверждения владельцем `/delete` под общей блокировкой проверяет квитанции и снимок настроек, убирает ссылку у всех провайдеров и удаляет выход. Первый оставшийся становится основным; при отсутствии оставшихся создаётся или используется явный direct. Его включение требует предупреждения в окне «Claude перейдёт на напрямую — сервис увидит ваш адрес». Устаревший снимок или неполный список квитанций → `409 network_conflict` без изменений. Удаление API-маршрута атомарно удаляет его цепочку в той же записи настроек. Старая осиротевшая цепочка доступна через GET с `orphaned:true`; POST с `exits:[]` и её revision удаляет запись, возвращая `configured:false, revision:null`. Для неизвестного провайдера без сохранённой цепочки и попытки непустой записи остаётся `404 provider_unknown`.

Отсутствующая цепочка возвращает `configured:false, exits:[], revision:null` — прежнее поведение до первой настройки. Сохранённая пустая цепочка возвращает `configured:true`: в будущем транспорте это **нет разрешённых выходов**, а не разрешение прямого соединения. Direct появляется только как явный выход в списке.

При первом обращении владельца к этим дверям старые записи Claude/Codex из `connections` переносятся один раз в `legacy-claude`/`legacy-codex` (при занятом id — свободный суффикс). Пароль из старого URL переносится в связку, новый URL не содержит userinfo. `iface` → `409 iface_unsupported` с предложением выбрать прокси или SSH; владелец может исправить прежнюю запись существующей дверью connections и повторить. Повреждённые файлы дают `network_unreadable` без перезаписи.

Применение к трафику — TS-22c. Прежний файл connections остаётся источником действующего транспорта до этой задачи; TS-22a его не переписывает.

TS-22e добавляет двери владельца: `GET /api/network/ssh-keys` (имена обычных файлов верхнего уровня `~/.ssh`, без содержимого, симлинков и `.pub`) и `POST /api/network/exits/:id/check {revision}`. Проверка прямого/прокси выхода использует фиксированные службы IP и страны; curl получает адрес с паролем только через stdin. TS-23a подключает SSH через `Runtime.sshTunnels.ensure` и полученный socks5h; без SSH-интеграции остаётся `network_check_unavailable`. Общая функция измерения с preview TS-23b создаёт отдельный временный `check-UUID`, освобождает процесс и копию ключа до завершения проверки (успех, ошибка, отмена или смена revision) и не трогает рабочий туннель провайдера. Закрытие HTTP-запроса отменяет сохранённую проверку; общий предел — 35 с. Снимок проверки привязан к revision, доступен как `lastCheck` в списке выходов и хранится в памяти до перезапуска. Изменение выхода во время проверки даёт `network_conflict`; старый результат не публикуется.

## Аналитика выходов — договор TS-22i / TS-22h

TS-22i.1: элементы сначала заданы в `00-design-code.html` (`network-stats-spec`).
Образцовые числа удалены. Строка провайдера показывает одну компактную строку из пяти показателей; карточка подключения TS-23a — измерения за сегодня. У провайдеров и API-маршрутов она появляется только после измерений; на карточках подключений до измерений — «ещё не использовался».
Время снимка, ошибка обновления и причины отсутствия показателей — в подсказке.
Пустая вкладка **Прокси** сообщает: «Измерений ещё нет · появятся после первых
ходов через выход»; графики и таблицы появляются только с измерениями.

TS-22h подключает карточки выходов, строки программ/API и вкладку **Прокси**
к SQLite движка (`.harnessy/network/stats.sqlite` рядом с файлом настроек владельца).
Чтение не запускает сетевых проб. Окно запрашивает снимок при открытии/изменении
статуса, по «Обновить» и раз в 30 секунд; pagehide останавливает чтение, pageshow
восстанавливает. Поздний ответ от предыдущей привязки/периода отбрасывается.
При `source:not_connected` действует то же правило отсутствия измерений; образцовых чисел нет.

Хранятся минутные агрегаты по выходу и провайдеру×выходу, числовые гистограммы
задержки и состояние непрерывного отказа. SQLite WAL и `BEGIN IMMEDIATE`
защищают суммы при одновременной работе движков. Активное соединение отдаёт
дельты байтов/времени раз в секунду и при закрытии. Финальная дельта записывается
до завершения `Runtime.close()`. Незавершённый последний интервал при аварии
процесса не считается измеренным. История удалённого выхода остаётся в статистике;
его прежняя цена не восстанавливается из выдуманного тарифа.
Адреса назначения, URL, заголовки, ключи и содержимое не передаются в хранилище.
Предыдущие внешний IP и страна для подсчёта изменений живут только в памяти:
первое наблюдение после старта движка не объявляется изменением.

### Чтение

`GET /api/network/stats?period=today|hour|day|week|month` — только владелец, та же защита,
что у `/api/network/exits`. Область — все выходы владельца, все его проекты.
`today` = от местной полуночи движка (для карточек «сегодня»); `hour` = последние 60 минут, `day` = 24 часа, `week` = 7 суток, `month` = 30 суток;
по умолчанию `day`. Нижняя граница округляется вниз до минуты (гранулярность
агрегатов), верхняя — миллисекунда после момента снимка, чтобы включить
наблюдения в текущую миллисекунду; фактические границы возвращаются в ответе. Неизвестный период — `400 network_stats_invalid`.
Период прокси хранится в окне отдельно от периода токенов (`proxyPeriod` в URL).

Источник не подключён: `200 {ok:true, source:"not_connected", period, reason}`.
Подключён, но измерений за период нет: `200`, `source:"connected"`, пустые `exits`
и `providers`; окно показывает **Измерений ещё нет · появятся после первых ходов через выход**.
Сбой чтения: `503 {ok:false, code:"network_stats_unavailable", error}`; при наличии
снимка он остаётся с датой и ошибкой обновления. Неверная/неполная форма ответа —
ошибка чтения, не нулевые метрики и не макет.

Успех (все времена — миллисекунды эпохи UTC):

```ts
{
  ok: true, source: 'connected', period: 'day',
  from: number, to: number, generatedAt: number, warning?: string,
  exits: Array<{exitId: string, label: string, metrics: Metrics,
                series: Array<{from: number, to: number, metrics: Metrics}>}>,
  providers: Array<{provider: string, metrics: Metrics,
                    exits: Array<{exitId: string, metrics: Metrics}>}>
}
```

`from <= t < to`. Интервалы `series` упорядочены, не пересекаются и лежат внутри
периода. Для часа — минуты, дня — часы, недели — 6 часов, месяца — сутки (краевые
интервалы обрезаются). ID выхода — из настроек; ID провайдера — ID программы или
`api:<routeId>`. Ответ не содержит адресов прокси, логинов, паролей, ключей или путей SSH.
Окно отбрасывает поздний ответ после смены периода/проекта или закрытия страницы.
Показанная дата относится к принятому снимку.

### Метрики и единицы

Каждый ключ `Metrics` обязателен. Значение — `{value: number, reason: null}` либо
`{value: null, reason: string}` при отсутствии именно этого измерения. Числа конечные
и неотрицательные; счётчики целые; процент 0..100. Отсутствующее измерение не равно нулю.
В серии та же форма и те же единицы. Проценты, скорость и перцентили агрегирует движок,
окно не усредняет перцентили и не складывает проценты.

| Ключ | Смысл и отображение |
|---|---|
| `speedBps` | Скорость передачи в байтах/с за активное время передачи; в окне Мбит/с (`×8/1e6`). |
| `bytesUp`, `bytesDown` | Учтённые байты вверх/вниз на сокете, без содержимого. |
| `bytes` | Суммарные отправленные и полученные байты; в окне ГБ (`/1e9`). |
| `availabilityPct` | Доля доступного времени среди наблюдаемых интервалов соединений, %. Параллельные соединения взвешены временем; это не календарный uptime. Ненаблюдавшееся время не считается доступным. |
| `failures` | Падения выхода за период, без повторного подсчёта одного непрерывного отказа. |
| `costUsd` | Цена за период в долларах, по сохранённому тарифу выхода. Если тариф не задан — null с причиной. |
| `latencyP50Ms`, `latencyP95Ms` | p50/p95 задержки подключения из замеров транспорта, мс. Нет замеров — null. |
| `http429` | Число отказов HTTP 429. |
| `blocks` | Число подтверждённых HTTP 451. Неопределённый 403 не объявляется блокировкой или отказом входа по догадке. |
| `ipChanges`, `countryChanges` | Число изменений наблюдавшихся IP и страны; первое наблюдение не изменение. Возвращаются счётчики, не адреса. |
| `reserveMs` | Время на резервном выходе, мс; в окне минуты. |
| `tunnelRestarts` | Перезапуски SSH-туннеля; первоначальный запуск не перезапуск. |

В API-пути статус ответа связывается с реальным выходом конкретного CONNECT;
смена цепочки во время ответа не переносит 429 на другой выход. Служебный
маркер корреляции остаётся на локальном ретрансляторе и не идёт к провайдеру.
В непрозрачном TLS-туннеле программы HTTP-коды не видны: метрики отказов — null
с причиной, пока нет измерения кодов. Время на резерве — null «Резерв ещё не
подключён» до TS-22d. Перезапуски приходят из подписки SshTunnelPool (TS-22b),
IP/страна — из явной проверки NetworkChecks. Дополнительных проверок не запускается.
Ошибка записи не ломает ход; снимок содержит `warning`, если часть наблюдений
не записалась. Ошибка чтения — типизированный 503, повтор разрешён.

`providers[].metrics` — агрегат трафика/сбоев этого провайдера по его выходам;
`providers[].exits` — разрез провайдер × выход. Общие доступность, IP/страна и
перезапуски относятся к выходу; если разрез нельзя измерить, движок отдаёт null
с причиной, а не придумывает привязку. Месячная цена выхода учитывается один раз
в его `costUsd`; на провайдер её не дублировать. До появления согласованного
распределения месячной цены `providers[].metrics.costUsd` — null с этой причиной,
если такой тариф задан. Для тарифа только за ГБ — стоимость трафика провайдера.

### Цена в настройках выхода

`NetworkExit.price?: {monthlyUsd?: number, perGbUsd?: number}` сохраняется через
существующий `POST /api/network/exits/:id/save` вместе с `config` и точной `revision`.
Пустое поле не записывается; оба пустых поля удаляют `price`. Явный 0 — бесплатно.
Можно задать одну или обе составляющие; они суммируются. Значения — конечные числа
от 0 до `Number.MAX_SAFE_INTEGER`, только доллары. Пустой объект, null, строки,
отрицательные и неизвестные поля — `network_invalid`; до изменения настроек.
Старые выходы без `price` остаются без тарифа, бесплатность не подразумевается.

TS-22h считает `monthlyUsd` пропорционально доле календарного месяца UTC,
попавшей в выбранный период (по каждому месяцу отдельно), плюс
`perGbUsd × bytes / 1e9`. Снимок указывает `generatedAt`; изменение тарифа
пересчитывает оценку за выбранный период по текущей сохранённой цене,
а не выдаёт её за исторический платёж. При отсутствии измерений стоимость не выдумывается. Оценка использует только учтённый
трафик; отсутствующий замер трафика при тарифе за ГБ не превращается в нулевую цену.


### Накопительные счётчики резерва (договор TS-22d)

`networkRelay.stats()` и `network.connection` могут дополнительно содержать
`switches`, `reserveMs`, `rateLimits`, `silences`. TS-22h принимает только
присутствующие числовые поля и сохраняет их прирост, а не повторную сумму снимка.
Один читатель на движок получает текущий интервал раз в секунду, перед чтением API
и перед закрытием. Время резерва распределяется по минутам; параллельные соединения
не умножают его. Эти же поля доступны в `metrics`; `rateLimits` не складывается
с `http429`, чтобы не учитывать один отказ дважды. Новых метрик в окне не добавлено.
При отсутствии полей — `null` с причиной «Резерв ещё не подключён».

TS-22c применяет цепочки через `Runtime.networkRelay`: один постоянный HTTP-прокси
на `127.0.0.1` с отдельным случайным портом для каждого провайдера. Он принимает
CONNECT и обычный HTTP. Новое соединение читает текущую цепочку и выбирает первый
доступный выход; действующее соединение не переносится. Поддержаны HTTP(S)-прокси,
SOCKS5h с удалённым DNS, пароль поколения из связки и явный direct. SSH подключается
через внедряемый порт `RuntimeDeps.sshTunnels.ensure(id, config)` — только состояние
`up` с SOCKS5h на loopback разрешает соединение. Ветка TS-22b подключает его реализацию.

Обе двери ретранслятора требуют `Proxy-Authorization: Basic` до чтения пароля
выхода, подготовки туннеля и обращения к сети. Токен — 32 случайных байта на
экземпляр движка, только в памяти; сравнение SHA-256 заголовка выполняется через
`timingSafeEqual`. Отсутствующий, неверный или повторённый заголовок получает
одинаковый пустой `407`, в трассе только `network.auth_failed` и id провайдера.
Программы получают `http://harnessy:<токен>@127.0.0.1:<порт>`; API-диспетчер
передаёт ту же авторизацию только локальному ретранслятору. Его токен не передаётся
внешнему прокси или серверу модели; пароль внешнего прокси остаётся отдельным.

Отсутствующая цепочка сохраняет прежний транспорт. Настроенная пустая цепочка,
отказ всех выходов, смена настроек во время подготовки или недоступный пароль дают
`network_unavailable`, без запасного прямого обращения. Перед моделью выполняется
проверка готовности. Отказ сохраняется как карточка хода с повтором/пропуском;
пробный ход сообщает ту же причину в карточке разрешения и трассе. Если цепочка
впервые добавлена, пока программа готовится со старым окружением, запуск отклоняется:
повтор получит окружение ретранслятора.

`LlmDependencies.providerFetch(provider)` направляет поток и поиск моделей API по
цепочке `api:<id>`; без этой зависимости сервис работает как прежде. Защита адреса,
переадресаций и поколений ключа остаётся в сервисе. Loopback не проксируется;
автоматические переадресации из loopback отклоняются, чтобы внешний адрес не мог
обойти цепочку. Явный `redirect:manual` возвращает ответ без перехода.
Облачная Ollama через локальный демон при настроенной цепочке отклоняется до pull
и вызова модели: для неё нужен API-маршрут Ollama Cloud `https://ollama.com/v1`.
Локальные модели работают через loopback независимо от цепочки.

CLI получает HTTP_PROXY/HTTPS_PROXY/ALL_PROXY (оба регистра), исключение loopback
и Node preload для `http`, `https`, `fetch` (`undici` 7.30.0). Preload требует Node
22.21+ или 24.5+, при неподдерживаемой версии останавливает процесс. Проверки входа
и моделей внутри CLI-хода получают то же окружение. Кодекс пересоздаёт процесс при
первом изменении окружения; смена выходов при постоянном адресе ретранслятора его
не перезапускает. Отдельные фоновые проверки каталога/лимитов и интерактивный вход
не являются ходами; эта задача не меняет их транспорт.

Каталог возвращает `network:{configured,verification,label}`. `verification`
равен `unverified`, пока ретранслятор не наблюдал успешное соединение этого
провайдера; после него — `verified`. Это наблюдение, а не обещание маршрутизации
всех сетевых библиотек сторонней программы. Дублёры проверяют передачу окружения
Claude/Codex/общего CLI и считают CONNECT для каждого id каталога; живых модельных
ходов для проверки не выполняется.
Дополнительная матрица запускает Node-дублёр для каждого id и проверяет userinfo
в HTTPS_PROXY через `https` и `fetch`, TLS с тестовым сертификатом и два CONNECT.

`networkRelay.stats()` возвращает накопительные счётчики по `(provider, exit)`:
`connections`, `errors`, `bytesUp`, `bytesDown`, `connectMs`, `durationMs`.
Активный трафик включён в снимок; после закрытия сокета значения фиксируются.
`RelayOptions.trace` получает эти же накопительные значения с исходом соединения;
движок пишет `network.connection` с `vendor`, `id` выхода и числами, без URL,
заголовков, текста модели и паролей. TS-22h может сохранять эти снимки.

Новые тесты ретранслятора занимают около 3 секунд локально; предел каждого теста
20 секунд. Они используют только loopback-дублёры. PEM в runtime/src/fixtures —
публично включённая тестовая пара, не учётные данные владельца.

Старая запись `POST /api/connections/route` закрыта: `409 network_route_moved`,
для iface — `iface_unsupported`. Чтение/проверка прежнего снимка и его одноразовая
миграция сохранены. В колонке «Маршрут» кнопка «Настроить» открывает цепочку на
вкладке «Выходы»; отсутствующий модуль редактора даёт сообщение о перезагрузке,
а не старую кнопку сохранения. Прежние тесты записи одиночного маршрута заменены
регрессиями миграции, отказа устаревшего POST, стабильного окружения и окна цепочки.
Отмена подготовки соединения остаётся `cancelled` и не оставляет карточку отказа.
API-маршрут `api:ollama` отделён от цепочки локальной программы `ollama`.

Интеграция 22c/22b: Runtime по умолчанию создаёт настоящий SshTunnels; ретранслятор получает socks5h из ensure проверенного SSH-выхода. При закрытии движка закрываются туннели и ретранслятор. Дублёры остаются только в тестах; интеграционный тест использует настоящий менеджер с локальным дублёром SSH-процесса.

## TS-22d: закрепление, резерв и ротация

POST цепочки дополнительно принимает `policy`: `{mode:'fallback',silenceSeconds}`
или `{mode:'rotation',rotationMinutes,silenceSeconds}`. Интервалы задаёт владелец:
1–1440 минут и 1–3600 секунд. GET возвращает policy. Старые цепочки получают
`fallback`, 60 секунд; старый клиент, не приславший policy, сохраняет её.
Revision охватывает список и режим вместе; подделанная страна в POST отвергается.
Удаление API-маршрута/осиротевшей цепочки удаляет также policy.

Страна берётся из `NetworkChecks.snapshot(id, revision)` актуального выхода:
успешная проверка IP и страны, без несовпадения ожидаемого IP. Отсутствие проверки
даёт `network_country_unverified`; другая страна или отсутствие живого резерва —
`network_no_reserve`. Основной выход может работать без проверки страны; резерв —
никогда. После ошибки выход исключается до новой успешной проверки или изменения
его конфигурации. При перезапуске проверки не выдумываются: их нужно повторить.

Выход захватывается на попытку хода целиком, включая запросы агентного цикла.
У места — постоянный loopback-порт; параллельные места провайдера имеют разные
привязки. При завершении попытки её соединения закрываются; поздний callback
старой попытки не получает доступ к новой. Процесс CLI может оставаться запущенным.
Период ротации отсчитывается от выбора выхода и проверяется при следующем ходе;
таймер не меняет выход работающего хода. Настройки и страна перепроверяются после
ожиданий; изменение останавливает попытку, не переносит её незаметно.

| Наблюдаемый исход | Действие |
|---|---|
| Ошибка соединения/CONNECT, HTTP 5xx, молчание до первого ответа/инструмента | Автоматическая новая попытка на резерве той же страны, не больше одной на выход |
| HTTP 429 у API до ответа/инструмента | То же; счётчик rateLimits |
| Ошибка после текста, reasoning, ответа API или вызова инструмента | Без автоповтора; долговечная карточка ошибки, «Повторить» начинает новый ход через резерв |
| HTTP 401/403, 407 прокси или отказ входа SOCKS | Ошибка входа; выход не переключается |
| Нет подходящего резерва | Типизированная причина в карточке; без неявного прямого выхода |
| Наступил интервал ротации | Следующий ход выбирает следующий доступный выход той же страны; работающие попытки остаются на прежнем |
| Отмена владельца | Без переключения и без автоповтора |

У CLI содержимое TLS не расшифровывается: доступны ошибки соединения/CONNECT и
молчание транспорта. HTTP-статус API виден fetch. Молчание — отсутствие входящих
байтов на активном соединении в течение silenceSeconds. У API таймер действует
только во время ожидания заголовков/чтения ответа; время выполнения инструмента
между завершёнными запросами не считается сетевым молчанием. При отправке через резерв
в чате сохраняется карточка с подписью выхода и фиксированной причиной; она
восстанавливается из стенограммы, событие привязано к чату.

`networkRelay.stats()` дополнительно возвращает по выходу и провайдеру:
`switches` (переходы на этот выход), `reserveMs` (время выбранного резервного выхода,
без умножения на число одновременных ходов), `rateLimits`, `silences`.
Те же значения дополняют `network.connection` в трассе. TS-22h сохраняет снимок;
никакой записи учётных данных или заголовков не добавлено.

Целевой набор 22d (15 тестов) занимает около 9 секунд на дублёрах, включая намеренное молчание и ожидание инструмента; предел каждого теста — 20 секунд. Проверки 22c сохранены; прежний тест выбора резерва дополнен подтверждённой страной, отказ входа SOCKS теперь проверяет network_proxy_auth.

TS-22d круг 2: перед автоматическим повтором движок ждёт завершения `runTurn` прежней попытки (включая `finally` адаптера), максимум 30 с — тот же предел, что у остановки хода. Нет подтверждения завершения → карточка `network_unavailable`, без запуска резерва. Это относится и к пробе. Текст, reasoning/thinking и полное assistant-сообщение CLI считаются началом ответа до буферизации/отображения; после них автоматического повтора нет. Метаданные сессии и чужие события ответа не считаются.

## TS-22f: проверка провайдеров через выходы

Вкладка «Выходы» открывает предварительную таблицу всех настроенных пар
провайдер × выход. До подтверждения она читает только настройки и текущий снимок
каталога. Первый настроенный API-model получает фиксированный запрос «Ответь: да.»
с `maxTokens:1`, без инструментов и reasoning; цена — оценка по соответствующей
записи pi-ai (вход примерно по длине запроса), при отсутствии записи — «неизвестна».
У программы выбран первый model каталога: один существующий probe в пустой временной
папке, «входит в подписку, расходует лимит». Локальный Ollama и API с loopback-адресом
пропускаются с причиной. При недоступной модели IP и страна выхода всё равно
проверяются, модельный вызов пропускается с причиной. Каждая строка заранее
показывает модель, выход, вызов и цену.

Двери владельца:

- `GET /api/network/checks?project=…`: последний список/результат текущего проекта.
- `POST /api/network/checks/preview {project}`: новый список с непрозрачным id,
  revision, rows, state=preview. Не запускает сеть или программу.
- `POST /api/network/checks/:id/start {project,decision:'allow'}`: явное подтверждение
  именно этого списка; повтор идемпотентен. Список действует 10 минут.
- `GET /api/network/checks/:id?project=…`: тот же снимок.
- `POST /api/network/checks/:id/cancel {project}`: отмена; повтор безопасен.

Подтверждение связано с проектом, настройками выходов и API-маршрутов, моделями и
поколением входа программы (в том числе A→B→A). После изменения — binding_changed,
нужен новый список. Параметры назначения/секреты/модели от тела start не принимаются.
Пары выполняются последовательно, не более 90 секунд на пару. Ошибка одной строки
не повторяет её и не мешает проверке остальных; отмена/смена проекта прекращает
последующие вызовы. Уже потраченные токены отменой не возвращаются.

Каждая проверка получает отдельную временную привязку ретранслятора к выбранному
выходу из снимка цепочки. Резерв/ротация отключены для этой привязки; проверенная
страна до IP-проверки не требуется. SSH использует тот же порт ensure/get/subscribe.
IP (api.ipify.org) и страна (ipapi.co) запрашиваются через этот же ретранслятор с
пределами 10/6 секунд и 16 КиБ на ответ, без переадресаций. Затем выполняется модельный
запрос. Отсутствие страны остаётся видимой причиной частичного результата даже
после успешного ответа модели. Пароли прокси и ключи API остаются в соответствующих транспортных слоях.
Неожидаемый IP останавливает модельную часть. Если программа вернула ответ, но
новое соединение через выбранный выход не наблюдалось — network_unverified:
в таблице честно «ответ да», проверка маршрута не подтверждена.

Результат строки содержит IP, страну, задержку IP-запроса, общую длительность,
response (да/нет/ещё не вызывался), код и очищенную причину. SSE networkCheck несёт
снимок с растущим revision; старый HTTP-ответ не перезаписывает новые результаты.
Закрытие карточки не отменяет и не подтверждает проверку; повторное открытие читает
текущий результат. Итоги каждой строки — network.provider_check в трассе, без тел
модельных ответов и секретов. После перезапуска движка результаты остаются в трассе;
новая проверка требует нового подтверждения.

Новые HTTP/DOM-регрессии: отсутствие вызовов до подтверждения, точный выход без
резерва, SSH через дублёр, цена, двойной старт, отмена/смена проекта, смена привязки
и входа A→B→A, неизвестный маршрут, mismatch IP, ограничение размера, безопасная
трасса, поздний HTTP/SSE и восстановление карточки. Живые провайдеры не вызывались.
Целевой прогон новых HTTP-тестов занял 1,7–10,1 секунды при разной нагрузке; пределы каждого теста — 15/20 секунд.
PEM network-check-* — публичная тестовая пара для локальных HTTPS-дублёров.

TS-23a: вкладка «Прокси и VPS» использует `today`, показывает ГБ, Мбит/с и падения, только если они измерены. Нет измерений — «ещё не использовался»; сбой чтения сохраняет прежние данные с датой. Кнопка проверки VPS использует `Runtime.sshTunnels.ensure`, затем существующий ограниченный запрос IP/страны через полученный локальный socks5h. Ключи и модели при чтении карточек не вызываются; SSH запускается только по нажатию проверки.

## Добавление прокси и VPS (TS-23b)

`LIVE.network.openAdd({provider?, title?, onSaved?})` открывает два шага скетча 25; `onSaved` получает квитанцию сохранённой записи. Без `provider` — только сохранение. Новые id создаются окном один раз и не выводятся в форме. Повтор запроса не создаёт второй id.

`POST /api/network/preview {config, password?}` — дверь владельца для проверки черновика, без записи настроек или пароля. VPS проверяется через отдельный временный SSH-туннель, который закрывается в finally и при разрыве HTTP. Внешний адрес и страна читаются тем же механизмом, что у сохранённых записей; запросы ограничены временем и размером. Возвращается `{ok:true, check}` с `ok/ip/country/durationMs/reason/code`; причина безопасна для показа человеку. Изменение полей, закрытие или смена проекта отменяют запрос и отбрасывают поздний результат.

`POST /api/network/exits/:id/save` дополнительно принимает `use:{provider, revision}`: запись и назначение провайдеру сохраняются под одной блокировкой; `revision` — полученная при открытии квитанция выбора провайдера. Конфликт не создаёт запись или пароль. Прежние подключения не удаляются. Успешная проверка того же адреса и учётных данных переносится в сохранённую запись (до пяти минут); название и цена не меняют проверенное соединение. Пароль передаётся только в теле явного запроса, затем в stdin curl или в связку ключей при сохранении; он не включается в URL записи, argv, окружение, ответ или журнал.
