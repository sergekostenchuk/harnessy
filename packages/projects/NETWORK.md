# Выходы и цепочки провайдеров

`Settings.network()` читает область `network` владельца. `NetworkSettings` выполняет миграцию, запись выходов и цепочек под той же блокировкой файла, что и настройки TS-21. Поле `network` недоступно через общий PATCH настроек; проект не может переопределить его.

`NetworkExit` экспортируется из `@harnessy/projects` (`src/network-config.ts`):

- Общие поля: `id`, `label`, необязательный `expectedIp` (IPv4/IPv6).
- `type: 'direct'`.
- `type: 'proxy'`: `url` (`http`, `https`, `socks5h`, без userinfo/пути/параметров), необязательный `login`. Сохранённый пароль представлен только `passwordRef` (= id выхода) и `passwordGeneration`.
- `type: 'ssh'`: `host`, `port`, `user`, `keyPath` (абсолютный путь внутри `~/.ssh` либо запись `~/.ssh/...`, без `..`). Содержимое ключа не читается. Проверка существования ключа, realpath и его пригодности при запуске относится к транспорту TS-22b.

Пароли используют `MacKeyStore({purpose:'proxy-password'})`: тот же backend Security.framework, отдельный service от ключей API. Каждая запись создаёт неизменяемое поколение. Конфигурация с адресом и ссылкой публикуется атомарно, затем прежнее поколение удаляется. При отказе публикации новое поколение удаляется. В HTTP доступны только наличие, полная маска и дата. Внутренний `resolvePassword(exit)` читает поколение захваченного выхода.

## HTTP (только владелец)

| Метод | Путь | Тело / ответ |
|---|---|---|
| GET | `/api/network/exits` | `{ok, exits:[{config,revision,password:{present,mask,updatedAt}}]}` |
| POST | `/api/network/exits/:id/save` | `{config,revision,password?}` → `{ok,config,revision,password:{present,mask,updatedAt}}` |
| POST | `/api/network/exits/:id/delete` | `{revision}` → `{ok}` |
| GET | `/api/network/providers/:id` | `{ok,provider,configured,exits,revision}` |
| POST | `/api/network/providers/:id` | `{exits:[id,...],revision}` → тот же снимок цепочки |

`revision` обязателен: `null` при создании, полученная строка при изменении/удалении. Несовпадение под блокировкой → `409 network_conflict`. Поле `password` при сохранении: строка заменяет пароль, `null` удаляет, отсутствие сохраняет прежнее поколение. Клиент не может выбрать чужую версию пароля.

Id программы совпадает с каталогом, включая `ollama`; API-маршрут имеет id `api:<id маршрута TS-21>`. Порядок `exits` сохраняется. Неизвестные и повторные ссылки отвергаются. Удаление используемого выхода → `409 exit_in_use`.

Отсутствующая цепочка возвращает `configured:false, exits:[], revision:null` — прежнее поведение до первой настройки. Сохранённая пустая цепочка возвращает `configured:true`: в будущем транспорте это **нет разрешённых выходов**, а не разрешение прямого соединения. Direct появляется только как явный выход в списке.

При первом обращении владельца к этим дверям старые записи Claude/Codex из `connections` переносятся один раз в `legacy-claude`/`legacy-codex` (при занятом id — свободный суффикс). Пароль из старого URL переносится в связку, новый URL не содержит userinfo. `iface` → `409 iface_unsupported` с предложением выбрать прокси или SSH; владелец может исправить прежнюю запись существующей дверью connections и повторить. Повреждённые файлы дают `network_unreadable` без перезаписи.

Применение к трафику — TS-22c. Прежний файл connections остаётся источником действующего транспорта до этой задачи; TS-22a его не переписывает.
