# @harnessy/api

HTTP/SSE-порт нового ядра Harnessy. Node.js 22+, без внешнего HTTP-фреймворка.

Запуск из корня: `ui/desktop/run.sh` или `node packages/api/bin/harnessy.ts`.
Сервер слушает `127.0.0.1:${PORT:-3777}`. `CHAT_WORK_DIR` задаёт папку без проекта,
`HARNESS_PROJECTS_ROOT` — корень создаваемых проектов, `HARNESSY_SITE` — каталог
`sketches`. Файлы владельца задаются `HARNESS_{LAST_PROJECT,PROJECTS,PINS,SETTINGS,CONNECTIONS}_FILE`.
`HARNESS_NO_LAST` запрещает чтение последней папки и изменение реестра/последней папки.

`createApi({runtime, siteDir, port})` предоставляет `listen()` и
идемпотентный `close()`. `bootstrap()` собирает runtime с обязательным `createActions()`;
очереди запускаются после привязки HTTP-порта. При ошибке старта созданный runtime
закрывается. SIGINT/SIGTERM обрабатываются также во время старта; отмена запрещает запуск очереди. Завершение прекращает приём запросов, закрывает SSE, отменяет ходы и
закрывает провайдеров, затем соединения HTTP.

Корень `/` отвечает `302` на вход прототипа `/sketches/proto/10-new-chat.html`.

Все API-запросы проверяют Host; изменяющие запросы — Origin/Sec-Fetch-Site и JSON
Content-Type. Лимит распакованного тела — 2 000 000 байт, в том числе chunked.
Codex-мост проверяет `X-Pane-Token` и передаёт неизменяемый TurnScope действию runtime.
`POST /api/owner/merge` — отдельный порт владельца. Загрузка сессии только через
`POST /api/sessions/open {pane,id}`; старые GET/HEAD возвращают 405 без изменений.

SSE подписывается на шину текущего проекта: `all`, `owner` или место. Карточки
переигрываются при подключении, `: ka` идёт каждые 15 секунд. Смена проекта,
отключение клиента и переполнение очереди 4000 закрывают подписку и соединение,
включая ожидание drain. Статика читается по проверенному дескриптору канонического
файла внутри корня; ответы и ошибки `/sketches` имеют `no-cache`.

HTTP-тесты рядом с кодом используют временные папки, случайные порты, провайдеры и
часы-дублёры. `fixtures/errors.json` — независимые формы Python `server.py`; успешные
формы сверяются по полям и данным, включая реальные git/чаты/подтверждения.
`bootstrap.test.ts` запускает фактический `ui/desktop/run.sh` с тестовой подстановкой модулей
Node, без SDK-процессов и обращений к моделям. Полный прогон: `npm test` в корне.

## Маршруты подключений моделей и сети

- `/api/providers/catalog` — каталог программ: установка, вход, модели, честные режимы мест (TS-20).
- `/api/llm/providers[...]` — API-маршруты: список, сохранение, ключ (в связку ключей), обнаружение моделей, проверка, удаление; каталожные провайдеры и свой адрес, Ollama Cloud как API-маршрут (TS-21).
- `/api/network[...]` — выходы, цепочки провайдеров, проверка, статистика, проверка провайдеров через выходы (TS-22, TS-23); `/api/connections[...]` — прежние маршруты подключений.
- Запросы под теми же проверками Host/Origin/`Sec-Fetch-Site`/Content-Type; секреты в ответах не возвращаются.
