# @harnessy/team

Манифест команды, каталоги ролей/режимов и создание `.harness`. Node ≥22, ESM, TypeScript strict; yaml 2.9.1. Процессов, журнала и вызовов моделей здесь нет.

`loadTeam(harnessDir)` возвращает команду, живые места и предупреждения о пропущенных вендорах. Пустая модель сохраняется до подстановки реестром ядра. `roleOf(team, id)` и `instructionsFor(team, seat)` читают роль и инструкции; отсутствующий файл инструкций даёт пустую строку, как в Python.

`ensureLine(projectDir)` создаёт шаблоны с `wx`, сохраняя существующие файлы. Все обязательные шаблоны читаются до создания `.harness`. `seedOrchestrator(harnessDir, vendor, model, mode)` возвращает `{seeded: true}` либо `{seeded: false, reason: 'seats_present'}`. `addSeat(harnessDir, args)` назначает свободный id и сохраняет манифест. Ошибки имеют `TeamError.code`, русский текст и исходный `vendorText`/`cause` для ошибок ОС и разбора.

Специализация `{title, text}` пишет базовую инструкцию роли + `\n\n` + текст в `roles/seats/<sid>.md`. Общий файл роли остаётся общим; инструкции специализированного места изолированы. Существующий файл места не перезаписывается; при отказе замены манифеста удаляется только файл, созданный данным вызовом. Нумерация учитывает сохранённые места той же роли, включая неподдерживаемых вендоров.

Мутации асинхронны и используют общий для team/projects `withPathLock` по каноническому корню проекта. Все публичные входы, в том числе вызванные внутри другой блокировки, всегда ждут общую очередь; разные экземпляры и симлинки используют один канонический путь. Составные операции передают явный PathLock во внутренние ensureLineLocked/seedOrchestratorLocked; токен проверяется и прекращает действовать при освобождении захвата. Публичный вызов того же пути нельзя ожидать, удерживая родительский захват: для композиции используются внутренние функции. Манифест заменяется через tmp + fsync + rename по каноническому файлу; симлинк на него сохраняется. Межпроцессной блокировки нет.

`parseYaml` использует безопасный YAML 1.1, merge и последнее значение повторного ключа. Разрешение bool/int/float соответствует PyYAML: `y`/`n` и `1e3` остаются строками. `dumpYaml` сохраняет порядок ключей, заголовок и представление обычного манифеста с неизвестными JSON-подобными полями по Python-эталонам. Fixtures получены из PyYAML 6.0.3; Python при работе пакета не нужен. Timestamp, binary, set и aliases находятся вне обещанной совместимости записи; небезопасные теги отклоняются. Комментарии исходного YAML после изменения заменяются штатным TEAM_HEADER, как в Python.

Проверка сценариев — `node --test packages/team/src/*.test.ts`; полный прогон — `npm test` в корне.
