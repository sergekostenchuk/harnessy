# Харнесс: окна Claude и Codex над одной папкой проекта

Одна страница в браузере, несколько окон-агентов: два с моделями Anthropic и одно
с Codex. Все работают в одной папке проекта, у каждого своя модель, режим доступа и
свой разговор. Окна пишут друг другу через журнал линии, а владелец разрешает или
запрещает опасные действия кнопками прямо в колонке.

Ходит по подпискам, а не по API-ключам:

- Claude через **Claude Agent SDK (Python)** поверх локального Claude Code,
  который залогинен командой `claude login` (подписка Max);
- Codex через **официальный Python SDK openai-codex**: двусторонний JSON-RPC с
  `codex app-server`, вход по подписке ChatGPT из `~/.codex/auth.json`.

## Запуск

```bash
cd /Users/kostenchuksergey/HARNESS
./run.sh            # = .venv/bin/python -m app.server
```

Открыть: http://localhost:3777. Другой порт: `PORT=4000 ./run.sh`.
Пересоздать окружение: `python3 -m venv .venv && ./.venv/bin/pip install openai-codex claude-agent-sdk aiohttp`.
Тесты: `./.venv/bin/python -m unittest discover -s tests -t .`

Сервер лучше держать в tmux, тогда он переживает закрытие окон Claude Code и Терминала:

```bash
bin/serve.sh            # запустить в отсоединённой сессии tmux «harness»
bin/serve.sh attach     # посмотреть экран сервера, выход Ctrl-b d
bin/serve.sh restart    # перезапустить после правок кода сервера
bin/serve.sh stop       # остановить
```

Журнал сервера копится в `logs/server.log`.

Вход, один раз, в Терминале: `claude login` для Claude, `codex login` для Codex.
Жёлтая полоса вверху страницы говорит, у кого вход не выполнен.

## Линия проекта: `.harness/`

Папка проекта задаётся сверху страницы. В ней харнесс держит линию:

```
<проект>/.harness/state/channel.ndjson   журнал: одна запись — одна строка, только дописывание
<проект>/.harness/state/cursors.json     до какой записи окно успешно отходило (курсор сдвигается после хода, не до)
<проект>/.harness/state/panes.json       настройки окон и их сессии — для восстановления после перезапуска
```

Первая строка журнала — протокол: правила канала в самом канале. Запись:
`seq` (сквозной номер, выдаёт сервер), `id`, `ts`, `from` (ставит сервер, агент
поле не задаёт), `to` (список окон или `*`), `kind`, `thread`, `reply_to`,
`text`, `evidence`, `policy`; у вердикта ещё `score` и `round`.

Виды записей: task, status, question, answer, review-request, verdict, blocker,
escalation, note, stop, resume, digest, proposal, decision, report.

## Команда: манифест, роли, политика

При первом открытии папки харнесс кладёт в `<проект>/.harness/` шаблоны из `templates/`
и больше их не трогает:

- `team.yaml` — места команды: роль, вендор, модель, режим доступа, `write_paths`
  (где разрешены правки), `digest`. Права идут за ролью: смена вендора или модели
  у места прав не меняет; два места с одной ролью равноправны. Колонки на
  странице строятся из манифеста, любую можно свернуть щелчком по имени.
- `roles/<роль>.md` — инструкции роли; попадают в системный промпт места вместе
  с автоматической выпиской его маршрутов из политики.
- `comms-policy.yaml` — политика связи: маршруты «роль → роль: виды записей»,
  триггеры `owner-ack` (запись ждёт карточки подтверждения у владельца) и
  `reply-to:<вид>` (например, verdict только в ответ на review-request от
  исполнителя), границы `max_rounds` и `accept_score`, секция `observe` — чьи
  разговоры роль вправе читать через `read_pane` и получать в сводке соседей.
  Правка файла подхватывается на лету, каждая запись журнала несёт версию
  политики; отказ уходит агенту с причиной и записью `rejected` владельцу.

Стартовая команда шаблона:

| Место | Роль | Вендор и модель | Режим | Правки |
|---|---|---|---|---|
| assistant | голос владельца: читает всех, пишет всем от его имени; не подтверждает owner-ack и не нажимает «разрешить» | Claude Sonnet 5 | чтение | нет |
| orchestrator | ведёт процесс: task, question, stop, decision всем; сливает вехи | Claude Fable 5.1 | правки без вопросов | везде |
| architect | документы решений, ответы на вопросы; задач не ставит | Codex gpt-6-astra | чтение и команды | docs |
| executor | код по задачам; review-request ревьюеру и тестеру | Codex gpt-5.6-sol | спрашивать | везде в своём worktree |
| reviewer | вердикт с баллом и раундом в ответ на review-request; порог 9, до 3 раундов | Claude Opus 5 | чтение и команды | нет |
| tester | независимые тесты и отчёты; задач не ставит | Codex gpt-5.3-codex-spark | чтение и команды | tests |
| researcher | факты с источниками, интернет | Claude Haiku 4.5 | чтение и интернет | docs/research |

Наблюдение по шаблону: owner, assistant, orchestrator и architect видят всех;
reviewer и tester — только executor; executor и researcher — никого.
Дебагер отдельной ролью не нужен: это executor с брифом «найти и доказать причину».

Вердикты: сервер принимает verdict только с `score` 0..10, `round` от 1 и
`reply_to` на review-request от адресата; раунд больше `max_rounds` отклоняется;
после каждого вердикта оркестратор получает `status` треда, при исчерпании
раундов без принятия владелец получает `escalation`.

## Экран

- Слева список команды из манифеста: точка состояния (свободен, думает, ждёт решения),
  длина очереди. Щелчок по месту открывает или закрывает его окно; окон открыто
  сколько угодно и в любом наборе, набор запоминается в браузере («все», «никого»).
- В центре окна выбранных мест: заголовок с моделью, доступом и веткой, под
  шестерёнкой настройки места (модель, доступ, разговор, сводка соседей), лента,
  поле ввода с видом записи и тредом. «Вмешаться» и «Стоп» появляются, пока идёт ход.
- Сверху папка проекта, треды чипами (раунд, балл, принято, слито) и счётчик
  «ждут решения»; справа карточки, ждущие решения владельца, и записи владельцу
  (эскалации, отчёты, статусы, отказы политики); снизу выдвижной журнал.
- Все события страница получает одним потоком `/api/events/all` (событие несёт
  `pane`): браузер держит не больше шести соединений на адрес, а мест семь плюс
  владелец. Поток одного окна `/api/events/<id>` остаётся.

## Рабочее пространство: worktree, SHA, свидетельства, слияние

- **Worktree на место.** У места с полем `worktree` в манифесте своя рабочая копия
  на ветке `seat/<место>` (по шаблону: executor, reviewer, tester). Создаётся при
  открытии папки, если проект под git; папки worktree и состояние линии
  добавляются в `.git/info/exclude`. Без git все места работают в корне, страница
  предупреждает. Для Codex к записи открываются `.git` проекта и папка свидетельств.
- **review-request несёт SHA.** Запрос на ревью без `sha` или с неизвестным
  коммитом отклоняется; короткий SHA раскрывается до полного.
- **Вердикт только с отчётом.** `verdict` требует `evidence` с путём к отчёту
  внутри проекта, обычно `.harness/evidence/<тред>/r<раунд>/report.md`, и в отчёте
  должны быть разделы Ran, Skipped, Planned, Manual. Вердикт наследует SHA запроса.
  Claude-ревьюер пишет в папку свидетельств без карточек.
- **Слияние — инструмент `merge`.** Пройдёт только SHA с принятым вердиктом,
  только от ролей из `merge_roles` манифеста или владельца, только когда корень
  проекта на интеграционной ветке и без незакоммиченных правок. Аттестация
  «в интеграцию попало ровно то, что прошло ревью» сводится к равенству SHA.
  После слияния владелец и оркестратор получают `status`. В журнале видно
  состояние тредов: раунды, балл, принято, SHA, слито.

## Доставка: очередь и автоход

Никакого «агент занят». Запись адресату кладётся в журнал и в его очередь; когда
окно свободно, сервер сам запускает ход со всеми накопившимися записями одним
входящим сообщением. Твои сообщения идут тем же путём: `Отправить` ставит в
очередь, а `Вмешаться` подаёт прямую инструкцию в идущий ход, агент видит её на
ближайшем шаге, не бросая работу. Проверено у обоих вендоров. `Стоп` обрывает ход.

Ответы на записи соседей адресат даёт сам инструментом `send` с `reply_to`.
Страховка: если ход был запущен вопросом или задачей соседа, а агент ничего не
отправил, сервер сам отправляет его итоговый текст ответом (answer на question,
status на task). На review-request страховки нет: вердикт обязан быть записью с
баллом, иначе приходит напоминание, при повторе — эскалация владельцу.

После перезапуска сервера очереди, сессии и курсоры восстанавливаются из
`.harness/state`: ничего не теряется. Ход, прерванный остановкой сервера или ошибкой модели,
доставленным не считается — его записи уходят заново со следующим ходом (доставка «не меньше одного раза»).

## Инструменты агентов

- `send(to, kind, text, thread?, reply_to?, evidence?, score?, round?)` — запись
  другому окну или владельцу, без ожидания; возвращает номер записи.
- `ask(to, text, thread?)` — вопрос с ожиданием ответа; адресат ответит, когда
  дойдёт до вопроса в очереди. Встречный `ask` тому, кто уже ждёт тебя, отклоняется.
- `read_pane(pane, last_n)` — прочитать последние реплики другого окна.
- `merge(sha, message?)` — слить принятый коммит в интеграционную ветку (см. выше).

У Claude инструменты живут внутри сервера (встроенный MCP Agent SDK), у Codex их
даёт мост `bin/pane-mcp.mjs` через HTTP-ручки `/api/send`, `/api/ask`,
`/api/pane_transcript`. Вызовы моста Codex разрешаются без вопросов, вызовы
чужих MCP-серверов идут карточкой.

## Что на странице

- **Папка проекта** сверху, общая для окон; кнопка **Журнал** открывает ленту
  записей линии.
- **Окна** из манифеста: имя места и роль в шапке (щелчок сворачивает колонку),
  модель, режим доступа, разговор, «Новый», галочка «сводка соседей» (только
  автоматическая сводка перед ходом; кто чьи разговоры читает, задаёт секция
  observe политики), счётчик очереди. Внизу: вид записи (task, question, note, decision, resume,
  stop), поле ввода, `Отправить`, `Вмешаться`, `Стоп`.
- **Лента**: твои записи с номером и видом, записи соседей сиреневым с шапкой
  `#seq · kind · от кого · тред`, исходящие записи агента строкой `→ #seq`,
  действия агента `▸ Bash: …`, карточки «разрешить / отказать».
- **Полоса владельцу** под шапкой: эскалации и записи, адресованные owner.

## Режимы доступа

| Режим | Claude | Codex |
|---|---|---|
| Только чат | без инструментов | песочница только чтение, инструкция не трогать файлы |
| Чтение папки | Read, Glob, Grep | песочница только чтение |
| Чтение и команды | Read, Glob, Grep, Bash с безопасным списком; прочие команды карточкой | песочница только чтение; команды свободно, запись карточкой |
| Чтение и интернет | Read, Glob, Grep, WebFetch, WebSearch | песочница только чтение |
| Спрашивать | инструменты работы в папке; правки и команды — карточкой | запись в папке проекта; всё вне её и сеть — карточкой |
| Правки без вопросов | правки файлов сами; git/ls/cat/npm/node/python без вопросов; остальное карточкой | то же, что «Спрашивать» |
| Всё без вопросов | все инструменты без ограничений (опасно) | полный доступ без песочницы (опасно) |

`write_paths` места добавляют право Edit и Write внутри этих папок без вопросов
(у Claude — правилами разрешений, у Codex — инструкцией плюс карточка на запись
в режимах чтения). Инструменты связи между окнами разрешены во всех режимах.

## Где журналы разговоров вендоров

- Claude: `~/.claude/projects/<путь папки, где всё кроме букв и цифр заменено на «-»>/<id>.jsonl`.
- Codex: `~/.codex/sessions/ГГГГ/ММ/ДД/rollout-…-<id>.jsonl`; список по папке даёт app-server.

## Что выключено нарочно

В треды Codex не попадают твои хуки, плагины, memories и MCP-серверы из
`~/.codex/config.toml`, в ходы Claude — хуки, настройки и MCP-серверы пользователя.
Подключён только твой роутер `sol-spark-router`, его записывающие инструменты
спрашивают карточкой.

## Устройство

- `app/journal.py` — журнал линии, курсоры, состояние окон.
- `app/server.py` — aiohttp: страница, `/api/status`, `/api/project`,
  `/api/panes/<окно>`, `/api/events/<окно>` и `/api/events/owner` (потоки
  событий), `/api/chat` (запись владельца в очередь), `/api/steer`,
  `/api/approve`, `/api/interrupt`, `/api/sessions`, `/api/send`, `/api/ask`,
  `/api/pane_transcript`, `/api/journal`; очередь и автоход (`pump`), страховка
  автоответа (`after_turn`).
- `app/team.py` — манифест команды и инструкции ролей; `app/policy.py` — политика связи.
- `app/gitops.py` — worktree, проверка коммитов, слияние; `app/evidence.py` — контракт отчётов.
- `app/panes.py` — реестр окон из манифеста, карточки разрешений, стенограммы, сводка.
- `app/bridge.py` — инструменты send, ask, read_pane для Claude и общие операции.
- `app/claude_provider.py`, `app/codex_provider.py` — адаптеры вендоров.
- `bin/pane-mcp.mjs` — те же инструменты для Codex (MCP stdio, Node).
- `index.html` — вся страница, без сборки. `tests/` — журнал и доставка.

Переменные: `PORT`, `CHAT_WORK_DIR` (папка по умолчанию), `CLAUDE_BIN`,
`NODE_BIN`, `CHAT_DEBUG=1` (печатать все события Codex).
